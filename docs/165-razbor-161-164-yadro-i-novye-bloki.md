# Часть II. 🔑 Главное: ядро положительно, и это первый положительный результат проекта

Тождество `--revx-carry` устроено так:

```
Δкапитал = бета среднего запаса + время под позицией + захват (с меткой по следующему тику)
итог без беты = время под позицией + захват
```

«Время под позицией» — это и есть ковариация запаса с ходом цены,
`Σ (запас − средний запас) · Δопора`. Хедж убирает именно её. Значит

```
потолок идеального хеджа = захват = (итог без беты) + (время под позицией)
```

и это **вычитание двух измеренных чисел**, а не модель. Считаем.

## II.1. Дефицит известен точно

| величина | окно A (падающее, 3 бота × 177 ч = 22.1 ботосуток) |
|---|---:|
| итог без беты, без хеджа | −0.4990 за окно = **−$0.0226 /бот/сут** |
| хедж снял (полоса 1 лот) | +0.3899 за окно = **+$0.0176 /бот/сут** (78%) |
| остаток | **−$0.0049 /бот/сут** |

Ваши числа воспроизводятся до последнего знака. Претензий нет.

## II.2. А вот «время под позицией» известно тремя разными способами — и они расходятся в 5.3 раза

| # | откуда | число, $/бот/сут | ядро = число − 0.0226 |
|---|---|---:|---:|
| 1 | **тождество** `--revx-carry`, строка «убирает» в 163 П2.1 | **0.0810** | **+0.0584** |
| 2 | **наклон излома**: (0.0392 / 2) × 0.3151 % × 24 ч | **0.1482** | **+0.1257** |
| 3 | **из денег**: снято 0.0176 при снятой доле вогнутости 1 − 0.0143/0.0392 = 0.64 | **0.0277** | **+0.0052** |

🔑 **Смотрите на правую колонку. Она положительна во всех трёх случаях.** Каким бы
из трёх приборов ни мерить, ковариационный член БОЛЬШЕ полного дефицита, а значит

```
захват − отбор − комиссии > 0
```

Это прямо противоречит тому, как мы оба читали результат последние два месяца
(«спред не покрывает отбор»). Спред отбор покрывает. **Весь минус — и даже больше
чем весь — сидит в ковариации запаса.** Это ровно то, на что нацелен блок 2, и
ровно то, чего не могли сдвинуть двадцать одна попытка с параметрами: параметры
двигали масштаб обоих членов сразу.

## II.3. Сколько это стоит в год — и почему расхождение нельзя оставить

Оба члена линейны по лоту, поэтому масштабирование прямое (164 говорит то же
самое про пошлину хеджа).

| ядро, $/бот/сут | лот $2.90 | лот $9 | лот $29 |
|---|---:|---:|---:|
| по тождеству +0.0584 | **$128/год** | $397/год | $1 280/год |
| по наклону +0.1257 | $275/год | $854/год | $2 752/год |
| по деньгам +0.0052 | **$11/год** | $35/год | $114/год |

(шесть ботов, идеальный хедж, ноль фондирования — верхняя граница, не прогноз)

Разница между первой и третьей строкой — это разница между «есть смысл заниматься

# Часть III. П2.4 — регрессия, которая закрывает вопрос без единой новой сделки

Это главный пункт документа. Он ничего не стоит и отвечает ровно на вопрос
«каков потолок хеджа».

| | |
|---|---|
| **вопрос** | чему равно ядро (захват − отбор − комиссии) и отличимо ли оно от нуля |
| **что меряем** | одна линейная регрессия на часовых отрезках, которые уже построены в приложении 2 к 164 |

Модель:

```
m_h  =  a  +  b · Δp_h  +  g · |Δp_h|  +  ε
```

где `m_h` — «итог без беты» за час, **делённый на число живых ботов в этом часе**
(окно A: 3, окно B: 6), а `Δp_h` — ход рынка за час в тех же единицах для всех
часов.

- `a` — деньги в час при нулевом ходе **и** нулевом модуле хода. Это и есть ядро,
  то есть **потолок идеального хеджа**;
- `b` — бета. Хедж убирает её целиком;
- `g` — вогнутость. Ожидается отрицательной. Хедж убирает её частично.

**Гонять только объединённо по двум окнам.** На окне A почти все часы имеют
`Δp < 0`, там `|Δp| = −Δp`, регрессоры вырождены и `a` не определяется. Окно B
даёт вторую ветвь и разводит их.

## Мощность — считаю заранее, как и положено

Из приложения 2: уровень −0.0007 $/ч при `t` = −0.48 даёт `SE` = 0.00146 $/ч на
корзину из трёх ботов, то есть разброс по часам `σ` = 0.0195 $/ч = 0.0065 $/бот/ч.

| | |
|---|---|
| отрезков объединённо | 178 + 85 = **263** |
| `SE(a)` при идеальном дизайне | 0.00040 $/бот/ч = **$0.0096 /бот/сут** |
| `SE(a)` с поправкой на остаточную коллинеарность (×1.3) | **$0.0125 /бот/сут** |

| гипотеза для `a` | ожидаемый `t` | исход |
|---|---:|---|
| +0.0584 (по тождеству) | **4.7** | решается уверенно |
| +0.1257 (по наклону) | **10.1** | решается уверенно |
| +0.0052 (по деньгам) | 0.4 | не решается — **и это тоже ответ** |

🔑 **То есть регрессия различает «есть бизнес» и «нет бизнеса» на уже собранных
данных.** Если `a` выходит в районе +0.06 с `t` ≈ 4–5 — конструкция жива, и весь
разговор переходит на то, как снять ковариацию полнее. Если `a` неотличим от нуля
при `SE` = $0.0125 — значит ядра нет, и тогда правило остановки срабатывает
по-настоящему, без оговорок.

| | |
|---|---|
| **подтверждает** | `a` > 0 с `t` ≥ 2 на объединённых 263 часах, и `g` < 0 |
| **опровергает** | \|`a`\| < 2·`SE`, то есть ядро неотличимо от нуля |
| **цена** | полдня, ноль новых сделок, данные уже в журналах |
| **что открывает** | право говорить о масштабе (часть VII.1 протокола) — или закрывает конструкцию окончательно |

⚠️ Что может испортить замер: если `b` и `g` сильно коррелируют даже на
объединённых данных, `SE(a)` вырастет. Смотреть VIF; если он выше 5 — добавить
третье окно или считать `a` как среднее остатков после вычитания подогнанных
`b·Δp + g·|Δp|`, а не как свободный член.

# Часть IV. Поправка к моему же протоколу: «опровергнуто» и «не измерено» — разные исходы

164 прав, и разбирательство в нём корректное: применять правило остановки к этому
замеру нельзя. Но причина глубже той, что там названа, и дефект — мой.

## IV.1. Что я написал неправильно

В части V протокола 160 стоит:

```
П2.1 арифметика не сходится  ИЛИ  П2.3 знак не перешёл
        └─> оба рычага проверены. СТОП по этой конструкции.
```

«Знак не перешёл» имеет **два разных смысла**, и дерево их не различает:

- знак не перешёл, и прибор имел силу это увидеть → **опровержение**;
- знак не перешёл, потому что прибор не различает эффект такого размера →
  **не измерено**.

Второй случай не даёт права ни на остановку, ни на продолжение. Он даёт право
только на одно: повышать мощность. Я этого в протокол не записал, и это третий
раз за проект, когда «ноль» оказывается вопросом мощности:

| где | что выглядело нулём | чем оказалось |
|---|---|---|
| 157 §V (A58) | эксперимент с воротами | настоящий ноль — **сила была** |
| 159 §II (размер) | развёртка по размеру | **не измерено**: `SE` 0.0109 при эффекте 0.012 |
| 164 прил. 2 (хедж) | итог с хеджем | **не измерено**: `t` = −0.4…1.5 |

## IV.2. Правило, которое заменяет строчку в дереве

🔑 **Перед тем как объявить блок опровергнутым, называется размер эффекта,
который блок был написан обнаружить, и `SE` прибора. Если \|эффект\| < 2·`SE` —
вердикт «не измерено», и единственные допустимые следующие шаги те, что поднимают
мощность.**

И сразу — какие шаги мощность поднимают на этой конструкции, а какие нет:

| шаг | поднимает `t` | почему |
|---|---|---|
| календарное время | ✅ `t ~ √n` | вчетверо часов — вдвое `t` |
| больше кругов в час (засев) | ✅ `t ~ √кругов` | вдвое кругов — `t` ×1.41 |
| парная разность на одних часах | ✅ сильно | рынок сокращается (приложение 2 это и делает) |
| **укрупнение лота** | ❌ | множит и среднее, и разброс. **Ваш вывод верен, подтверждаю** |
| ещё одна развёртка параметра | ❌ | меняет масштаб обоих членов сразу (фильтр 159 §IV) |

## IV.3. Срабатывает ли правило остановки сейчас

**Нет — но оно теперь на часах, и часы короткие.**

Причина отсрочки не «давайте попробуем ещё»: причина в том, что часть II нашла
положительное ядро на двух приборах из трёх, а часть III даёт тест, который

🔑 **Записываю обязательство так же заранее, как и прошлое: если П2.4 даёт `a`,

Не «померим ещё одно окно», не «попробуем полосу поуже». Закрывается.

# Часть V. П2.5 — лестницу полос надо вести ВНИЗ, а не вверх

164 мерил полосы 0.5 / 0.7 / 1 / 1.5 / 2 / 3 / 4. Вся информация — в двух самых
узких, а самые широкие подпадают под ваше же правило двадцати перевешиваний.

Арифметика простая: при блуждании шагом в лот полоса `B` проходится примерно за
`B²` исполнений, поэтому **число перевешиваний растёт как 1/B², а пошлина — тоже
как 1/B²** (каждое перевешивание стоит лот × 2 б.п. = $0.00058, и ваш замер это
подтверждает: $0.099 / 110 = $0.0009).

| полоса | перевешиваний за окно A (≈) | пошлина, $/бот/сут | падение вогнутости (164) |
|---:|---:|---:|---|
| 2 лота | 28 | 0.0007 | 2.01× |
| 1 лот | 110 | 0.0029 | 2.74× |
| **0.5 лота** | 440 | 0.0115 | **4.41×** |
| **0.35 лота** | 898 | 0.0235 | не мерили |
| 0.25 лота | 1 760 | 0.0461 | не мерили |

🔑 **При потолке ядра в $0.02–$0.13 /бот/сут пошлина в $0.012 при полосе 0.5
и $0.024 при полосе 0.35 — ещё по карману.** А вогнутость при 0.5 падает в 4.4
раза против 2.7 при полосе 1. И на деньгах то же: лучший результат падающего окна
(+0.0713) получен на самой узкой из мерянных полос — 0.7 лота.

| | |
|---|---|
| **вопрос** | где полоса перестаёт окупаться |
| **что меряем** | «итог без беты» и `t` парной разности на полосах 0.7 / 0.5 / 0.35 / 0.25, оба окна, шаг $1 |
| **подтверждает** | разность «с хеджем минус без» растёт при сужении и достигает `t` ≥ 2 |
| **опровергает** | разность перестаёт расти до того, как `t` дотянет до 2 — значит хедж снимает не всё, и остаток не ковариационный |
| **цена** | прогон существующего `--revx-hedge`, полдня |
| **что открывает** | настоящую верхнюю оценку того, что хедж вообще способен вернуть |

⚠️ Оговорка, которой нет в моей арифметике: при полосе 0.25 лота перевешивание
меньше шага контракта на всех парах, кроме SOL. То есть лестница вниз упирается в
тот же шаг, что и BTC сегодня, и честно она гоняется только с `--step-usd=1`.
Это по-прежнему гипотетический прогон.

⚠️ И второе: 1/B² — это оценка для блуждания. Реальный запас удерживается скосом,
то есть возвратен к цели, и число перевешиваний при узкой полосе может выйти
заметно больше. Мерить, а не предполагать.

# Часть VI. Блок 3 — динамическая формула отступов

Вы сформулировали это так: «правильнее определить функцию, которая даёт отступы на
основе входящих данных, чем подобранные константы на основе прогонов». Инстинкт
верный, и у него есть точная причина: грид-подобранная константа — это одно число,
оценённое из шумной выборки, и оно наследует весь шум выборки; функция же
переносит на новые данные не число, а **зависимость**, которую можно проверить
отдельно от результата.

Но у этой идеи есть барьер, и его надо взять до того, как писать код.

## VI.1. ⚠️ Проверяю формулу тем же фильтром, которым отбраковал 21 попытку

Фильтр 159 §IV: меняет ли идея **ковариацию** запаса с ходом цены — или только её
**масштаб**?

Константный отступ — масштаб. Отступ, зависящий от волатильности последнего часа —
**ковариация**: в опасный час бот котирует шире, ловит меньше исполнений и
набирает меньше запаса именно тогда, когда запас дороже всего. Число исполнений
становится отрицательно связано с опасностью. **Формула фильтр проходит.** Это
другое семейство, чем двадцать одна константа, и правило остановки на него не
распространяется.

## VI.2. Но плато — это плохая новость, и её надо обезвредить первой

Ценность условной политики над лучшей константой примерно равна

```
выигрыш ≈ ½ · |кривизна прибыли по δ| · разброс(δ*_час)
```

А в 151 измерено, что поверхность по отступу — **плато 8.6–13.1 б.п.**, то есть
кривизна близка к нулю. При нулевой кривизне никакой разброс `δ*` ничего не даёт:
формула будет ездить по плоскому дну и возвращать то же самое.

🔑 **Если только плато не является артефактом усреднения.** Может быть так, что
внутри каждого часа поверхность острая, но её пик ездит, и среднее по всем часам
выглядит плоским. Это ровно тот случай, ради которого формула и нужна, — и
отличить одно от другого можно на уже собранных данных.

## П3.0. Плато — настоящее или усреднённое? (ворота блока)

| | |
|---|---|
| **вопрос** | острая ли поверхность прибыли по отступу ВНУТРИ однородного класса часов |
| **что меряем** | делим часы на 4 класса по волатильности ПРЕДЫДУЩЕГО часа (по ленте, не по своим сделкам) и строим кривую «прибыль против δ» отдельно внутри каждого класса, по ленточной кривой маркаута из 151 |
| **подтверждает** | внутри классов поверхность имеет измеримую кривизну, И пики разных классов разнесены больше, чем ширина плато (4.5 б.п.) |
| **опровергает** | внутри каждого класса поверхность так же плоская, ИЛИ все пики лежат внутри плато |
| **цена** | один проход по имеющейся ленте, полдня. Новых сделок ноль |
| **что открывает** | право строить формулу вообще |

🔑 **Если П3.0 опровергает — блок 3 закрывается здесь же, и двадцать вторая
попытка с параметрами не делается.** Это и есть способ проверить вашу идею, не
потратив на неё месяц.

## П3.1. Каждый вход проверяется как предсказатель ВПЕРЁД

| | |
|---|---|
| **вопрос** | предсказывает ли вход `x`, снятый на часе `h−1`, ту величину, ради которой он взят, на часе `h` |
| **что меряем** | для каждого кандидата: регрессия вперёд на отложенном куске данных, не использованном при подборе |
| **подтверждает** | `R²` вне выборки > 0 и `t` ≥ 2 |
| **опровергает** | связь есть внутри часа и исчезает со сдвигом на час — значит это не предсказатель, а совпадение |
| **цена** | день |
| **что открывает** | список допустимых входов |

Кандидаты, которые имеет смысл проверять, и все — **с ленты, а не со своих
исполнений**:

- реализованная волатильность за последние 1 / 3 / 6 часов;
- спред площадки и его устойчивость (161 П0.2 показал, что он не реагирует на
  активность — значит он несёт информацию о поставщике, а не о потоке);
- дисбаланс тейкерских покупок и продаж (ваша интуиция из прошлого разговора);
- распределение глубины свипов, отдельно вверх и вниз;
- час суток.

⚠️ **Почему именно с ленты.** Свои исполнения зависят от того самого δ, который
формула назначает. Вход, построенный на своих исполнениях, замыкает контур на
себя: формула подстраивается под последствия собственных решений и подтверждает
себя. Это не тонкость, это способ получить красивую кривую и нулевой результат.

## П3.2. Пропорционален ли часовой безубыток волатильности этого часа

| | |
|---|---|
| **вопрос** | верно ли, что `2δ = c(δ)` решается при `δ`, пропорциональном `σ` часа |
| **что меряем** | по ленточной кривой маркаута строим `c(δ)` отдельно внутри каждого класса волатильности и находим безубыток класса |
| **подтверждает** | `безубыток_класса / σ_класса` держится в пределах ±20% по всем классам — тогда формула имеет вид `δ = k · σ` с одним параметром |
| **опровергает** | отношение гуляет или связь немонотонна — тогда `σ` не тот вход |
| **цена** | день, данные есть |
| **что открывает** | вид формулы, а не только право её строить |

## П3.3. Стороны несимметричны — мерить λ(δ) и c(δ) отдельно по покупке и продаже

| | |
|---|---|
| **вопрос** | одинаковы ли эластичность потока и отбор на бидовой и асковой стороне |
| **что меряем** | `λ(δ)` и `c(δ)` раздельно по сторонам, по ленте |
| **подтверждает** | безубытки сторон различаются больше чем на ширину плато — тогда **скос перестаёт быть свободным параметром и становится вычисляемым** |
| **опровергает** | стороны совпадают в пределах ошибки — тогда один δ на обе стороны законен, и это упрощение, а не потеря |
| **цена** | день |
| **что открывает** | связь с блоком 4: асимметрия сторон — это и есть след порога запаса |

## П3.4. Устойчивость: свойство площадки или свойство недели

| | |
|---|---|
| **вопрос** | переживают ли найденные зависимости смену недели |
| **что меряем** | всё из П3.1–П3.3 переоценивается отдельно по неделям; сравниваются не значения, а знаки и порядок величин |
| **подтверждает** | знак и порядок держатся на всех неделях |
| **опровергает** | асимметрия сторон или коэффициенты меняют знак между неделями — значит это свойство недели, и в формулу его зашивать нельзя |
| **цена** | полдня после П3.3 |
| **что открывает** | какие коэффициенты можно считать константами формулы, а какие надо пересчитывать на ходу |

## П3.5. Формула против константы — на тех же двух окнах, по тому же критерию

| | |
|---|---|
| **вопрос** | даёт ли формула больше, чем лучшая константа |
| **что меряем** | **парную разность на одних и тех же часах**: «формула минус константа», а не два уровня по отдельности |
| **подтверждает** | разность > 0 с `t` ≥ 2 на обоих окнах |
| **опровергает** | разность неотличима от нуля |
| **цена** | зависит от П3.0–П3.4; сам прогон — день |
| **что открывает** | замену константы в живом боте |

⚠️ **Честно про мощность, и это ограничение принципиальное.** Формула с `k`
входами требует БОЛЬШЕ данных, чем константа, а не меньше. Если константу нельзя

Единственное, что спасает, — парная разность на одних часах: там рынок
сокращается и `SE` падает в разы. **Поэтому П3.5 меряется только как разность.
Уровни в этом пункте не смотрим вообще.**

# Часть VII. Блок 4 — засев инвентаря и двусторонняя котировка

Идея: дать боту стартовый запас, чтобы аск стоял в книге всегда, а не только
после того, как что-то куплено.

Основание из ваших же замеров: доля времени, когда **аска нет в книге вообще** —
BTC 49.9%, ETH 55.9%, SOL 68.0%. Половину времени и больше одна нога молчит.

## VII.1. ⚠️ Прогоняю идею через тот же фильтр — и она его НЕ проходит

Честно, потому что это моя идея и правило должно работать против неё так же.

Засев убирает пол на нуле, и бот начинает котировать обе стороны всегда. Пропускная
способность растёт: в нынешнем режиме круг занимает `1/λ_бид + 1/λ_аск`
(сначала купить, потом продать), при двусторонней котировке — примерно `1/λ`,
то есть **круги ускоряются примерно вдвое**.

Но это **множитель на обе половины тождества сразу**: и на ядро, и на ковариацию.

| | без хеджа | с идеальным хеджем |
|---|---:|---:|
| сейчас | −$0.0226 /бот/сут | +$0.0584 /бот/сут (ветвь тождества) |
| засев ×2 | **−$0.0451** — вдвое хуже | **+$0.1169** — вдвое лучше |

🔑 **Значит засев — не источник края, а множитель. Без работающего хеджа он
вреден ровно во столько же раз, во сколько полезен с ним.** Записываю это как
правило допуска: **блок 4 не запускается, пока П2.4 не показала положительное
ядро.** Порядок здесь не вопрос удобства, он меняет знак.

⚠️ И отдельная поправка к тому, что я мог бы сказать месяц назад: засев НЕ убирает
вогнутость. Симметричный запас теряет на падениях, будучи в лонге, и на росте,
будучи в шорте, — вогнутость от этого скорее растёт. Убирает её хедж, а не засев.

## VII.2. Но одна выгода от засева безусловна — мощность

Вдвое больше кругов в час — это `t` ×1.41 в том же календарном времени. При
нынешней нужде в 160–1450 часах это единственный рычаг мощности помимо времени,
который у вас есть (лот, как вы верно показали, не рычаг). **Поэтому П4.0 имеет
смысл посчитать сейчас, даже если сам засев не включать.**

## П4.0. Сколько кругов реально добавит засев — считается по журналам, без кода

| | |
|---|---|
| **вопрос** | сколько событий ленты дошло бы до аска, если бы он стоял всегда |
| **что меряем** | по журналам котировок и ленте: для каждого часа, когда аска не было, ищем сделки ленты, которые достали бы до цены, по которой бот выставил бы аск при нынешней формуле скоса |
| **подтверждает** | множитель кругов ≥ 1.5 хотя бы на двух парах |
| **опровергает** | множитель < 1.2 — значит отсутствие аска не было узким местом, и вся идея отпадает |
| **цена** | день. Ноль новых сделок, ноль риска |
| **что открывает** | честный множитель вместо моей оценки 1/(1−доля), которая заведомо завышена: `λ_аск` ограничена ещё и потоком покупателей |

## П4.1. Цена засева — упущенная доходность на среднем отклонении

Считается заранее, как П2.1.

Вы не «замораживаете биткоины под бота». Вы отдаёте боту право **отклоняться** от
вашей базовой позиции. Цена — доходность на среднем модуле отклонения, а не на
всём запасе:

| рост BTC | упущено за год |
|---|---|
| 20 %/год | 0.42 лота × 20 % = **8.4 % лота** |
| 50 %/год | **21 % лота** |
| 100 %/год | **42 % лота** |

Против дохода бота за год в тех же единицах: 65 % лота (ветвь «по деньгам») или
735 % лота (ветвь «по тождеству»). **Отношение от масштаба не зависит — и цена, и
доход линейны по лоту.** То есть по этой оси засев окупается в обеих ветвях; не
окупается он только там, где ядра нет вовсе.

## П4.2. Что придётся переделать в коде — перечисляю, чтобы это не всплыло потом

- `sizeFor` и вся арифметика размера предполагают запас ≥ 0;
- пол запаса на нуле сидит не в одном месте, а в логике «продать нечего»;
- цель скоса задана как 0.3 потолка — при симметричном диапазоне цель должна стать
  нулём отклонения, а потолок — двусторонним ±`cap`;
- предохранители («заявка ≤ $10», «экспозиция ≤ $40») считают экспозицию как
  положительную величину. Их надо переопределить на модуль отклонения, иначе они
  либо не сработают, либо сработают всегда.

⚠️ Это не «переписать бота», но это и не настройка. Полторы-две недели, и делать
это до П2.4 — значит писать код под гипотезу, которая может не подтвердиться.

## П4.3. Два блокера вне кода

**Хранение.** Сейчас ваш долгосрочный запас лежит отдельно от торгового счёта.
Засев означает, что часть его переезжает на счёт с горячим API-ключом. Это не
финансовый, а операционный риск, и решается он размером: засевать столько, сколько
не жалко потерять целиком, а не столько, сколько красиво в модели.

**Налог.** Тут я не советчик и говорю только про форму вопроса, а не про ответ.
В Польше обмен одной виртуальной валюты на другую налогово нейтрален, а доход от

неиспользованные расходы переносятся на будущие годы. То есть **пара BTC/USDC,
скорее всего, вообще не порождает налогового события на каждом круге** — а это
принципиально для бота, делающего десятки тысяч сделок.

⚠️ Но есть ровно два места, где это может сломаться, и оба надо спросить у
бухгалтера **до** масштабирования, а не после:

1. считается ли USDC «walutą wirtualną» в смысле этой нормы, или как токен

2. **перп на Kraken — это производный инструмент, а не виртуальная валюта.**

Вопрос бухгалтеру формулируется в одну строку: **«спот BTC/USDC и перп PF_XBTUSD —
это один источник дохода или два, и зачитываются ли убытки между ними?»**

# Часть VIII. Вопрос 1 — можно ли брать под это свои долгосрочные биткоины, и не перекладывание ли это убытков

Отвечаю по порядку, потому что в вопросе три разных вопроса.

## VIII.1. Засев — это не шорт

Если вы даёте боту свои биткоины, чтобы он мог продавать, — бот **не шортит**. Он
продаёт то, что есть, и выкупает обратно. Запас колеблется вокруг вашей базовой
позиции и остаётся положительным в абсолюте. Нет заёмных средств, нет
фондирования, нет базиса, нет ликвидации, нет второй площадки. Это самый дешёвый
способ получить двустороннюю котировку, какой существует.

Шорт — это другое: перп на Kraken, и он нужен не для котирования, а для хеджа.
Две вещи, которые стоит не смешивать, потому что они решают разные задачи:

| | что даёт | чем платите |
|---|---|---|
| **засев спотом** | двустороннюю **котировку** (аск всегда в книге) | доходностью на среднем отклонении |
| **перп-хедж** | двустороннюю **экспозицию** (ковариация снимается) | пошлиной 2 б.п. + фондирование + базис |

Хедж у вас уже посчитан и частично измерен. Засев — нет.

## VIII.2. «Приход денег из внешней системы» — нет. Деньги приходят от контрагентов

Разложим, откуда берётся каждый доллар:

| член | откуда деньги | матожидание |
|---|---|---|
| захват | от контрагента, который **перешёл спред**, потому что ему было некогда | **> 0** |
| отбор | к контрагенту, который знал больше | < 0 |
| ковариация запаса | ни от кого — это **экспозиция к цене** | **< 0**, и это главное |
| комиссии | площадке | < 0 |

Шорт не «приносит деньги извне». Шорт **удаляет третью строку**. И вот
принципиальное: у третьей строки матожидание **отрицательное, а не нулевое**.
Если бы оно было нулевым, хедж был бы чистым снижением разброса и не приносил бы
ни цента — вы бы просто меняли дисперсию на пошлину. Но оно отрицательное, потому
что ваш запас систематически растёт, когда цена падает: бид исполняется на
падении. Это тот же отбор, только в форме переноски, а не в форме цены сделки.

🔑 **Поэтому это не перекладывание убытков из кармана в карман. Вы убираете член,
который в среднем отрицателен, — и в тождестве после него остаётся положительное
ядро. Часть II это и показала.**

## VIII.3. Что будет на горизонте лет

Три вещи, и они не связаны между собой:

**Ваш биткоин никуда не девается.** Бот не продаёт его насовсем — он колеблется
вокруг базовой позиции. Через год у вас столько же биткоинов, сколько было, плюс
накопленный результат бота в USDC, минус доходность на среднем отклонении (см.
П4.1: 8–21 % лота в год, то есть $0.24–$0.61 на бота при лоте $2.90).

**Отклонение не растёт со временем.** Это важно, потому что интуиция подсказывает
обратное. Запас возвратен: скос тянет его к цели, потолок ограничивает. Средний
модуль отклонения — 0.42 лота, и он таким и остаётся хоть за месяц, хоть за пять
лет. Накапливается только результат, а не позиция.

**Единственный настоящий долгосрочный риск — режимный.** Если биткоин уходит в
многолетний однонаправленный тренд, бот всё это время держит отклонение в
неудобную сторону: на затяжном росте он в среднем недобирает BTC, на затяжном
падении — перебирает. Хедж это снимает по построению, но тогда вы платите
фондирование перпа, а оно на многолетнем горизонте в среднем платится длинными
шортам — то есть, скорее всего, в вашу пользу, но это **не то, на чём можно
строить план**, потому что бывают затяжные периоды обратного знака.

## VIII.4. Прямой ответ

Да, брать можно, и с точки зрения экономики это дешевле любой альтернативы. Но
**не сейчас**, и причина не в биткоинах, а в порядке: засев без работающего хеджа
удваивает убыток (часть VII.1). Порядок такой:

```
П2.4 (регрессия, полдня)  →  ядро положительно?
   нет → конструкция закрывается, вопрос снимается
   да  → П2.5 (полоса вниз)  →  П4.0 (множитель по журналам)  →  и только тогда засев
```

# Часть IX. Вопрос 2 — не перенести ли самого бота на Kraken фьючерсы

Вы предположили: «наверное, не большая разница между связкой Револют плюс шорт на
Кракене и всё на Кракене». **Разница огромная, и она в противоположную сторону.**

## IX.1. Одна таблица, которая закрывает вопрос

Круг брутто для маркет-мейкера, котирующего обе стороны у касания, — это
`спред − 2 × мейкерский сбор`. До всякого отбора, до всякой переноски.

| площадка | спред | мейкер | **круг брутто** |
|---|---:|---:|---:|
| Revolut BTC/USDC | 13.63 б.п. | 0 | **+13.63 б.п.** |
| Revolut ETH/USDC | 21.24 б.п. | 0 | **+21.24 б.п.** |
| Revolut SOL/USDC | 25.55 б.п. | 0 | **+25.55 б.п.** |
| **Kraken PF_XBTUSD** | **0.16 б.п.** | 2 б.п. | **−3.84 б.п.** |

(спреды Revolut — из 161 П0.2, спред перпа — из 163 П2.2: один тик в 94.3 %
снимков)

🔑 **На PF_XBTUSD котирование убыточно на 3.84 б.п. за круг ещё до того, как
кто-либо вас отберёт.** Мейкерский сбор 2 б.п. в двенадцать раз больше всего
спреда. Это не «чуть хуже» — это арифметически невозможно.

## IX.2. Почему так получилось и что отсюда следует вообще

Спред на Revolut в **85 раз** шире, а сбор нулевой. Это и есть вся рента, которую
вы измеряли в блоке 0, и существует она ровно потому, что на Revolut никого нет:
$1.52 млн оборота в сутки против $509 млн у одного только `PF_XBTUSD`. Узкий спред
на Kraken — это не удача площадки, это след того, что там стоят профессионалы с
петлёй в миллисекунды.

И тут возвращается оговорка из части I про 162. На Revolut вывод «скорость не
рычаг» верен, потому что при спреде 13.6 б.п. очередь почти ничего не решает. На
перпе спред — **один тик**, середины между тиками не существует (163 сам это
отмечает), значит всё решает **место в очереди**. Петля 1.2 с там означает, что вы
всегда в конце очереди, и исполняетесь только тогда, когда цена собирается пройти
сквозь уровень. Это определение токсичного исполнения. Блок 1 на Kraken дал бы
прямо противоположный ответ — и проверять это не надо, это видно из спреда.

## IX.3. Правило отбора площадок, которое стоит записать один раз

**Круг брутто = спред − 2 × мейкерский сбор. Ниже 5 б.п. — не котировать вообще,
независимо от оборота, ликвидности и красоты API.**

Проверьте им, чего вы избежали: Kraken PF даёт −3.84 при обороте в 335 раз больше
Revolut. Оборот не спасает отрицательный круг, он его множит.

## IX.4. Единственное, что Kraken действительно даёт, — и почему это не повод

Перп двусторонен от рождения: там не нужен ни засев, ни свои биткоины, чтобы
продавать. То есть Kraken бесплатно решает задачу блока 4.

Но цена этого решения — весь захват. Вы покупаете двустороннюю котировку за
−3.84 б.п. за круг, когда на Revolut ту же двусторонность даёт засев ценой
8–21 % лота в год. Это обмен один к сотне не в вашу пользу.

## IX.5. Прямой ответ

**Нет.** Revolut — это место, где есть рента; Kraken — место, где дёшево
хеджироваться (пересечь 0.16 б.п. стоит копейки, платит только комиссия). Эти две
площадки не заменяют друг друга, они **дополняют** друг друга, и связка «котируем
там, где широко и бесплатно; хеджируем там, где узко и глубоко» — это не
компромисс, а и есть правильная конструкция. Перенос бота на Kraken удаляет
единственный положительный член.

⚠️ Чего я тут НЕ утверждаю: что на Kraken вообще нельзя заработать. Можно — но
другим классом бота (тейкерским, арбитражным, на фондировании), где узкий спред
не мешает, а помогает. Это разговор части VII.2 протокола 160, и он открывается
только после того, как эта конструкция закрыта или масштабирована.

# Часть X. Обновлённое дерево решений

Заменяет часть V протокола 160 целиком.

```
СОСТОЯНИЕ: блок 0 пройден, блок 1 опровергнут (скорость не рычаг на этой площадке),

        │       └─> СТОП. Ядра нет. Конструкция закрывается. Разговор
        │           переходит на другой класс бота (VII.2 протокола 160).
        └─ a > 0 с t ≥ 2
                └─> ядро есть, потолок хеджа известен числом. Дальше:

П2.5  лестница полос вниз: 0.7 / 0.5 / 0.35 / 0.25, оба окна          [полдня]
        └─ разность «с хеджем минус без» на одних часах, t ≥ 2
                ├─ не дотягивает даже при узкой полосе
                │       └─> хедж снимает не всё; остаток не ковариационный.
                │           Вернуться к П2.4 и посмотреть, что в g.
                └─ дотягивает -> знаем, сколько хедж реально возвращает

П3.0  плато настоящее или усреднённое (внутри классов волатильности)  [полдня]
        ├─ плоско внутри классов -> БЛОК 3 ЗАКРЫТ. Формулу не строим.
```
