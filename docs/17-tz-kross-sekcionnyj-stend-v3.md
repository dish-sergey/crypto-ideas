# Кросс-секционный стенд — ТЗ на реализацию, v3

**Назначение:** задание для исполнителя (Claude Code).
**Зависимости:** `16-kross-sekcionnye-strategii.md`, `04-validaciya-backtest.md`, `15-stend-sravneniya-detektorov-v3.md`.
**Теория:** `t10` (IC и фундаментальный закон), `t07` (погрешность метрик), `t08` (самообман), `t05 v3` §4 (симметрия волатильности).

**Что изменилось в v3:** добавлен §7 — независимая валидация меры стресса как гейта защиты от обвала моментума. Вывод doc 19 о непригодности `stress_level` получен для другой задачи и **на эту не переносится**; ссылка на ось `S` детектора заменена на явно валидируемую здесь величину.

**Главное отличие от стенда детекторов:** там узким местом была статистика. Здесь наблюдений достаточно, и узкое место — **данные и издержки**. Кросс-секционный бэктест на плохо собранной вселенной даёт красивый и полностью фальшивый результат.

## 3. Фаза 1. Вселенная point-in-time

### 3.1 Что нужно получить

`universe(date) -> list[symbol]` — состав **на ту дату**, без знания будущего.

### 3.2 Источники

- **CoinGecko / CoinMarketCap исторические снимки** — рейтинги капитализации; проверить доступность на бесплатном тарифе.
- **Биржевые списки с датами листинга и делистинга** — `ccxt` даёт текущие, исторические собирать из архивов объявлений.
- **Косвенный способ:** актив входит на дату `t`, если есть свечи за все 60 дней до `t` и хотя бы 1 день после. Второе условие — взгляд в будущее, использовать **только** для оценки смещения (§3.3), не в основном прогоне.

### 3.3 Обязательное измерение смещения выживаемости

```
1. Вселенная наивно: сегодняшний топ-100, прогнать назад.
2. Вселенная корректно: point-in-time.
3. Прогнать S2 на обеих.
4. Разница в CAGR — цена ошибки.
```

Число записать в отчёт: оно объясняет, почему нельзя доверять чужим бэктестам крипто-стратегий.

### 3.4 Правила фильтрации

- Исключить стейблкоины (список ручной, датированный).
- Исключить обёрнутые и производные токены: WBTC, stETH, cbETH и аналоги.
- Исключить токены младше 60 дней с первой свечи.
- Фильтр ликвидности: медианный дневной оборот за 30 дней ≥ порога из конфига.
- **Делистинг обрабатывается явно:** позиция закрывается по последней доступной цене. Молчаливое исчезновение — скрытая утечка.

## 4. Фаза 2. Движок бэктеста

### 4.1 Цикл

```
для каждой даты ребалансировки t:
    вселенная  = universe(t)
    сигналы    = signal.compute(вселенная, данные до t включительно)
    целевые    = portfolio.construct(сигналы, текущий_портфель)
    целевые    = constraints.apply(целевые)
    целевые    = risk.apply(целевые, гейт_стресса(t))     # см. §7
    исполнение на день t+1
    учёт издержек
```

### 4.2 Разнесение расчёта и исполнения

**Сигнал по закрытию дня `t`, сделки по цене дня `t+1`.** Совмещение — самая частая скрытая утечка в кросс-секционных бэктестах, дающая правдоподобный результат.

Цена исполнения: `open` дня `t+1` либо `(open + close)/2` как консервативный вариант. Не `close` дня `t`.

### 4.3 Модель издержек

```
комиссия  = 0.05% тейкер (или 0.02% мейкер при лимитных)
спред     = половина типичного спреда монеты
влияние   = k · (объём_сделки / медианный_дневной_оборот) ^ 0.5
```

Для монет вне топ-20 суммарные издержки round-trip реалистично 0.3–1.0%.

**Тест:** прогон с нулевыми издержками и с удвоенными даёт заметно разный результат.

### 4.4 Проверка на синтетике

Сгенерировать ряды с **заложенным** кросс-секционным моментумом известной силы — движок обязан его найти. Затем ряды без структуры — движок обязан показать ноль минус издержки.

## 6. Информационный коэффициент

### 6.1 Расчёт

```
На каждую дату ребалансировки t:
    IC(t) = spearman( signal_i(t), r_i(t → t+h) )
IC_mean, IC_std, IC_IR = IC_mean / IC_std
```

### 6.2 Как читать

| `IC_mean` | Интерпретация |
|---|---|
| < 0.01 | сигнала нет |
| 0.02–0.05 | рабочий сигнал, нормальный результат |
| 0.05–0.10 | хорошо |
| > 0.15 устойчиво | почти наверняка ошибка, искать утечку |

**Слабый IC — норма.** Из `t10`: устойчивый результат даёт слабый сигнал, применённый к многим активам многократно.

### 6.3 Сверка с фундаментальным законом

```
IR_ожидаемое ≈ IC_mean · √N_эффективное
```

- Фактический **заметно выше** → искать утечку.
- Фактический **заметно ниже** → издержки или конструкция портфеля съедают сигнал; чинить портфель, не сигнал.

`N_эффективное` = число позиций / средняя корреляция внутри портфеля. Монеты сильно коррелированы, реальная широта в разы меньше числа позиций.

## 7. Валидация гейта стресса (новое в v3)

**Выполняется до внедрения защиты из `16-kross-sekcionnye-strategii.md` §7.1.**

### 7.1 Почему это отдельная задача

Doc 16 §7.1 предписывает резать экспозицию при высоком стрессе, ссылаясь на ось `S` детектора режима. **Ось `S` удалена** (`01-detektor-rezhima-v4.md` §2.3), а мера `stress_level` признана непригодной как триггер выхода (`19-razbor-voltarget-v2.md`).

Однако тот вывод получен **для другой задачи** и на эту не переносится:

| | Защита экспозиции BTC | Защита моментум-портфеля |
|---|---|---|
| Что угрожает | обвал цены | разворот после капитуляции |
| Когда случается | из низковолатильного состояния (`t05 v3` §4.3) | когда волатильность **уже высока** |
| Что нужно от меры | опережать событие | распознать состояние «после паники» |

Во втором случае запаздывающая мера стресса может как раз подойти: обвал моментума происходит на отскоке, то есть после того, как волатильность выросла. Это надо **измерить**, а не предположить — ни в ту, ни в другую сторону.

### 7.2 Что измерить

Сначала определить целевое событие независимо от меры:

```
Обвал моментума = период, где доходность моментум-портфеля
                  относительно равновзвешенной корзины
                  падает более чем на 15% за 20 дней.
```

Найти все такие эпизоды на истории. Затем для каждой кандидатной меры стресса:

| Кандидат | Определение |
|---|---|
| `vol_z_7` | z-score реализованной волатильности 7д к 1 году (форма `stress_level`) |
| `vol_z_30` | то же с окном 30д |
| `dd_market` | просадка равновзвешенной корзины от 60-дневного максимума |
| `disp` | кросс-секционная дисперсия доходностей внутри вселенной |

Для каждой посчитать:

- значение меры за 5 дней **до** начала эпизода;
- долю эпизодов, где мера превысила порог 0.6 **до** начала;
- долю ложных срабатываний: превышение порога вне эпизодов;
- экономику: прогон S2 с гейтом и без, `Δ MaxDD / Δ CAGR` стратегии.

### 7.3 Критерий

Гейт внедряется только если он **улучшает `Δ MaxDD / Δ CAGR` стратегии** на out-of-sample по сравнению с прогоном без гейта.

Если ни один кандидат не улучшает — защита из doc 16 §7.1 **не внедряется**, а обвал моментума принимается как риск стратегии и ограничивается другими средствами (лимит просадки портфеля, запрет шортов после капитуляции — они не требуют меры стресса).

Пороги (0.6 для меры, 15%/20д для определения эпизода) фиксируются в `params.yaml` до прогона и не подбираются.

### 7.4 Ожидание, записанное заранее

`disp` (кросс-секционная дисперсия) — наиболее вероятный победитель: она измеряет разброс внутри вселенной, то есть напрямую то, от чего зависит моментум, а не косвенную рыночную волатильность. `vol_z_7` — наименее вероятный, поскольку это в точности та форма, что провалилась в doc 19.

Ожидание записано до эксперимента, чтобы результат нельзя было переинтерпретировать задним числом.

## 8. Анализ устойчивости (не оптимизация)

**Оптимизация** — перебрать `L` ∈ {20,30,40,...}, взять лучшее. Запрещено.
**Анализ устойчивости** — прогнать `L` ∈ {30,60,90}, посмотреть, сохраняется ли эффект. Обязательно.

Устойчивая закономерность деградирует плавно, а не обрывается.

Проверить по каждому измерению отдельно:

- окно `L`: 30 / 60 / 90
- пропуск `K`: 0 / 3 / 7 (при `K`=0 ожидается ухудшение — проверка гипотезы о краткосрочном развороте)
- размер портфеля: 5 / 10 / 20
- период ребалансировки: 3д / 7д / 14д
- день недели ребалансировки: все семь
- порог ликвидности вселенной: три уровня
- **разбиение по периодам: 2018–2020 / 2021–2022 / 2023–2026**

Последний пункт важнейший. Если эффект есть только до 2022 года, стратегию запускать нельзя.

В отчёт идёт **таблица всех прогонов**, а не лучший.

## 10. Кросс-рыночная проверка

Та же логика ранжирования, без изменения параметров, на других вселенных:

| Вселенная | Состав | Период |
|---|---|---|
| Секторные ETF США | 11 SPDR-секторов | 1999– |
| Страновые индексы | 20+ MSCI-страновых ETF | 2000– |
| Товары | металлы, энергия, агро | 1990– |
| Валюты | основные пары к USD | 1999– |

**Критерий:** `IC` остаётся положительным и того же порядка.

- Работает везде → сильное свидетельство робастности: кросс-секционный моментум документирован на всех классах активов за десятилетия.
- Только в крипте → возможно крипто-специфика, вероятнее подгонка; требует объяснения, почему механизм уникален.
- Нигде, включая крипту → отрицательный результат, направление закрывается дёшево.

## 12. Антибаг-чеклист

1. **Causality.** Сигнал на дату `t` использует только данные `≤ t`. Для каждого сигнала отдельно.
2. **Разнесение расчёта и исполнения.** Сдвиг цен исполнения на день назад должен заметно улучшить результат.
3. **Смещение выживаемости измерено** (§3.3), число в отчёте.
4. **Делистинги закрываются явно.** Тест на синтетическом делистинге с обвалом −90%.
5. **Издержки применяются** (§4.3).
6. **Молодые токены исключены.**
7. **Секторная разметка датирована** (S10).
8. **Синтетика проходит** (§4.4).
9. **Перемешивание.** Перемешать доходности **поперёк активов внутри дня**: `IC` должен упасть до нуля, преимущество над корзиной исчезнуть.
10. **Веса корректны.** Сумма равна целевой экспозиции, нет отрицательных в long-only, лимиты соблюдаются на каждой дате.
11. **Оборот правдоподобен.** При недельной ребалансировке с буфером — 30–60% в неделю.
12. **Детерминированность.**
13. **IC согласован с IR** (§6.3).
14. **Журнал гипотез непуст** и согласован с числом прогонов.
15. **Кросс-рыночный прогон выполнен.**
16. **Гейт стресса валидирован независимо** (§7, новое в v3). Внедрение защиты без прохождения §7.3 — дефект.

---

## 13. Чего делать не надо

- **Не подбирать параметры.** Разница с анализом устойчивости — §8.
- **Не запускать без вселенной point-in-time.** Прогон на сегодняшнем топ-100 — не предварительный результат, а дезинформация.
- **Не исключать «странные» монеты постфактум.** Если LUNA попала в портфель в апреле 2022-го — она там и остаётся. Это и есть риск стратегии.
- **Не оптимизировать модель издержек в сторону оптимизма.**
- **Не показывать только удачные конфигурации.**
- **Не редактировать журнал задним числом.**
- **Не гнаться за высоким IC.** `IC > 0.15` устойчиво — повод искать ошибку.
- **Не переносить выводы между задачами** (новое в v3). Непригодность меры стресса для защиты BTC не означает непригодности для защиты моментума, и наоборот. Каждое применение валидируется отдельно.

## 15. Заметки на будущее

- Кросс-секционный **разворот** на 1–5 днях — отдельная гипотеза, сильно чувствительнее к издержкам.
- Корреляция стратегии с S1–S8 — считать до внедрения.
- Интеграция с Approval Gate: ребалансировка порождает много сделок, режим подтверждения нужен пакетный.
- Анализ ёмкости: с какого капитала мешает влияние на цену.
- Разложение `IC` по секторам и по размеру: возможно, сигнал работает только в части вселенной.
