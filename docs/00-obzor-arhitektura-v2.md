# Торговая система: обзор и архитектура — v2

> Статус: спецификация до имплементации. Все числовые параметры — стартовые значения, подлежащие проверке на исторических данных.

**Что изменилось в v2:** детектор режима заменён на однострочное правило SMA200 по результатам стенда (`20-itog-sravneniya-detektorov.md`). Удалены состояния `RANGE`, `TRANSITION`, `CRASH`. Матрица аллокации переработана под два состояния. S3 переведена в статус «под вопросом». Обновлён принцип §5.1.

---

## 1. Идея системы в одном абзаце

Система состоит из двух уровней. **Верхний уровень** — детектор режима рынка (бык / медведь), работающий на дневных данных и обновляющийся раз в сутки. **Нижний уровень** — пул стратегий, каждая из которых имеет «родной» режим. Детектор не предсказывает будущее, а распознаёт текущий режим с запозданием в дни–недели; его задача — включать и выключать стратегии и задавать веса капитала. Ядро доходности во всех режимах — рыночно-нейтральный funding-арбитраж; направленные стратегии подключаются только в подтверждённом режиме.

## 2. Архитектура (модули)

```
┌─────────────────────────────────────────────┐
│ 1. Data Layer                               │
│    цены/объёмы (CEX API), funding, OI,      │
│    on-chain, macro                          │
└──────────────┬──────────────────────────────┘
               │
┌──────────────▼──────────────────────────────┐
│ 2. Regime Detector (док. 01 v5)             │
│    close > SMA200 → BULL, иначе BEAR        │
│    + модификаторы (не влияют на состояние)  │
└──────────────┬──────────────────────────────┘
               │
┌──────────────▼──────────────────────────────┐
│ 3. Allocator                                │
│    режим + модификаторы → веса капитала     │
└──────────────┬──────────────────────────────┘
               │
┌──────────────▼──────────────────────────────┐
│ 4. Strategy Pool (док. 02 v2)               │
│    S1 funding-arb │ S2 momentum │ S3 (?)    │
│    S4 bear-yield  │ S5 unlock   │ S6 ladder │
└──────────────┬──────────────────────────────┘
               │
┌──────────────▼──────────────────────────────┐
│ 5. Execution + Risk Monitor (док. 03 v2)    │
│    ордера, контроль маржи, лимиты, алерты   │
└─────────────────────────────────────────────┘
```

**Важное уточнение о слое данных.** On-chain, макро и ширина рынка **не участвуют в определении состояния** — они модификаторы, влияющие на размер позиции (`01-detektor-rezhima-v5.md` §2). Состояние определяется исключительно ценой.

## 3. Пул стратегий и их режимы

| ID | Стратегия | Родной режим | Роль |
|----|-----------|--------------|------|
| S1 | Funding-арбитраж (delta-neutral) | все; основной вес при `state ≠ BULL` | Ядро, база доходности |
| S2 | Momentum-ротация топ-N монет | BULL | Основной направленный доход |
| S3 | Mean reversion в диапазоне | **под вопросом**, см. ниже | Не активна |
| S4 | Кэш в стейблах + доходность | BEAR | Сохранение капитала |
| S5 | Event-шорты под токен-разлоки | BEAR | Спутник, малый капитал |
| S6 | Лестница накопления по капитуляции | поздний BEAR | Подготовка к следующему циклу |

**Про S3.** Гейтилась на состоянии `RANGE`, которого больше нет. Проверка показала убыточность канонического дневного mean reversion **в обоих режимах**: −34% годовых на BTC, −80% на ETH (`21-granicy-detektora-i-naklon-sma-v2.md` §4.3). Статус — не «ждём гейт», а «возможно, стратегии нет». До проверки с нулевыми издержками (doc 21 v2 §5.1) капитал не выделяется.

## 4. Матрица аллокации (стартовая)

Доли от общего капитала. Два состояния вместо четырёх.

| Стратегия | BULL | BEAR |
|-----------|------|------|
| S1 funding-arb | 50% | 30%* |
| S2 momentum | 35% | 0% |
| S3 mean-rev | 0% | 0%** |
| S4 стейблы + yield | 5% | 55% |
| S5 unlock-шорты | 0% | 10% |
| S6 лестница накопления | 0% | 0–15%*** |
| Свободный резерв | 10% | 5% |

\* В медвежку funding часто отрицательный или нулевой — S1 работает только при положительном скользящем funding, иначе капитал уходит в S4.
\** S3 не активна до разрешения вопроса §3.
\*** Включается только по триггерам капитуляции (док. 02 v2, S6), забирает долю из S4.

**Модификаторы поверх матрицы:**

| Модификатор | Действие |
|---|---|
| `cycle_phase = EUPHORIA` | запрет наращивания, срезание плечевого лимита |
| `cycle_phase = ACCUMULATION` | разрешает S6 |
| `macro_flag = −1` | целевая экспозиция × 0.75 |
| `breadth < 0.35` | S2 не запускается даже в BULL |
| `leverage_warning` | сигнал риск-модулю |
| `stress_level` | **диагностический, на решения не влияет** |

## 5. Принципы, которые не обсуждаются

1. **Детектор медленный и простой — и это результат измерения, а не выбор вкуса.** Композит из четырёх параметров не превзошёл однострочник на кросс-рыночной проверке. Детектор выбран как самый дешёвый среди статистически неразличимых, а не как доказанно лучший. Строить на нём конструкции, которые сломаются при его ошибке, нельзя.
2. **Никакая направленная стратегия не работает без разрешения детектора.** Даже если сигнал стратегии идеален.
3. **Параметры не оптимизируются под историю.** Веса и пороги назначаются из логики; бэктест проверяет устойчивость, а не подбирает максимум.
4. **Тривиальный бенчмарк прогоняется до постройки сложного, а не после.** Главный процессный урок детекторного направления (`15-…-v5.md` §4.1).
5. **Комиссии и проскальзывание считаются в каждом бэктесте** по пессимистичной модели (док. 04).
6. **Плечо ≤ 3x и только в нейтральных конструкциях** (шорт-нога funding-арбитража). Направленные позиции — без плеча.
7. **Минимум 2 биржи** для распределения контрагентского риска.
8. **Отвергнутое не возвращается без нового основания.** Реестр — `rejected.md`, сводка — `00-index-i-status-v2.md` §3.

## 6. Дорожная карта имплементации

| Этап | Содержание | Критерий выхода | Статус |
|------|-----------|-----------------|--------|
| 0. Данные | Свечи D1, funding history, OI, on-chain. Хранилище | 3+ года по BTC/ETH/топ-50 без дыр | выполнено |
| 1. Детектор режима | SMA200 по док. 01 v5 | внедрён, S1 переведена на `state ≠ BULL` | **текущий** |
| 2. Бэктест-движок | Каркас: события, комиссии, отчёты | воспроизводимость, тест на look-ahead | частично (стенд детекторов) |
| 3. S1 funding-arb | Первая живая стратегия | paper trading 1 мес. | — |
| 4. Кросс-секция | Вселенная point-in-time → корзина → S2 | корзина посчитана **до** S2 | следующий |
| 5. S5 unlock | Пайплайн расписаний разлоков | event study на свежих данных | — |
| 6. Малый капитал live | 5–10% планируемого капитала | 3 мес. без расхождений paper vs live | — |

Этап 4 заменил прежний «S2 + S3»: направление уточнено до кросс-секционного (`16`, `17`), S3 из плана исключена до разрешения вопроса.
