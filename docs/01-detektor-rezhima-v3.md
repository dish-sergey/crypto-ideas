# Детектор режима рынка — v3

**Статус:** ревизия v2 (`01-detektor-rezhima-v2.md`).
**Причина ревизии:** состояние `CRASH` и ось `S` удаляются по результатам диагностики (`18-ispravlenie-zalipaniya-crash-v2.md`, фаза A). Основная архитектура — оси `D` и `T` плюс модификаторы — сохраняется без изменений: она подтвердила свою ценность экономически.

**Главный результат измерений:** без `CRASH` детектор даёт **−7.2 п.п. CAGR за +51.5 п.п. снятой просадки** (отношение 0.14), с `CRASH` — **−13.0 п.п. за +51.4 п.п.** (отношение 0.25). Максимальная просадка в обоих случаях −25.2%. Состояние стоило 5.8 пункта доходности в год и не покупало ничего.

---

## 0. Что изменилось и почему

### 0.1 Итог диагностики

| Измерение | Результат | Вывод |
|---|---|---|
| A1 | `dd_speed` доминирует в 85% дней с `S ≥ 0.5`, с 1-го дня эпизода — 87%, к 16-му дню — 95% | храповик подтверждён; он тянул и вход, не только выход |
| A2 | серии `dd_speed` над 0.5 до 41 дня против 13 у `vol_z`; автокорреляция вдвое длиннее | прямое подтверждение храповика |
| A3 | склейка 23 → 21 эпизод, 3.2/год | триггер откалиброван, проблема **только** в длительности |
| A4 | вариант без CRASH: CAGR 32.7% против 26.9%, MaxDD идентичен −25.2% | **CRASH строго хуже, а не просто не лучше** |
| A5 | до 88 дней вне рынка на эпизод; 42% восстановления марта 2020 пропущено | цена дефекта выше, чем видно по одной метрике |
| A6 | 125 дней CRASH внутри истинного BULL; `false_bear_rate` 19.6% против 12.2% | самая дорогая ошибка подтверждена |
| A7 | среднее `passed` = 53% | защищает частично; решение переходит к экономике |
| A8 | корреляция с voltarget 0.34; ноль дней опережения | voltarget не опережает CRASH |

### 0.2 Почему CRASH оказался чистым расходом

Механизм следует из матрицы аллокации. В `BEAR` и `RANGE` экспозиция уже 0%. `CRASH` отличался от них ровно двумя вещами:

1. мгновенный выход вместо реаллокации за 5 дней — выигрыш микроскопический;
2. обход dwell-lock с обнулением таймера — **блокировка возврата на 15 дней после выхода**.

Портфель и так был бы в кэше. `CRASH` только мешал вернуться. Отсюда идентичный MaxDD при потере 5.8 п.п. CAGR.

### 0.3 Честная оговорка

Вариант «CRASH → BEAR без мгновенного выхода» дал MaxDD −24.0% — на 1.2 п.п. лучше варианта без CRASH, ценой 0.8 п.п. CAGR. То есть **сам триггер что-то ловит** (это согласуется с отрицательными отскоками +5д/+10д в A7).

Но разница в пределах шума при одной выборке из 6.6 лет. При ничьей правило отсечения сложности предписывает простое. **Решающий аргумент — простота, а не превосходство.**

### 0.4 Что осталось незакрытым

**Volatility targeting не подтвердил ожиданий.** В прогоне A4 он дал MaxDD −75.0% при −76.6% у buy & hold, Sharpe 0.81 против 0.86 у B&H, отношение 4.12. Как реализовано — не работает.

Из этого следует важное ограничение для настоящего документа: **нельзя заменять провалившуюся сложную конструкцию на непроверенную простую в предположении, что та сработает.** Поэтому `stress_level` ниже вводится с явной пометкой «не валидирован» и без права влиять на состояние. Разбор причин — `19-razbor-voltarget.md`.

## 1. Требования (без изменений с v2)

| Требование | Следствие в конструкции |
|---|---|
| Ошибка «не переключился» дешевле ошибки «дёргается» | dwell-time lock |
| Выход потребляется аллокатором, а не входным сигналом | дискретное состояние + непрерывный confidence |
| Данные могут отвалиться | нейтральное значение по умолчанию у каждого компонента |
| История коротка (~3 цикла) | минимум свободных параметров, никакой оптимизации |
| Запаздывание 2–6 недель приемлемо | медленные устойчивые метрики |

Детектор оптимизируется **не на точность классификации, а на экономику**: сколько просадки снимает и сколько доходности стоит.

## 2. Архитектура: две оси и модификаторы

```
D  — Direction   ∈ [−1, +1]   направление долгосрочного тренда
T  — Trendiness  ∈ [0, 1]     насколько движение направленное, а не пилообразное
```

Модификаторы (не участвуют в определении состояния, передаются аллокатору отдельно):

```
cycle_phase      ∈ {ACCUMULATION, EARLY, MID, LATE, EUPHORIA}   — из on-chain
macro_flag       ∈ {−1, 0, +1}                                  — из макро
breadth          ∈ [0, 1]                                       — ширина рынка
leverage_warning ∈ {true, false}                                — из деривативов
stress_level     ∈ [0, 1]                                       — НОВОЕ, см. §2.4, НЕ ВАЛИДИРОВАН
```

### 2.1 Ось D — направление (без изменений)

```
dist  = (close − SMA200) / ATR90
slope = (SMA200_t − SMA200_{t−30}) / ATR90

D = 0.7 · clip(dist / 4, −1, +1) + 0.3 · clip(slope / 1.5, −1, +1)
```

Данные: дневные свечи BTC/USDT, ccxt.

### 2.2 Ось T — трендовость (без изменений)

```
ER      = |P_t − P_{t−90}| / Σ|P_i − P_{i−1}|
R2      = R² линейной регрессии log(P) по времени, окно 90 дней
ADX_n   = clip((ADX(14) − 15) / 25, 0, 1)

T_raw = median(ER_norm, R2, ADX_n)
T     = процентильный ранг T_raw по скользящему окну 3 года
```

### 2.3 Ось S — удалена

Компоненты и их судьба:

| Компонент | Судьба | Основание |
|---|---|---|
| `dd_speed` | **удалён полностью** | храповик по построению (A1, A2); информация о глубине просадки уже содержится в `D` |
| `vol_z` | перенесён в модификатор `stress_level` | описывает фон, а не событие |
| `liq_pct` | зарезервирован для внутридневного контура (§7) | на дневных данных бесполезен (A7) |

`dd_speed` не подлежит восстановлению ни в какой форме: величина убывает только при росте цены либо при выкатывании старого пика из окна, то есть удерживает высокое значение календарное время независимо от рынка. Это дефект определения, а не параметра.

### 2.4 stress_level — новый модификатор, не валидирован

```
stress_level = clip( vol_z / 3, 0, 1 )     # z-score реализованной волатильности 7д к 1 году
```

**Статус: экспериментальный.** По умолчанию **выключен** (`stress_multiplier_enabled: false` в конфиге).

Предполагаемое использование при включении:

```
множитель_экспозиции = 1 − 0.5 · stress_level
```

**Почему выключен по умолчанию.** Механизм родственен volatility targeting, который в A4 не сработал (§0.4). Пока не установлено, почему именно, включать его нельзя: это была бы замена измеренно-вредной конструкции на непроверенную.

**Условие включения:** результаты `19-razbor-voltarget.md` объясняют провал и показывают, что данная форма от него свободна. До этого `stress_level` вычисляется, логируется и передаётся в выходной контракт, но **не влияет ни на состояние, ни на экспозицию**.

**Второй потребитель.** Мера стресса нужна не только аллокатору: `16-kross-sekcionnye-strategii.md` §7.1 использует порог `S ≥ 0.6` для защиты от обвала моментума. Этот потребитель сохраняется и должен читать `stress_level`. Валидация под эту задачу — отдельная, в рамках doc 17: защита от обвала моментума и управление экспозицией BTC — разные задачи, и пригодность величины для одной не доказывает пригодности для другой.

### 2.5 Модификаторы cycle_phase, macro_flag, breadth, leverage_warning

Без изменений с v2 §2.4.

## 3. Классификация состояния

Пять состояний вместо шести. Порядок проверки сверху вниз, первое сработавшее выигрывает.

```
1. если дней_в_текущем_состоянии < 15     → текущее состояние (dwell-time lock)
2. если T < 0.40                          → RANGE
3. если T ≥ 0.40 и D > +0.20              → BULL
4. если T ≥ 0.40 и D < −0.20              → BEAR
5. иначе                                  → TRANSITION
```

Отличия от v2:

- **Правило `S ≥ 0.80 → CRASH` удалено.** Основание — A4: состояние строго хуже отсутствия состояния.
- **Dwell-time lock больше не имеет исключений.** Раньше `CRASH` его обходил и обнулял таймер; это и было основным механизмом ущерба (A5).
- Правила 2–5 не изменились.

### 3.1 Confidence

```
agreement   = 1 − |D_price_dist − D_price_slope| / 2
clarity     = |D|
persistence = clip(дней_в_состоянии / 30, 0, 1)

confidence = 0.4·clarity + 0.3·agreement + 0.3·persistence
confidence *= 0.7  если leverage_warning
confidence *= (1 − 0.15 · число_отвалившихся_источников)
```

Без изменений с v2.

## 5. Измеренная экономика

Прокси-аллокация BULL 100% / TRANSITION 50% / остальное 0% (кэш 8%), реаллокация 5 дней, издержки 0.10% с оборота. Окно 2020-01-01 … 2026-07-23.

| Конфигурация | CAGR | MaxDD | Sharpe | ΔMaxDD/ΔCAGR |
|---|---|---|---|---|
| buy & hold | 39.9% | −76.6% | 0.86 | — |
| v2 (с CRASH) | 26.9% | −25.2% | 0.92 | 0.25 |
| **v3 (без CRASH)** | **32.7%** | **−25.2%** | **1.04** | **0.14** |
| voltarget | 33.3% | −75.0% | 0.81 | 4.12 |

**Основная архитектура себя оправдывает:** оси `D` и `T` снижают просадку с −76.6% до −25.2%, отдавая 7.2 п.п. CAGR. Отношение 0.14 — это и есть главное число проекта на текущий момент.

Оговорка о точности: `SE(Sharpe) ≈ 0.48` при 6.6 годах, поэтому 1.04 против 0.92 само по себе неотличимо от шума. Вывод опирается не на Sharpe, а на доминирование по паре CAGR/MaxDD при идентичной просадке — это существенно сильнее, но выборка по-прежнему одна.

## 6. Правила, защищающие от самообмана

1. **Параметры фиксируются до бэктеста.** Пороги `T < 0.40`, `|D| > 0.20`, dwell 15 дней перенесены из v2 без изменений и не перекалибровывались после удаления `CRASH`. Это важно: соблазн «раз конструкция изменилась, подстроим пороги» — прямой путь к подгонке.
2. **Оптимизация порогов запрещена.**
3. **Корреляционный контроль.** Посчитать `corr(D, T)` и `corr(breadth, D)`. Ожидание: `corr(breadth, D) > 0.7`.
4. **Point-in-time данные обязательны.**
5. **Отказ данных = нейтраль**, confidence снижается.
6. **Детектор не меняется под стратегию.**
7. **Удалённое не возвращается без нового основания** (новое в v3). `dd_speed` и состояние `CRASH` удалены на основании измерений. Возврат требует не аргумента «а давайте попробуем иначе», а нового измерения, опровергающего A4.

## 7. Открытые вопросы

1. **Проверить точное совпадение MaxDD** в вариантах 1 и 3 (−25.2% в обоих). Вероятное объяснение безобидное: максимум просадки приходится на период, где варианты ведут себя одинаково. Найти дату максимума и убедиться, что это так, а не артефакт расчёта. **Приоритет высокий** — от этого зависит надёжность основного вывода.
2. **Кросс-рыночная проверка** (`15` §8) для v3: ETH, SPY, золото, нефть, EUR/USD. Стоит дёшево, а выборка сейчас одна.
3. **Разбор провала voltarget** — `19-razbor-voltarget.md`. От результата зависит судьба `stress_level`.
4. **Внутридневной контур для S7.** A7 показал: среднее `passed` = 53%, при этом отскок +5д в среднем −8.0%. То есть паника на дневных данных распознаётся к моменту, когда половина движения пройдена, а последующие дни продолжают падение. Для S7 (выкуп паники) нужен отдельный детектор на 15м–1ч с лентой ликвидаций; `liq_pct` зарезервирован под него. Потребитель — только S7, не аллокатор.
5. **Валидация `stress_level` под задачу S2/S9** (защита от обвала моментума, doc 16 §7.1) — отдельно от задачи управления экспозицией BTC.
6. **BTC как единственный прокси**, **двухуровневый детектор**, **альтернативные алгоритмы классификации** — перенесены из v2 §8 без изменений.

## Приложение. Что не подтвердилось из прогнозов

Фиксируется намеренно: прогнозы, сделанные до эксперимента, должны сверяться с результатом, иначе они бесполезны.

| Прогноз (doc 18) | Факт | Следствие |
|---|---|---|
| Склейка эпизодов выявит мерцание, останется 10–12 событий, частота ниже коридора | 23 → 21, частота 3.2/год в коридоре | триггер был откалиброван верно; отметка в чеклисте §10.6 остаётся в силе |
| `vol_z` лидирует в дни 1–3, `dd_speed` перехватывает позже | `dd_speed` доминирует с 1-го дня (87%) | храповик тянул и срабатывания, не только выход |
| `passed > 70%` → детектор фиксирует убыток | 53%, разброс 30–73% | развилка ушла к экономике, и та дала однозначный ответ |
| voltarget может побить композит | MaxDD −75.0%, Sharpe 0.81 — хуже B&H | нельзя опираться на него как на замену; см. doc 19 |

Из четырёх прогнозов подтвердился один (храповик), причём сильнее ожидаемого. Три остальных — нет. Это нормальная пропорция и повод не доверять следующим прогнозам сильнее, чем они заслуживают.
