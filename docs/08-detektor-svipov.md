# Doc 08 — Детектор ликвидационных sweep'ов и интеграция с S7 (fade-panic)

**Статус:** спецификация к реализации
**Зависимости:** doc 01 (regime detector), doc 02 (S7), doc 03 (риск-менеджмент), doc 04 (методология бэктеста), doc 05 (news module — калибровка вокруг событий)

---

## 1. Назначение

Детектор идентифицирует **ликвидационный sweep** — прокол значимого уровня, собирающий кластер ликвидаций/стопов, с последующим быстрым возвратом за уровень. Событие используется:

1. Как **триггер входа** для S7 (fade-panic).
2. Как **фильтр-запрет** для трендовых стратегий (не входить по пробою, который классифицирован как sweep).
3. Как **источник статистики** для валидации гипотезы о микроструктурной охоте за ликвидностью на конкретном инструменте.

Ключевая гипотеза: после подтверждённого sweep'а топливо в сторону прокола выгорело (позиции ликвидированы, стопы собраны), и вероятностное преимущество на горизонте минут–часов смещено в противоположную сторону.

## 3. Карта магнитных уровней

Поддерживается на каждом баре как список `Level = {price, type, weight, created_at}`.

### 3.1. Типы уровней

- **SWING**: локальные экстремумы за окна 4h / 24h / 72h (rolling min/max по 1m-закрытиям с подтверждением фрактала: экстремум окружён N=3 барами с обеих сторон).
- **ROUND**: круглые числа. Шаг сетки зависит от цены: для цены P шаг = 10^floor(log10(P)) × {0.25, 0.5, 1.0}; в скоринг идёт только ближайший уровень каждой градации.
- **HVN/LVN**: узлы volume profile за 72h (POC, границы value area, локальные минимумы профиля).

### 3.2. Веса

Базовый вес по типу: SWING 24h = 1.0, SWING 72h = 0.8, SWING 4h = 0.5, ROUND (крупная градация) = 0.4, HVN = 0.4.

Модификаторы:
- **Конфлюэнция**: уровни разных типов в пределах 0.15 × ATR(14, 1h) друг от друга сливаются в один, веса суммируются с коэффициентом 0.8 на каждый добавочный.
- **Свежесть**: вес × exp(−age_hours / 96) для SWING-уровней.
- **Ретесты**: каждый предыдущий отбой от уровня без пробоя: вес × 1.15 (капается на 1.5× от базового).

Уровень считается **активным магнитом**, если итоговый вес ≥ `W_min` (дефолт 0.8).

## 4. Условия события SWEEP

Событие фиксируется **только на закрытии бара возврата** (см. §8 про look-ahead). Все условия обязательны (AND):

### 4.1. Прокол (bar B0 … Bk)

- Цена пробила активный магнитный уровень L: экстремум прокола за пределами L на глубину `D`, где `D ∈ [0.3, 0.8] × ATR(14, 1h)` (нормировка в ATR, не в процентах).
- Прокол глубже `D_max = 2.0 × ATR` → событие **отменяется** (это уже импульсный пробой, не sweep).

### 4.2. Объём

- Объём бара(-ов) прокола ≥ `K_vol` × медианного объёма 1m-бара за 24h. Дефолт `K_vol = 2.5`.

### 4.3. Ликвидации

- Суммарный объём ликвидаций в сторону прокола за окно [B0−1; Bk] ≥ `K_liq` × SMA объёма ликвидаций того же инструмента за 7 дней (нормировка на собственный фид — не на абсолюты, см. §8). Дефолт `K_liq = 4.0`.

### 4.4. Возврат

- Закрытие 1m-бара обратно за уровнем L (со стороны исходного диапазона) в течение `T_ret` минут от первого касания L. Дефолт `T_ret = 12` мин, диапазон калибровки [5; 20].
- Нет возврата за `T_ret` → событие классифицируется как **BREAKOUT**, публикуется в шину для трендовых стратегий, S7 запрещена на этом уровне на 4h.

## 5. Скоринг события

Событие не бинарное. Итоговый `sweep_score ∈ [0; 100]`:

| Компонент | Диапазон баллов | Логика |
|---|---|---|
| Вес уровня | 0–15 | Линейно от W_min до 2×W_min |
| Глубина прокола | 0–15 | Пик при 0.5–0.8 ATR, спад к границам |
| Кратность объёма | 0–15 | Линейно от K_vol до 3×K_vol, далее плато |
| Ликвидации | 0–20 | Лог-шкала от K_liq |
| Funding-контекст | 0–15 | Максимум, если funding был экстремален **в сторону, противоположную проколу до события** (пробили лоу при перегретых лонгах: funding ≥ +0.05%/8h → полный балл; funding в сторону прокола → 0) |
| Падение OI на проколе | 0–12 | ΔOI ≤ −1% за окно прокола → пропорционально до −3% |
| Разворот дельты | 0–8 | Доминация маркет-селлов на проколе + маркет-баев на возврате |

Пороги:
- `score ≥ S_trade` (дефолт 55) → торговое событие для S7.
- `S_watch ≤ score < S_trade` (дефолт 35–55) → логируется, не торгуется (материал для калибровки).
- Пороги S_trade, K_vol, K_liq, T_ret, D — параметры walk-forward оптимизации (см. §9).

## 6. Торговая логика S7 на событии

### 6.1. Вход

- **Не входить на проколе.** Вход после фиксации события, двумя вариантами (выбор — параметр):
  - `ENTRY_CLOSE`: маркет/лимит по закрытию бара возврата.
  - `ENTRY_RETEST`: лимит на ретесте уровня L со стороны диапазона, TTL ордера 30 мин; нет ретеста → пропуск.
- Направление: противоположно проколу (пробили лоу → лонг).

### 6.2. Стоп

- За экстремумом прокола + буфер `0.25 × ATR(14, 1h)`.
- Инвалидация гипотезы: повторный уход цены за экстремум прокола = продавцы не кончились → выход без условий, никаких пересиживаний.

### 6.3. Выходы

- **TP1** (50% позиции): ближайший из — середина диапазона до пробоя / противоположный магнитный кластер / 1.5R.
- **Остаток**: трейлинг по структуре (за локальные экстремумы 5m) либо тайм-стоп `T_max = 8h` — sweep-эффект короткоживущий, позиция, не поехавшая за часы, статистически мертва.

### 6.4. Сайзинг

- Базовый риск на сделку — по doc 03.
- Понижающий коэффициент по score: `size_mult = 0.5 + 0.5 × (score − S_trade)/(100 − S_trade)`, кап 1.0.
- Стандартные лимиты корреляции и совокупного риска из doc 03 применяются без исключений.

## 7. Режимная привязка (интеграция с doc 01)

| Режим | Поведение S7-sweep |
|---|---|
| RANGE | Разрешена полностью, обе стороны |
| WEAK_TREND | Разрешена, но фейд **по направлению** тренда получает бонус к score (+5), фейд против тренда — штраф (−10) |
| STRONG_TREND | Разрешён только фейд sweep'ов **против** тренда (в аптренде — только лонг после прокола лоу). Фейд по направлению против тренда запрещён жёстко |
| CRISIS / NEWS_LOCKOUT (doc 03, 05) | Детектор работает (собирает статистику), торговля запрещена. Вокруг событий календаря (doc 05) — lockout-окно ±30 мин |

Переключение режима **во время открытой позиции** не закрывает её принудительно, но отменяет добавления и ужесточает трейлинг (переход на 1m-структуру).

## 8. Бэктест-ловушки (обязательные требования к реализации, doc 04)

1. **Look-ahead на возврате.** Событие существует только с момента закрытия бара возврата. Вход `ENTRY_CLOSE` — по цене не лучше закрытия этого бара + слиппедж; вход в бэктесте на том же баре по цене внутри бара — запрещён.
2. **Неполнота liquidation feed.** Binance с 2021 транслирует ≤1 ордер/сек/инструмент — исторические абсолюты занижены и неоднородны во времени. Поэтому нормировка **только на скользящую статистику того же фида** (7d SMA), никаких абсолютных порогов в USD. При смене политики биржи — разрыв в данных помечается, walk-forward сегменты не должны пересекать разрыв.
3. **Слиппедж.** Вход происходит в момент всплеска волатильности. Модель исполнения: слиппедж ≥ 2.5× среднего спреда инструмента за спокойные периоды, для `ENTRY_CLOSE` — консервативнее, чем для `ENTRY_RETEST` (лимитник). Sensitivity-анализ: стратегия обязана оставаться прибыльной при 2× заложенного слиппеджа, иначе — в стол.
4. **Survivorship вселенной.** Вселенная инструментов фиксируется на начало каждого walk-forward сегмента по данным, доступным на тот момент (листинги/делистинги учитываются, см. doc 04).
5. **Множественные уровни.** Один прокол может задеть несколько магнитов — событие агрегируется по самому весомому, дубли в пределах 0.3 ATR подавляются (иначе бэктест накрутит фантомную частоту сигналов).
6. **Funding-снэпшоты.** Использовать значение funding, известное **до** начала прокола, не расчётное на конец периода.

## 9. Параметры walk-forward оптимизации

**Оптимизируются** (грубая сетка, walk-forward по doc 04):
`D` (глубина, в ATR), `K_vol`, `K_liq`, `T_ret`, `S_trade`, выбор `ENTRY_CLOSE` vs `ENTRY_RETEST`, `T_max`.

**Фиксируются** (не оптимизировать — источник переобучения при малой выборке):
структура скоринга и веса компонентов, `D_max`, буфер стопа, режимные правила из §7, `W_min`.

**Критерии принятия** (в дополнение к общим из doc 04):
- ≥ 100 событий `score ≥ S_trade` на инструмент-сегмент, иначе выборка недостаточна — результат не интерпретируется.
- Устойчивость знака edge при ±30% вариации каждого оптимизируемого параметра по отдельности.
- Профит сохраняется при 2× слиппедже (§8.3).
- Проверка деградации по подпериодам: edge, живущий только в одном квартале истории, считается артефактом.

## 10. Метрики мониторинга (production)

- Частота событий по инструментам vs бэктест-ожидание (дрейф > 2× — флаг на пересмотр).
- Win-rate и средний R по бакетам score (валидация, что score реально ранжирует качество).
- Доля событий, отменённых как BREAKOUT (баланс sweep/breakout — прокси смены микроструктуры инструмента).
- Фактический слиппедж входов vs модельный.
- Логирование ВСЕХ событий `score ≥ S_watch` c полным контекстом — датасет для будущей рекалибровки.

## 11. Открытые вопросы / следующие итерации

- L2-подтверждение (испарение стен при подходе цены) — только forward-сбор данных, интеграция после накопления ≥ 3 мес. истории (пересекается с doc 06).
- Кросс-инструментные sweep'ы (BTC-прокол как триггер событий на альтах с лагом) — кандидат в S8-логику (doc 05).
- Он-чейн подтверждение (притоки на биржи перед проколом) — низкий приоритет, высокий шум.
