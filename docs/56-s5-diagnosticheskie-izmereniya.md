# S5: два диагностических измерения — без изменения протокола

**Назначение:** задание для исполнителя (Claude Code).
**Статус:** **диагностика, не пересмотр стратегии.** Протокол `54-…md` остаётся в силе без изменений; микро-live запускается по нему.
**Повод:** два вопроса о структуре премии, ответы на которые нужны до появления живых данных, а не после.

---

## 0. Рамка: почему это не пересмотр

Мы на пороге запуска. Обе проверки касаются возможных изменений стратегии, и здесь есть конкретный риск: **начать крутить конструкцию по результатам того же бэктеста, на котором она построена.**

Именно так умирает дисциплина: не одним решением, а серией разумных на вид уточнений.

**Правило для этого задания:**

| Что можно | Что нельзя |
|---|---|
| измерить и записать | изменить протокол по результату |
| получить разложение премии | добавить гейт или хедж «раз уж посмотрели» |
| использовать как ориентир при сверке с живыми данными | пересчитать ожидания в сторону улучшения |

**Любое изменение правил требует новой фиксации критериев** и отдельного решения, а не следует из этих измерений автоматически.

Микро-live идёт по протоколу `54` как есть.

## 1. Измерение A: премия против размера разлока

### 1.1 Вопрос

Порог единый — ≥3% циркулирующего supply. Но 3% и 30% — разные события: при малом разлоке трудно ожидать заметного давления на цену.

Если премия растёт с размером, это основание не для сдвига порога, а для **сайзинга**: давать больше капитала крупным событиям в пределах того же лимита на позицию.

### 1.2 Что посчитать

```
Бины по размеру разлока (% circulating):
    3–5%, 5–10%, 10–20%, 20%+

В каждом бине:
    число событий
    премия над безусловной 5-дневной шорт-доходностью
    медиана, доля прибыльных
    худшие 10%
```

**Обязательно показывать число событий в каждом бине.** Крупные разлоки редки, и в верхних бинах выборка редеет — именно там мы дважды обожглись: на глубине падения в S7 (n=2–6) и на дециле из 16 имён в S12.

### 1.3 Как читать

| Результат | Смысл |
|---|---|
| Премия монотонно растёт, выборки достаточны | основание для сайзинга по размеру |
| Премия не зависит от размера | размер разлока не драйвер; механизм в чём-то другом |
| Растёт только в бинах с n < 20 | шум, игнорировать |

**Ожидание, записанное до расчёта:** слабая положительная связь, но не монотонная — размер важен, однако его влияние размывается ликвидностью инструмента и тем, насколько событие ожидаемо.

## 2. Измерение B: разложение премии на событийную и рыночную

**Это главное измерение задания.**

### 2.1 Вопрос

Доходность шорта складывается из двух компонент:

```
результат = премия события + общее движение рынка
```

Вторая к разлоку отношения не имеет. Шорт в растущем рынке — это шорт против общего движения, и сквизы там вероятнее. **Худшая сделка −189% почти наверняка пришлась на бычий отрезок.**

У нас есть детектор SMA200, который сейчас **ничего не гейтит для S5**. Прежде чем решать, должен ли он это делать, надо измерить, сколько премии приходится на каждую компоненту.

### 2.2 Что посчитать

```
Для каждой сделки:
    результат_шорта
    доходность BTC за те же 5 дней
    бета токена к BTC (окно 90 дней до входа)
    остаточная премия = результат_шорта + бета × доходность_BTC
                        (знак: шорт выигрывает от падения рынка)

Отчёт:
    средняя премия сырая против остаточной
    разложение: сколько из +2.49% приходится на событие, сколько на рынок
```

### 2.3 Разбиение по состоянию детектора

```
Разделить события по state детектора SMA200 на дату входа:
    BULL: число событий, премия сырая, премия остаточная, худшие 10%
    BEAR: то же
```

**Это ключевая таблица задания.**

### 2.4 Как читать

| Результат | Смысл | Следствие (не действие) |
|---|---|---|
| Остаточная премия ≈ сырой | событие — основной драйвер | гейт не нужен, конструкция чиста |
| Остаточная существенно ниже | значительная часть премии — рыночная бета | без хеджа стратегия частично направленная |
| Премия в BULL заметно хуже, хвост толще | шорт против тренда дорог | основание рассмотреть гейт **отдельным решением** |
| Худшие сделки сконцентрированы в BULL | сквизы связаны с рынком | то же |

**Ожидание, записанное до расчёта:** остаточная премия окажется ниже сырой, но останется положительной; худшие сделки сконцентрируются в BULL. Основание — механика сквиза и то, что бэктест покрывает 2022 (медвежий, шорт выигрывал) и 2025–26.

## 3. Три варианта, которые могут появиться по результату

**Ни один не внедряется сейчас.** Фиксируются, чтобы решение потом принималось из заранее описанного набора, а не изобреталось под результат.

| Вариант | Что делает | Цена |
|---|---|---|
| **Гейт по режиму** | не шортить в BULL | режет число событий, а их и так ~5/мес |
| **Хедж рынком** | шорт токена + лонг BTC на ту же сумму | вторая нога: комиссии, funding, сложность |
| **Ничего** | оставить как есть | принимаем рыночную компоненту как часть риска |

**Гейт особенно опасен по частоте:** при ~5 событиях в месяц отсечение BULL может оставить 2–3, и двадцать событий наберутся за год вместо четырёх месяцев.

**Хедж чище методически, но дороже:** удваивает число ног, а премия и так скромная (+2.49% на сделку, ≈+13 п.п. на портфель).

Решение принимается **после** микро-live, когда будут и разложение, и живые данные — а не сейчас на одном бэктесте.

---

## 4. Что делать с результатами

### 4.1 Записать как ориентир для сверки

Разложение из §2 — это **то, с чем будут сверяться живые данные**. Если в микро-live реализованная премия окажется ниже модельной, разложение подскажет, где искать: в событийной компоненте или в рыночной.

Без него расхождение будет необъяснимым.

### 4.2 Внести в журнал гипотез

```
| — | премия растёт с размером разлока | §1 | | |
| — | остаточная премия (за вычетом рынка) остаётся положительной | §2 | | |
| — | худшие сделки сконцентрированы в BULL | §2.3 | | |
```

### 4.3 Не менять ожидания

Оценка ≈ +13 п.п. остаётся. Даже если разложение покажет, что событийная компонента чище, **это не повод повышать оценку**: премия уже помечена как верхняя граница из-за смещения расписаний.

---

## 5. Чего не делать

- **Не менять протокол `54` по результатам этих измерений.**
- **Не добавлять гейт или хедж** без отдельного решения с новой фиксацией критериев.
- **Не сдвигать порог 3% circulating** ни в какую сторону.
- **Не полагаться на бины с n < 20** (§1.2).
- **Не пересчитывать ожидаемую доходность вверх** (§4.3).
- **Не откладывать запуск микро-live** ради этих измерений — они параллельны, не блокирующие.

| Задача | Блокирует запуск? |
