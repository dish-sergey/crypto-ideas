# ТЗ для Claude Code: оптимальный размер позиции для S5 с учётом ошибки оценки

**Позиции каталога:** C2 (M-kelly-shrink) + H1 (S38), частично H3 (S40). Док. `64` §Блок C, §Блок H.

**Что строим.** Счётный модуль, который по существующему датасету событий S5 (токен-разлоки) даёт: распределение оценки оптимального размера позиции, честный размер с учётом ошибки оценки, и распределение исходов при разных размерах.

**Что НЕ строим.** Изменений в идущем микро-live S5. **Правило одного изменения:** расчёт делается параллельно, результат применяется на следующей итерации после отдельного решения.

---

## 0. Главное предупреждение исполнителю

**Формула Kelly `f* = μ/σ²` при подстановке точечной оценки `μ̂` систематически завышает размер, и завышение тем сильнее, чем меньше `N`.** Это не тонкость — при `N ≈ 40` и крипто-дисперсии исходов ошибка может быть в разы.

Три источника завышения, и каждый должен быть обработан отдельно:

1. **Ошибка оценки `μ`.** `μ̂` — случайная величина. `f*` нелинейна по `μ`, и `E[f*(μ̂)] ≠ f*(E[μ̂])`. Подстановка точечной оценки даёт смещённый вверх размер.
2. **Смещение отбора.** `μ̂` оценивается на **том же датасете, на котором эффект был найден**. Эффект прошёл фильтр «t-stat > 2» — значит выборка условна на том, что оценка оказалась большой. Это классическое смещение победителя, и оно не устраняется бутстрапом.
3. **Асимметрия последствий.** Переоценка `f` и недооценка `f` наказываются по-разному: рост `f` выше оптимума сначала не меняет темп роста, потом обрушивает его, и при `f > 2f*` темп роста становится отрицательным. Симметричный доверительный интервал по `f` вводит в заблуждение — решение принимается по **нижней** границе.

**Если модуль выдаст размер больше текущих 2% на событие — первая гипотеза должна быть «не учтено одно из трёх смещений», а не «можно ставить больше».**

**Записанное заранее ожидание.** Честный размер окажется **меньше** текущего лимита в 2%, а не больше. Записано до постройки.

## 3. Модуль 1: распределение исходов события

### 3.1 Что считается «исходом»

Для каждого события — доходность **позиции** от входа до выхода, на задействованный на неё капитал, **после всех издержек**:

```
outcome_j = (P_вход − P_выход)/P_вход        для шорта
          − комиссии (вход + выход, taker/maker по факту)
          − funding за период удержания
          − оценка проскальзывания
```

**Не аномальная доходность, а фактический P&L позиции.** Аномальная доходность (за вычетом BTC) — правильная величина для вопроса «есть ли эффект»; для вопроса «сколько ставить» нужна фактическая, потому что риск считается по ней.

Обязательные поля на событие: дата, токен, размер разлока (% supply), режим SMA200 на дату входа, факт срабатывания стопа, факт отмены по funding-фильтру, длительность удержания.

### 3.2 Обработка усечений — обязательная

Распределение исходов **усечено с двух сторон конструкцией стратегии**, и это меняет и `μ`, и `σ`:

| Механизм | Эффект на распределение |
|---|---|
| Стоп +8% | убыток усечён сверху; наблюдаемая `σ` **занижена** относительно σ без стопа |
| Фильтр funding > 1.5% | события с дорогим шортом отсутствуют в выборке. Это **не случайное** усечение |
| Ликвидный перп в фильтре события | отсутствуют неликвидные токены, где эффект может быть больше, а исполнение хуже |

Требование: считать распределение **дважды** — с усечениями как есть (это то, что торгуется) и без стопа (гипотетическое), и показать обе `σ`. Разница — цена стопа в терминах сайзинга.

**Отдельно проверить: срабатывал ли стоп, и как часто.** Если стоп не срабатывал ни разу за 40 событий, он не влияет на распределение и не защищает — это тоже результат.

### 3.3 Проверка на профиль проданного опциона

Обязательная диагностика (правило корпуса, `t07`):

- распределение `outcome_j`: среднее, медиана, квартили, асимметрия, эксцесс;
- вклад лучших 5% и худших 5% событий в суммарный P&L;
- результат после удаления лучших 5% сделок.

**Если убыток сосредоточен в редких крупных потерях, средние к решению о сайзинге не применяются**, и Kelly в стандартной форме неприменим — нужен вариант с явным учётом хвоста (§4.4).

## 4. Модуль 2: оценка размера

### 4.1 Точечный Kelly — как база для сравнения, не как ответ

```
f_point = μ̂ / σ̂²
```

для непрерывного приближения; для дискретных ставок — численная максимизация `E[ln(1 + f·outcome)]` по `f` на эмпирическом распределении. **Численная версия основная**, непрерывная формула — только для сверки порядка величины.

### 4.2 Бутстрап-распределение `f*`

Ресэмплинг событий с возвращением, `B` = 10 000 повторов из конфига. Для каждой реплики — своё `f*`. На выходе: распределение `f*`, его медиана, 5-й и 25-й процентили.

**Решение принимается по нижней границе, а не по медиане.** Обоснование в §0, п. 3.

**Обязательная проверка:** если 5-й процентиль `f*` ≤ 0, эффект при честном учёте неотличим от нуля, и вопрос о сайзинге вторичен по отношению к вопросу о существовании эффекта. Это выносится в вердикт отдельной строкой.

### 4.3 Байесовская усадка

Оценка `μ` с учётом неопределённости:

```
f_shrunk = (μ̂/σ̂²) · 1/(1 + σ²_μ/σ̂²_μ̂)
```

где `σ²_μ` — дисперсия оценки `μ̂`. Реализуется как нормально-нормальная модель с априорным средним **ноль** (консервативно: «эффекта нет, пока не доказано»).

Прогнать по сетке априорной силы: от неинформативного до сильного нулевого приора. Показать, как `f` меняется.

**Дополнительно — фракционный Kelly** как практический ориентир: `f = k · f*` для `k` ∈ {1, ½, ¼}. Это не теоретический результат, а признанная практика; в отчёте помечается как эвристика, а не вывод.

### 4.4 Учёт смещения отбора

Самое тонкое место, и его надо сделать явно.

Эффект был обнаружен при прохождении фильтра значимости. Оценка `μ̂`, условная на прохождении фильтра, смещена вверх. Требование: реализовать **хотя бы одну** поправку и явно назвать её ограничения:

- **разделение выборки по времени**: оценка на ранних событиях, применение к поздним (см. §5.1) — самый честный вариант при достаточном `N`;
- либо усадка к нулю с силой, соответствующей числу проверенных гипотез (честный `N` из журнала прогонов проекта).

**Если ни одна поправка не применима из-за малого `N`, это фиксируется в отчёте как ограничение**, а не обходится молчанием.

### 4.5 Одновременные события (H3)

Текущее правило — ≤ 3 одновременных события. Kelly для нескольких одновременных ставок:

```
максимизировать  E[ ln(1 + Σ_i f_i · outcome_i) ]
```

с эмпирической **совместной** матрицей исходов одновременных событий.

Ключевой вопрос: коррелированы ли исходы одновременных событий? Гипотеза — да, потому что все события в один режим рынка испытывают общий фактор. При положительной корреляции оптимальный **суммарный** размер меньше суммы индивидуальных.

Требование: посчитать эмпирическую корреляцию исходов событий, попавших в одно окно, и показать оптимальный суммарный размер против `3 × f_individual`.

**Если одновременных событий в датасете мало, корреляция оценивается по общему фактору** (доходность BTC в окне события) как прокси, и это помечается как приближение.

## 5. Модуль 3: симуляция траекторий

### 5.1 Разделение по времени — главный тест

Разделить события по дате пополам. Оценить `f` на первой половине всеми методами §4. Применить каждое `f` ко второй половине. Показать:

| Метрика на второй половине |
|---|
| Итоговый рост капитала |
| Максимальная просадка |
| Число событий до восстановления после худшей просадки |
| Доля траекторий с просадкой > 30%, > 50% (по бутстрапу порядка событий) |

**Это основной тест, а не дополнительный.** Он отвечает на вопрос, который нельзя решить на той же выборке: приводит ли размер, оценённый по прошлому, к катастрофе на будущем.

### 5.2 Сетка размеров

Прогон Монте-Карло по `f` ∈ {0.5%, 1%, 2%, 3%, 5%, `f_shrunk`, `f_point`, `f_5-й процентиль`} с ресэмплингом порядка событий:

- распределение конечного капитала (медиана, 5-й и 95-й процентили);
- распределение максимальной просадки;
- **вероятность просадки, несовместимой с продолжением работы** — порог из конфига, по умолчанию 50%;
- темп роста `E[ln(1+f·X)]` как функция `f` — кривая с явно отмеченным максимумом и точкой, где темп роста обращается в ноль.

**Кривая темпа роста по `f` — главная картинка отчёта** (в виде таблицы, не графика). Она показывает асимметрию: плато слева от оптимума и обрыв справа.

### 5.3 Горизонт

Все выводы привязать к реальному горизонту: сколько событий в год проходит фильтр S5. При 40 событиях за 5 лет это ≈ 8 в год — и любые утверждения про «асимптотически оптимальный рост» на таком горизонте некорректны. Это выносится в README.

## 6. Отчёт

### 6.1 Разделы

**Данные:** число событий, период, распределение по годам и по размеру разлока, доля отменённых по funding-фильтру, доля со сработавшим стопом, доля одновременных.

**Распределение исходов:** статистики, вклад хвостов, результат без лучших 5%, ответ на вопрос о профиле проданного опциона.

**Оценки размера:** таблица `f` по всем методам §4 с доверительными интервалами.

**Симуляции:** таблицы §5.

### 6.2 Вердикт

1. Какой размер даёт точечный Kelly? Какой — 5-й процентиль бутстрапа?
2. Отличается ли честный размер от текущих 2% практически значимо?
3. Отличен ли 5-й процентиль `f*` от нуля?
4. Что показывает разделение по времени: приводит ли `f`, оценённый на первой половине, к приемлемой траектории на второй?
5. Коррелированы ли исходы одновременных событий? Каков оптимальный суммарный размер против `3 × f`?
6. Имеет ли распределение профиль проданного опциона?
7. Какова вероятность просадки > 50% при рекомендуемом размере на горизонте 5 лет?

### 6.3 Kill-критерии и пороги действия

| Условие | Вывод |
|---|---|
| 5-й процентиль `f*` ≤ 0 | **эффект неотличим от нуля при честном учёте.** Вопрос переходит из «сколько ставить» в «есть ли что ставить» — и это более важный вопрос |
| `f` с первой половины даёт просадку > 50% на второй | оценка непереносима; размер брать по нижней границе и ниже |
| Убыток сосредоточен в редких крупных потерях | Kelly в стандартной форме неприменим; решение по хвостовым метрикам |
| Рекомендуемый размер выше 2% | **перепроверить три смещения §0 перед тем, как принимать.** Повышение лимита требует отдельного решения, а не следует из расчёта |
| Оптимальный суммарный размер по трём событиям меньше `3 × f` | текущее правило «≤ 3 события» завышает суммарную экспозицию |

## 7. Тесты — критерии приёмки

### 7.1 Синтетика с известным ответом

| Сценарий | Ожидаемое |
|---|---|
| Ставка с известным `μ`, `σ`, большое `N` | численный `f*` сходится к `μ/σ²` |
| То же, но `N` = 40 | бутстрап-распределение `f*` широкое; медиана выше истинного `f*` (**демонстрация смещения**) |
| Нулевой эффект, `N` = 40 | 5-й процентиль `f*` отрицателен; точечный Kelly при этом положителен в части реплик |
| Два полностью коррелированных события | оптимальный суммарный размер равен размеру одного, а не двойному |
| Два независимых события | оптимальный суммарный больше одиночного, но меньше двойного |
| Ставка с `f > 2f*` | симулированный темп роста отрицателен |

**Второй и третий сценарии — главные.** Модуль, не показывающий смещение на синтетике с заведомо нулевым эффектом, не выполняет свою задачу.

### 7.2 Корректность

- усечение стопом воспроизводится: искусственно применённый стоп к синтетическим исходам даёт ожидаемое изменение `σ`;
- издержки списываются один раз;
- бутстрап с фиксированным seed воспроизводим побитово;
- разделение по времени не подглядывает: оценка на первой половине не использует ни одного события второй (автоматический тест с подменой второй половины на пропуски).

## 10. Оговорки для README

- **8 событий в год.** Все утверждения об асимптотической оптимальности Kelly на этом горизонте некорректны и в отчёте не используются.
- **`μ` оценена на той же выборке, где эффект найден.** Даже после поправок оценка смещена вверх. Направление смещения известно, величина — нет.
- **Стоп +8% усекает распределение**, поэтому наблюдаемая `σ` занижена относительно риска без стопа. Если стоп не срабатывал ни разу, он и не защищал.
- **Результат «ставить меньше» — полноценный результат.** Он не уменьшает ценность S5, он уточняет цену её риска.
- **Модуль не проверяет, работает ли S5.** Он принимает эффект как данность и отвечает только на вопрос о размере. Если 5-й процентиль `f*` окажется ≤ 0, это сигнал вернуться к первому вопросу.
