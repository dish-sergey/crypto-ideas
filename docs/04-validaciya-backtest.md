# Валидация и бэктестинг

Цель этапа — не найти "лучшие параметры", а честно ответить: переживает ли каждая гипотеза издержки и смену периодов. Плохой бэктест опаснее отсутствия бэктеста: он даёт уверенность без основания.

## 1. Данные

| Тип | Источник | Глубина | Примечания |
|-----|----------|---------|------------|
| Свечи D1/H1, топ-100 | ccxt (Binance/Bybit/OKX) | с 2019 | учесть делистинги — см. survivorship bias |
| Funding history | API бирж напрямую | с 2020 | по каждой бирже отдельно, ставки различаются |
| Open Interest | Coinglass API / биржи | с 2021 | агрегат + по биржам |
| MVRV, supply in profit, LTH | Glassnode/CryptoQuant (платно) или Dune | с 2017 | для детектора достаточно D1 |
| Разлоки (для S5) | Tokenomist + ручная верификация | ретроспектива 2021+ | собирается вручную/парсером |
| Капитализация топ-100 исторически | CoinGecko API | с 2019 | нужна для вселенной S2 и C5 |

Хранилище: Postgres или SQLite + parquet-файлы. Обязательное правило: у каждой записи два времени — время события и время, когда данные стали бы доступны (`available_at`). Бэктест читает только по `available_at`.

## 2. Пять ошибок, которые убивают бэктест

1. **Look-ahead bias.** Использование данных до их доступности. On-chain метрики публикуются с лагом (часы/сутки) — в бэктесте лаг моделируется явно (+24ч к on-chain по умолчанию). Дневная свеча "закрывается" только на следующий день.
2. **Survivorship bias.** Вселенная "топ-50 сегодня" в 2021 году содержит только выжившие — momentum на такой вселенной завышен радикально. Вселенная строится на каждый исторический день из капитализаций того дня, включая позже умершие токены (LUNA, FTT — обязаны быть в данных).
3. **Переподгонка.** Правила: параметры назначаются до прогона из логики; на каждый параметр — sensitivity-тест (±30% значения не должны разрушать результат); количество тестируемых вариаций фиксируется в журнале (10 прогонов с выбором лучшего = подгонка, даже неосознанная).
4. **Игнорирование издержек.** Пессимистичная модель по умолчанию: taker 0.05% фьючи / 0.1% спот, slippage 0.05% для BTC/ETH и 0.15–0.5% для альтов по убыванию ликвидности, funding для шортов S5 — фактический исторический. Отдельный прогон "издержки ×1.5": стратегия, умирающая при полуторных издержках, слишком хрупкая.
5. **Смешение in-sample / out-of-sample.** См. §4, walk-forward.

## 3. Валидация детектора режима (док. 01)

Детектор проверяется первым — от него зависят все стратегии.

Методика: прогон score на всей истории BTC 2017–2025 → разметка режимов → сравнение с "идеальной" разметкой задним числом (пики/днища ±20% движения).

Критерии допуска:
- Все крупные медвежьи фазы (2018, 2022, любые падения BTC > 45%) распознаны с лагом ≤ 40 дней от вершины.
- Ложных полных циклов BULL→BEAR→BULL внутри одного фактического режима — не более 1 на 2 года истории (гистерезис работает).
- Простейшая проверка ценности: стратегия "лонг BTC в BULL, стейблы иначе" на разметке детектора должна иметь максимальную просадку минимум вдвое меньше buy&hold при сопоставимой или лучшей доходности. Если нет — детектор не добавляет информации к SMA200, и надо упрощать, а не усложнять.
- Sensitivity: сдвиг порогов ±0.05 и весов ±20% не меняет разметку катастрофически.

## 4. Walk-forward для стратегий S2, S3

```
[2019–2021 design] → [2022 test] → [2019–2022 design] → [2023 test] → ... → [2025 test]
```

Параметры фиксируются на design-окне, результат засчитывается только по test-окнам. Склейка test-окон = честная кривая эквити.

Критерии допуска стратегии в paper trading:
- Положительный результат после издержек на склейке test-окон.
- Профит не сконцентрирован: удаление лучших 5% сделок не делает стратегию убыточной.
- Работает в своём режиме в каждом цикле, где режим встречался (S2 должна зарабатывать и в 2020–21, и в 2023–24 бычьих фазах).
- Просадка на тесте × 1.5 совместима с лимитами док. 03.

## 5. Специфика по стратегиям

**S1 (funding-arb):** бэктест почти арифметика — историческая ставка минус издержки ротаций. Главное проверить: частоту ротаций при пороге 30% (слишком частая — съедает всё), долю времени с отрицательным funding по режимам, и поведение в вертикальных ралли (пиковые требования к марже — вход для настройки порогов док. 03 §3).

**S5 (unlock):** до любого кода — event study. Собрать все события ≥3% supply за 2021–2025, посчитать среднюю аномальную доходность (за вычетом движения BTC) в окне [−10, +5] дней. Критерии: эффект отрицателен в окне [−5, 0], статистически отличим от нуля (t-stat > 2 на ≥ 40 событиях), устойчив по годам и **не затухает** в 2024–2025 (если затухает — стратегия опоздала, не запускать). Затем вычесть фактический funding шортов — эффект должен выживать.

**Детектор + аллокация целиком:** финальный интеграционный прогон — вся система (матрица аллокации док. 00) на 2019–2025 с издержками. Сравнение с двумя бенчмарками: buy&hold BTC и "SMA200-стратегия". Система оправдана, если даёт сопоставимую доходность при существенно меньшей просадке, либо лучшую доходность при не большей просадке.

## 6. Paper trading и переход в live

| Фаза | Длительность | Критерий перехода |
|------|-------------|-------------------|
| Paper (симуляция на живых данных) | S1: 1 мес.; S2/S3: 3 мес.; S5: 10 событий | Расхождение с моделью бэктеста в пределах модели издержек |
| Live micro (5–10% капитала) | 3 мес. | Фактические издержки ≤ модель ×1.2; нет операционных инцидентов уровня CRITICAL |
| Live целевой | — | Поэтапное увеличение по 25% в месяц при выполнении лимитов док. 03 |

Правило одного изменения: между фазами меняется что-то одно (код ИЛИ параметры ИЛИ капитал), иначе причину расхождений не установить.

## 7. Журнал исследований

Каждая гипотеза получает запись: формулировка ДО теста, данные, число прогонов, результат, вердикт (принято / отклонено / отложено). Отклонённые гипотезы не перезапускаются с "чуть другими параметрами" без новой идеи — это защита от подгонки через настойчивость.
