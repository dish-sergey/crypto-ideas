# Детектор режима рынка — v4

**Статус:** ревизия v3. Изменение точечное: статус модификатора `stress_level` переведён из «выключен до выяснения» в «выключен постоянно» по результатам `19-razbor-voltarget-v2.md`.

**Архитектура не менялась:** две оси (`D`, `T`), пять состояний, модификаторы. Измеренная экономика та же.

---

## 0. Что изменилось относительно v3

Единственное содержательное изменение — §2.4.

В v3 `stress_level` был введён выключенным, с условием: включить, если разбор провала volatility targeting покажет, что данная форма от него свободна. Разбор выполнен, условие **не наступило и наступить не может**:

- `stress_level` ограничен множителем [0.5, 1.0], то есть минимальная экспозиция 0.5 против 0.29 у voltarget — выходить он способен ещё меньше;
- быстрое окно σ7д снимает часть проблемы запаздывания (H3), но не снимает упор в потолок (H1), отсутствие выхода (H2) и симметрию волатильности (H4), а каждой из них хватило бы по отдельности;
- дополнительно установлено (doc 19 v2 §3.3), что механизм не нейтрален, а слегка вреден: обвалы в крипте стартуют из низковолатильного состояния, поэтому в первый и самый дорогой день падения экспозиция полная, а во время волатильных ралли — урезанная.

Величина продолжает вычисляться и попадать в выходной контракт как **диагностическая**, но не влияет ни на состояние, ни на экспозицию.

## 1. Требования

| Требование | Следствие в конструкции |
|---|---|
| Ошибка «не переключился» дешевле ошибки «дёргается» | dwell-time lock |
| Выход потребляется аллокатором, а не входным сигналом | дискретное состояние + непрерывный confidence |
| Данные могут отвалиться | нейтральное значение по умолчанию у каждого компонента |
| История коротка (~3 цикла) | минимум свободных параметров, никакой оптимизации |
| Запаздывание 2–6 недель приемлемо | медленные устойчивые метрики |

Детектор оптимизируется **не на точность классификации, а на экономику**: сколько просадки снимает и сколько доходности стоит.

## 2. Архитектура: две оси и модификаторы

```
D  — Direction   ∈ [−1, +1]   направление долгосрочного тренда
T  — Trendiness  ∈ [0, 1]     насколько движение направленное, а не пилообразное
```

Модификаторы:

```
cycle_phase      ∈ {ACCUMULATION, EARLY, MID, LATE, EUPHORIA}   — из on-chain
macro_flag       ∈ {−1, 0, +1}                                  — из макро
breadth          ∈ [0, 1]                                       — ширина рынка
leverage_warning ∈ {true, false}                                — из деривативов
stress_level     ∈ [0, 1]                                       — ДИАГНОСТИЧЕСКИЙ, не влияет на решения
```

### 2.1 Ось D — направление

```
dist  = (close − SMA200) / ATR90
slope = (SMA200_t − SMA200_{t−30}) / ATR90

D = 0.7 · clip(dist / 4, −1, +1) + 0.3 · clip(slope / 1.5, −1, +1)
```

Данные: дневные свечи BTC/USDT, ccxt.

### 2.2 Ось T — трендовость

```
ER      = |P_t − P_{t−90}| / Σ|P_i − P_{i−1}|
R2      = R² линейной регрессии log(P) по времени, окно 90 дней
ADX_n   = clip((ADX(14) − 15) / 25, 0, 1)

T_raw = median(ER_norm, R2, ADX_n)
T     = процентильный ранг T_raw по скользящему окну 3 года
```

### 2.3 Ось S — удалена (с v3)

| Компонент | Судьба | Основание |
|---|---|---|
| `dd_speed` | удалён полностью | храповик по построению (doc 18, A1/A2); информация о глубине просадки уже в `D` |
| `vol_z` | перенесён в диагностический `stress_level` | описывает фон, а не событие |
| `liq_pct` | зарезервирован для внутридневного контура (§7) | на дневных данных бесполезен (doc 18, A7) |

`dd_speed` не подлежит восстановлению ни в какой форме: величина убывает только при росте цены либо при выкатывании старого пика из окна, то есть удерживает высокое значение календарное время независимо от рынка. Дефект определения, а не параметра.

### 2.4 stress_level — диагностический модификатор (изменено в v4)

```
stress_level = clip( vol_z / 3, 0, 1 )     # z-score реализованной волатильности 7д к 1 году
```

**Статус: вычисляется, логируется, на решения не влияет. Постоянно.**

Конфигурация: `stress_multiplier_enabled: false`. Флаг сохранён в коде для прозрачности (чтобы было видно, что механизм рассматривался и отвергнут), но **включение требует не изменения конфига, а нового документированного основания** — см. §6.7.

Основание для отключения — `19-razbor-voltarget-v2.md`, измерения на BTC 2020–2026:

| Что измерено | Значение | Что означает |
|---|---|---|
| Дней с экспозицией на потолке | 67% | две трети времени механизм выключен |
| Минимальная экспозиция за историю | 0.29 | ноль недостижим, полного выхода не бывает |
| Экспозиция в 20 худших дней | 0.78 | в худшие дни держится более трёх четвертей позиции |
| Экспозиция: лучшие / худшие дни | 0.73 / 0.78 | перекос **в неправильную сторону** |
| corr(экспозиция, доходность t→t+20) | −0.14 | больше позиции перед плохими периодами |
| Отношение защита / цена | 0.79 | за единицу упущенного роста отводится 0.79 падения |

Последняя строка решающая: отношение меньше единицы означает отрицательный чистый эффект даже без учёта издержек.

**Для чего величина всё же полезна.** Она остаётся корректной **оценкой** текущего риска: помогает понимать реалистичные пределы дневного движения, ожидать широких спредов, задавать размер позиции. Непригодна она именно как **триггер выхода**. Разграничение — в `t02 v2` §4 и `t05 v2` §4.

**Второй потребитель — вопрос открыт.** `16-kross-sekcionnye-strategii.md` §7.1 использует меру стресса для защиты от обвала моментума. Задача там другая: обвал моментума случается на отскоке после капитуляции, то есть когда волатильность уже высока, и запаздывающая мера может как раз подойти. Результат по BTC на эту задачу **не переносится**; проверка — в рамках doc 17.

### 2.5 Модификаторы cycle_phase, macro_flag, breadth, leverage_warning

**cycle_phase** — из on-chain, дискретная метка без арифметики:

| Условие | Метка |
|---|---|
| MVRV Z < 0 и supply_in_profit < 50% | ACCUMULATION |
| MVRV Z ∈ [0, 1) | EARLY |
| MVRV Z ∈ [1, 2.5) | MID |
| MVRV Z ∈ [2.5, 3.5) или supply_in_profit > 90% | LATE |
| MVRV Z ≥ 3.5 или supply_in_profit > 95% | EUPHORIA |

Потребитель — аллокатор: `EUPHORIA` срезает плечевой лимит и запрещает наращивание, `ACCUMULATION` разрешает лестницу S6.

**macro_flag** — грубый флаг из FRED (ставка, баланс ФРС) плюс тренд DXY, обновление раз в неделю. `−1` умножает целевую экспозицию на 0.75. Вето, не сигнал.

**breadth** — доля монет из исторического, point-in-time топ-100 выше своей SMA200. Потребитель — S2/S9: при `breadth < 0.35` альт-стратегии не запускаются даже в BULL.

**leverage_warning** — `true`, если OI/MarketCap вырос на ≥20% за 14 дней без роста цены, либо funding по BTC+ETH держится >0.05%/8ч более 7 дней. Потребитель — риск-модуль и confidence.

## 3. Классификация состояния

```
1. если дней_в_текущем_состоянии < 15     → текущее состояние (dwell-time lock)
2. если T < 0.40                          → RANGE
3. если T ≥ 0.40 и D > +0.20              → BULL
4. если T ≥ 0.40 и D < −0.20              → BEAR
5. иначе                                  → TRANSITION
```

Dwell-time lock не имеет исключений. В v2 его обходило состояние `CRASH`, и это было основным механизмом ущерба (doc 18, A5).

### 3.1 Confidence

```
agreement   = 1 − |D_price_dist − D_price_slope| / 2
clarity     = |D|
persistence = clip(дней_в_состоянии / 30, 0, 1)

confidence = 0.4·clarity + 0.3·agreement + 0.3·persistence
confidence *= 0.7  если leverage_warning
confidence *= (1 − 0.15 · число_отвалившихся_источников)
```

## 5. Измеренная экономика

Прокси-аллокация BULL 100% / TRANSITION 50% / остальное 0% (кэш 8%), реаллокация 5 дней, издержки 0.10% с оборота. Окно 2020-01-01 … 2026-07-23.

| Конфигурация | CAGR | MaxDD | Sharpe | ΔMaxDD/ΔCAGR |
|---|---|---|---|---|
| buy & hold | 39.9% | −76.6% | 0.86 | — |
| v2 (с CRASH) | 26.9% | −25.2% | 0.92 | 0.25 |
| **v3 = v4 (без CRASH)** | **32.7%** | **−25.2%** | **1.04** | **0.14** |
| voltarget (отвергнут) | 33.3% | −75.0% | 0.81 | 4.12 |

v4 не меняет цифр относительно v3: `stress_level` и там, и там на решения не влиял.

**Оси `D` и `T` снижают просадку с −76.6% до −25.2%, отдавая 7.2 п.п. CAGR.** Отношение 0.14 — главное число проекта на текущий момент.

Оговорка о точности: `SE(Sharpe) ≈ 0.48` при 6.6 годах. Вывод опирается не на Sharpe, а на пару CAGR/MaxDD, но выборка по-прежнему одна.

## 6. Правила, защищающие от самообмана

1. **Параметры фиксируются до бэктеста.** Пороги `T < 0.40`, `|D| > 0.20`, dwell 15 дней перенесены из v2 без изменений и не перекалибровывались ни при удалении `CRASH`, ни сейчас.
2. **Оптимизация порогов запрещена.**
3. **Корреляционный контроль.** Посчитать `corr(D, T)` и `corr(breadth, D)`. Ожидание: `corr(breadth, D) > 0.7`.
4. **Point-in-time данные обязательны.**
5. **Отказ данных = нейтраль**, confidence снижается.
6. **Детектор не меняется под стратегию.**
7. **Удалённое и отключённое не возвращается без нового основания.** `dd_speed`, состояние `CRASH` и множитель `stress_level` отключены на основании измерений. Возврат требует нового измерения, опровергающего это основание, а не аргумента «попробуем иначе» и не изменения конфига.

## 7. Открытые вопросы

1. **Проверить точное совпадение MaxDD** в вариантах «с CRASH» и «без CRASH» (−25.2% в обоих). Найти дату максимума просадки и убедиться, что это следствие совпадения периодов, а не артефакт расчёта. **Приоритет высокий.**
2. **Кросс-рыночная проверка** (`15` §8): ETH, SPY, золото, нефть, EUR/USD. Стоит дёшево, выборка сейчас одна.
3. **Валидация меры стресса под задачу S2/S9** (защита от обвала моментума) — отдельно, в рамках doc 17. Не унаследована из doc 19.
4. **Внутридневной контур для S7.** Doc 18 A7: среднее `passed` = 53%, отскок +5д в среднем −8.0%. Для выкупа паники нужен детектор на 15м–1ч с лентой ликвидаций; `liq_pct` зарезервирован. Потребитель — только S7, не аллокатор.
5. **BTC как единственный прокси**, **двухуровневый детектор**, **альтернативные алгоритмы классификации** — перенесены из v2 §8.
