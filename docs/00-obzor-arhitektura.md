# Торговая система: обзор и архитектура

> Статус: спецификация до имплементации. Все числовые параметры в документах — стартовые значения (defaults), подлежащие проверке на исторических данных, а не догмы.

## 1. Идея системы в одном абзаце

Система состоит из двух уровней. **Верхний уровень** — детектор режима рынка (бык / боковик / медведь), работающий на дневных данных и обновляющийся раз в сутки. **Нижний уровень** — пул стратегий, каждая из которых имеет "родной" режим. Детектор не предсказывает будущее, а распознаёт текущий режим с запозданием в дни–недели; его задача — включать/выключать стратегии и задавать веса капитала. Ядро доходности во всех режимах — рыночно-нейтральный funding-арбитраж; направленные стратегии подключаются только в подтверждённом режиме.

## 3. Пул стратегий и их режимы

| ID | Стратегия | Родной режим | Роль |
|----|-----------|--------------|------|
| S1 | Funding-арбитраж (delta-neutral) | Все (лучше всего BULL) | Ядро, база доходности |
| S2 | Momentum-ротация топ-N монет | BULL | Основной направленный доход |
| S3 | Mean reversion в диапазоне | RANGE | Сбор мелкой волатильности |
| S4 | Кэш в стейблах + доходность на стейблы | BEAR | Сохранение капитала |
| S5 | Event-шорты под токен-разлоки | BEAR / RANGE | Спутник, малый капитал |
| S6 | Лестница накопления по капитуляции | Поздний BEAR | Подготовка к следующему циклу |

## 4. Матрица аллокации (стартовая)

Доли от общего капитала. TRANSITION = детектор в зоне неопределённости или недавняя смена режима.

| Стратегия | BULL | RANGE | BEAR | TRANSITION |
|-----------|------|-------|------|------------|
| S1 funding-arb | 50% | 60% | 30%* | 50% |
| S2 momentum | 35% | 0% | 0% | 0% |
| S3 mean-rev | 0% | 25% | 0% | 0% |
| S4 стейблы+yield | 5% | 10% | 55% | 40% |
| S5 unlock-шорты | 0% | 5% | 10% | 5% |
| S6 лестница накопления | 0% | 0% | 0–15%** | 0% |
| Свободный резерв | 10% | 10% | 5% | 5% |

\* В медвежку funding часто отрицательный или нулевой — S1 работает только при положительном скользящем funding, иначе капитал уходит в S4.
\** Включается только по отдельным триггерам капитуляции (см. док. 02, S6), забирает долю из S4.

## 5. Принципы, которые не обсуждаются

1. **Детектор медленный — и это правильно.** Обновление раз в день, смена режима требует подтверждения (гистерезис). Цель — не поймать разворот первым, а не торговать против режима месяцами.
2. **Никакая направленная стратегия не работает без разрешения детектора.** Даже если сигнал стратегии идеален.
3. **Параметры не оптимизируются под историю.** Веса и пороги назначаются из логики, бэктест используется для проверки устойчивости (работает ли в каждом подпериоде), а не для подбора максимума.
4. **Комиссии и проскальзывание считаются в каждом бэктесте** по пессимистичной модели (док. 04).
5. **Плечо ≤ 3x и только в нейтральных конструкциях** (шорт-нога funding-арбитража). Направленные позиции — без плеча.
6. **Минимум 2 биржи** для распределения контрагентского риска.

## 6. Дорожная карта имплементации

| Этап | Содержание | Критерий выхода |
|------|-----------|-----------------|
| 0. Данные | Сборщики: свечи D1, funding history, OI, on-chain метрики. Хранилище (SQLite/Postgres) | 3+ года истории по BTC/ETH/топ-50, без дыр |
| 1. Детектор режима | Реализация композита по док. 01, прогон на истории | Ретроспективно корректно размечает 2020–2025 (визуальная + метрики из док. 04) |
| 2. Бэктест-движок | Общий каркас: события, комиссии, отчёты | Воспроизводимость, тест на look-ahead |
| 3. S1 funding-arb | Первая живая стратегия | Paper trading 1 мес., доходность в рамках модели |
| 4. S2 + S3 | Направленные стратегии под управлением детектора | Walk-forward тест пройден (док. 04) |
| 5. S5 unlock | Требует пайплайна расписаний разлоков | Event study подтверждает эффект на свежих данных |
| 6. Малый капитал live | 5–10% планируемого капитала | 3 мес. без расхождений paper vs live > модели проскальзывания |
