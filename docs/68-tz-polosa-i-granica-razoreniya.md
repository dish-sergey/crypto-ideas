# ТЗ для Claude Code: полоса бездействия и граница разорения

**Позиции каталога:** C4 (M-ruin) + D1 (M-band), частично D2 (M-impulse). Док. `64` §Блок C, §Блок D.

**Что строим.** Два расчётных модуля общего назначения, применяемых ко всем позициям проекта, где сейчас стоят подобранные числа: **когда ребалансировать** (полоса бездействия) и **какова вероятность дойти до барьера** (граница разорения). Плюс — численная проверка того, применима ли асимптотическая формула при фактических издержках проекта.

**Что НЕ строим.** Ни одной стратегии. Это калькуляторы, встраиваемые в существующие и будущие конструкции.

---

## 0. Главное предупреждение исполнителю

**Формула ширины полосы выведена в пределе малых издержек. У проекта издержки не малы.**

Правило кубического корня даёт ширину полосы вокруг целевой доли:

```
Δ = ( 3/(4γ) · π*² · (1−π*)² )^{1/3} · ε^{1/3}
```

с потерями в полезности порядка `ε^{2/3}`. Это **асимптотика при `ε → 0`**. Фактические параметры проекта — `ε` порядка 0.1–0.2% (спот taker 0.1% плюс проскальзывание, док. `60` §7.1) и `σ` порядка 60–80% годовых. Это не режим малых издержек, и применимость асимптотики **надо проверить численно, а не предположить**.

**Поэтому центральный результат этого ТЗ — не формула, а сравнение:** асимптотическая ширина против численно-оптимальной на сетке реальных параметров. Если расхождение велико, использовать надо численную, и это вывод задания.

Три дополнительных предупреждения:

1. **Полоса вокруг чего угодно бессмысленна.** Целевая доля `π*` требует оценённой `μ`. Если `μ` не измерена (а у проекта она измерена только для S5), полосу строить не вокруг чего. Модуль обязан требовать `π*` на вход и отказываться работать без неё.
2. **Оптимальность формы политики (зона бездействия) доказана строго; оптимальность ширины — асимптотически.** Это разные уровни уверенности, и в отчёте они не смешиваются.
3. **Граница разорения зависит от предпосылки о распределении.** Классическая формула предполагает независимые приращения. Крипта даёт кластеризацию волатильности и скачки; Монте-Карло на **эмпирическом** распределении обязателен как сверка.

**Если численная полоса совпадёт с асимптотической при `ε` = 0.2% — первая гипотеза должна быть «ошибка в численном решении», а не «асимптотика хороша».**

Требования, не зависящие от выбора библиотек:

- Конфигурация — **один файл конфигурации**. Все параметры стратегии, издержек и порогов — только оттуда, никаких констант в коде.
- Время — **UTC, миллисекунды, целые числа** (`long`). Ни одного значения времени без явной зоны.
- Логирование структурное (JSON-строки), уровень настраивается.
- Автотесты обязательны и покрывают §7 целиком.
- `README.md` с командами сборки и запуска каждого модуля.

**Воспроизводимость:** git-хэш, конфиг, seed в каждой записи. Монте-Карло — только с seed из конфига.

**Модуль поставляется как библиотека с чистым API**, а не как исполняемый скрипт: он будет вызываться из ТЗ `63` (MM-стенд), из ТЗ `66` (сайзинг S5) и из будущих. Требования: никакого чтения глобального или статического изменяемого состояния, все параметры — аргументы методов, публичный API покрыт тестами §7.

## 3. Модуль 1: целевая доля

### 3.1 Вход и выход

```
TargetWeight targetWeight(double mu, double sigma, double gamma, OptionalDouble muSe)
  -> { piStar, piStarShrunk, ciLow, ciHigh }
```

`π* = μ/(γσ²)`; при `γ = 1` это Kelly `μ/σ²`.

**Если передана `muSe` (стандартная ошибка оценки `μ`), обязательно возвращается усаженная версия** по той же схеме, что в ТЗ `66` §4.3. Если `muSe` не передана — в результат пишется флаг `shrinkageApplied = false`, и он попадает в отчёт.

### 3.2 Жёсткое требование

**Функция отказывается работать при отсутствии `μ`.** Никаких значений по умолчанию, никакого «предположим 20% годовых». Отсутствие измеренной `μ` означает, что целевой доли нет, и всё остальное задание к этому случаю неприменимо.

Это прямое следствие §0, п. 1 и правила 17 корпуса.

## 4. Модуль 2: полоса бездействия

### 4.1 Асимптотическая формула

```
Band bandAsymptotic(double piStar, double gamma, double sigma, double epsilon)
  -> { lower, upper, width, welfareLossOrder }
```

Реализуется как есть, с явной пометкой в javadoc: **асимптотика при малых `ε`**.

### 4.2 Численно-оптимальная полоса — основной результат

Прямое решение задачи: найти пару границ `(a, b)`, максимизирующую долгосрочный темп роста капитала при заданных `μ`, `σ`, `ε`, `γ` и политике «внутри `[a,b]` не торгуем, на границе торгуем до границы».

Реализация: симуляция на длинном горизонте (или численное решение уравнения на стационарное распределение доли) с перебором `(a, b)` по сетке. Метод — на усмотрение исполнителя, но требования жёсткие:

- горизонт и число траекторий из конфига, достаточные для стабилизации оценки — **доказывается** сходимостью, а не утверждается;
- целевая функция — **геометрический** темп роста по траектории, не арифметическое среднее по ансамблю. Обоснование: док. `60` §0.3 прямо показывает, что ансамблевое среднее вводит в заблуждение, потому что оператор живёт на одной траектории;
- издержки списываются с фактического оборота при каждой ребалансировке.

### 4.3 Сетка сравнения — центральная таблица задания

Прогон по декартовой сетке:

| Параметр | Значения |
|---|---|
| `ε` | 0.01%, 0.05%, 0.10%, 0.15%, 0.20%, 0.50% |
| `σ` (годовая) | 40%, 60%, 80%, 100% |
| `π*` | 0.2, 0.4, 0.6, 0.8 |
| `γ` | 1, 2, 5 |

Для каждой комбинации: асимптотическая ширина, численная ширина, их отношение, и **потеря темпа роста от применения асимптотической вместо численной**.

**Последняя величина — главный практический ответ.** Если потеря пренебрежима, пользуемся формулой; если нет — численной таблицей.

### 4.4 Positive control

При `ε` → 0 (0.001% и ниже) численная и асимптотическая ширины **обязаны сойтись**. Расхождение при малых `ε` — дефект численного решения, а не результат. Это условие приёмки.

### 4.5 Импульсный вариант (D2)

При наличии фиксированной части издержек `cFixed` (вывод 1–3 GBP, док. `61` §1.1; минимальный размер ордера) задача меняется: оптимальная политика — **зона бездействия плюс прыжок внутрь зоны**, а не к границе.

```
ImpulseBand bandImpulse(double piStar, double gamma, double sigma, double epsilon,
                        double cFixed, double wealth)
  -> { triggerLow, triggerHigh, targetLow, targetHigh }
```

Численно, тем же методом. **Требование к проверке: при `cFixed` = 0 целевые точки обязаны совпасть с границами срабатывания** — то есть импульсное решение вырождается в полосу. Расхождение — дефект.

Обязательный прогон: при каком отношении `cFixed / wealth` разница между «прыжок к границе» и «прыжок внутрь» становится практически значимой. Для малого капитала это может быть решающим: вывод 2 GBP на счёте в 1000 GBP — это 0.2%, сопоставимо со всеми остальными издержками.

## 5. Модуль 3: граница разорения

### 5.1 API

```
RuinResult ruinProbability(int steps, double[] stepSizes, double capital,
                           double barrier, Distribution distribution)
  -> { pRuin, pRuinMc, ci }
```

Две независимые реализации, обе обязательны:

- **аналитическая** — классическая задача о разорении игрока и её диффузионный предел, для случая независимых приращений;
- **Монте-Карло на эмпирическом распределении** — ресэмплинг фактических приращений с блоками (block bootstrap), чтобы сохранить кластеризацию волатильности.

**Расхождение аналитической и МК оценок — результат, а не проблема.** Оно измеряет цену предпосылки о независимости. В отчёт идут обе.

### 5.2 Обязательные применения

| Применение | Вопрос |
|---|---|
| **Лестница S6** | какова вероятность, что цена пройдёт все 5 ступеней (шаг 7–10%) от точки активации? Каково распределение числа пройденных ступеней? |
| **Потолок инвентаря MM** | при заданном потоке и потолке `Q` — какова вероятность упереться в потолок и как долго там стоять? |
| **Одновременные события S5** | при ≤ 3 одновременных и корреляции исходов из ТЗ `66` §4.5 — вероятность просадки, несовместимой с продолжением |
| **Общий счёт** | при рекомендуемом `f` из ТЗ `66` — вероятность просадки > 50% на горизонте 5 лет |

Первое применение — самое конкретное: лестница S6 сейчас имеет 5 ступеней, и число 5 ничем не обосновано. Модуль даёт распределение числа пройденных ступеней на исторической волатильности BTC/ETH и отвечает, покрывает ли бюджет в 15% реальный диапазон.

### 5.3 Блочный бутстрап — требование

Обычный ресэмплинг с возвращением разрушает кластеризацию волатильности и **занижает** вероятность разорения. Требуется block bootstrap с длиной блока из конфига; чувствительность к длине блока — обязательный прогон.

## 6. Отчёт

### 6.1 Разделы

**Контроли:** сходимость численной и асимптотической полосы при малых `ε`; вырождение импульсного решения при `cFixed` = 0; сверка МК-разорения с аналитическим на синтетике с независимыми приращениями. **Идут первыми** — от них зависит действительность остального.

**Полоса:** сетка §4.3 целиком, с отношением ширин и потерей темпа роста.

**Импульс:** пороги и целевые точки для реальных `cFixed` проекта; порог значимости отличия от простой полосы.

**Разорение:** таблицы по четырём применениям §5.2, аналитическая и МК-оценка рядом, чувствительность к длине блока.

**Применение к текущим правилам:** по каждой строке таблицы §1 — что даёт выведенное правило против текущего подобранного, и значимо ли расхождение.

### 6.2 Вердикт

2. Насколько выведенная полоса отличается от «ребалансировать раз в неделю» и от «при отклонении на 5%»?
3. Значима ли разница между импульсным решением и простой полосой при фактических фиксированных издержках проекта?
4. Какова вероятность пройти все 5 ступеней лестницы S6? Достаточно ли 5 ступеней и бюджета 15%?
5. Насколько МК-оценка разорения на эмпирических данных отличается от аналитической? В какую сторону?
6. Какие из текущих подобранных чисел §1 расходятся с выведенными настолько, что их стоит менять?

### 6.3 Kill-критерии и пороги действия

| Условие | Вывод |
|---|---|
| Численная и асимптотическая полоса не сходятся при `ε` → 0 | **дефект численного решения.** Прогон недействителен |
| Импульсное решение не вырождается в полосу при `cFixed` = 0 | дефект. Прогон недействителен |
| МК-разорение на синтетике с независимыми приращениями расходится с аналитическим | дефект. Прогон недействителен |
| Расхождение выведенных и текущих чисел меньше их же неопределённости | текущие правила оставить. **Валидный и вероятный исход** |
| `μ` для конструкции не измерена | полосу не строить. Задание к этой конструкции неприменимо |
| Вероятность пройти всю лестницу S6 выше порога из конфига | число ступеней и бюджет пересмотреть — отдельным решением, не автоматически |

## 7. Тесты — критерии приёмки

### 7.1 Аналитика

- `π*` при `γ = 1` равна `μ/σ²`; при удвоении `γ` уменьшается вдвое;
- асимптотическая ширина растёт как `ε^{1/3}`: восьмикратный рост `ε` даёт двукратный рост ширины (**проверяется численно, а не глазами**);
- ширина обращается в ноль при `π*` = 0 и `π*` = 1 (множитель `π*²(1−π*)²`);
- разорение: для симметричного случайного блуждания с барьерами `a` и `b` вероятность достижения `a` равна `b/(a+b)` — классический результат, точная сверка.

### 7.2 Численное решение

- сходимость: удвоение числа траекторий меняет оптимальную ширину меньше чем на порог из конфига;
- **positive control §4.4**: при `ε` = 0.001% численная и асимптотическая ширины совпадают в пределах допуска;
- при `ε` = 0 оптимальная ширина равна нулю (непрерывная ребалансировка);
- при очень больших `ε` полоса покрывает весь диапазон (не торговать вообще) — вырожденный случай обрабатывается, а не падает;
- **вырождение импульса §4.5**: при `cFixed` = 0 целевые точки совпадают с границами.

### 7.3 Разорение

- МК на синтетических независимых приращениях воспроизводит аналитическую формулу в пределах доверительного интервала;
- блочный бутстрап на данных с искусственно вставленной кластеризацией волатильности даёт **более высокую** вероятность разорения, чем обычный бутстрап (тест на то, что блоки вообще работают);
- при нулевой волатильности вероятность разорения равна нулю или единице в зависимости от знака дрейфа.

### 7.4 Воспроизводимость

Повторный прогон с тем же seed — побитово тот же результат.

## 8. Чего не делать

| Не делать | Причина |
|---|---|
| Использовать значение `μ` по умолчанию | отсутствие измеренной `μ` — не техническая проблема, а содержательная. См. §3.2 |
| Подбирать ширину полосы по историческому P&L | это оптимизация параметра, а не вывод. Полоса выводится из `μ`, `σ`, `ε`, `γ` |
| Считать целевую функцию как арифметическое среднее по ансамблю | док. `60` §0.3: оператор живёт на одной траектории. Только геометрический темп по траектории |
| Применять формулу при `ε` = 0.2%, не проверив численно | это и есть содержание задания |
| Обычный бутстрап для разорения | занижает вероятность, разрушая кластеризацию волатильности |
| Автоматически менять параметры действующих стратегий по результату | модуль даёт числа; изменение конфигурации — отдельное решение. **Правило одного изменения** |
| Строить графики и дашборды | нужны таблицы чисел |

## 10. Оговорки для README

- **Форма политики доказана, ширина — асимптотически.** Зона бездействия оптимальна строго; её ширина выведена в пределе малых издержек, которых у проекта нет. Отсюда обязательность численной проверки.
- **Ценность формул — в структуре и масштабировании, не в третьем знаке.** Главные выводы: ширина растёт как кубический корень из издержек, а не линейно; при фиксированной комиссии прыгать надо внутрь зоны, а не к её границе. Эти два утверждения устойчивы к нарушению предпосылок сильнее, чем конкретные числа.
- **Модуль ничего не говорит о том, стоит ли держать позицию.** Он отвечает только на вопрос «когда двигать» при уже принятом решении «сколько держать». Без измеренной `μ` он неприменим.
- **Исход «текущие числа менять не нужно» — валидный результат.** Он превращает подобранные числа в проверенные, что само по себе снимает неопределённость.
