# Стенд сравнения детекторов режима — ТЗ на реализацию, v3

**Назначение:** задание для исполнителя (Claude Code). Цель — **честно сравнить несколько алгоритмов на одной разметке и одних метриках и выбрать один**.

**Зависимости:** `01-detektor-rezhima-v4.md`, `04-validaciya-backtest.md`.
**Теория:** `t07` (метрики и погрешность), `t08` (виды самообмана), `t09` (фильтрация).

**Что изменилось в v3:** `baseline_voltarget` переведён из обязательных кандидатов в **отвергнутые** по результатам `19-razbor-voltarget-v2.md`; критерий отсечения сложности возвращён к одному baseline; добавлен §12 с реестром отвергнутых конструкций.

**Главный принцип:** стенд ценен ровно настолько, насколько способен забраковать нашу же любимую гипотезу. Если победил тривиальный SMA200 — это валидный результат, а не повод «докрутить» композит.

## 2. Данные

- `BTC/USDT`, дневные свечи, с `2017-01-01`.
- `ccxt`, Binance основной, Kraken/Coinbase резерв.
- `DataFrame[open, high, low, close, volume]`, `DatetimeIndex`, UTC, без дыр.

Обязательные проверки при загрузке:

- нет пропущенных дней (дыра → исключение, не `fillna`);
- нет дубликатов индекса;
- `high ≥ max(open, close)`, `low ≤ min(open, close)`;
- **запрещён `bfill` в любом виде.** Только `ffill`, с явным логом.

Ликвидации и on-chain не подключаем: истории мало, данные ревизуются (`t08`).

## 3. Разметка истории (эталон для оценки)

```
1. Локальные экстремумы, окно ±30 дней.
2. Чередование пик → впадина → пик; два подряд одного типа — оставить экстремальный.
3. Подъём ≥ +50%  → BULL. Падение ≥ −30% → BEAR. Остальное → RANGE.
4. Отрезки короче 30 дней поглощаются предыдущим.
```

**Разметка смотрит в будущее по построению.** Допустима только в `eval/`. Импорт `labeling` в `detectors/` — ошибка сборки (§10.2).

Проверить глазами: топ декабря 2017, дно декабря 2018, дно марта 2020, топ ноября 2021, дно ноября 2022.

## 4. Единый интерфейс детектора

```python
class Detector(Protocol):
    name: str
    def fit(self, df: pd.DataFrame) -> None: ...
    def predict(self, df: pd.DataFrame) -> pd.Series: ...
```

- `predict(df)[t]` зависит **только** от `df[:t]`. Тестируется автоматически.
- Для правиловых детекторов `fit` — no-op, но метод обязателен: WFO применяется ко всем одинаково.
- Допустимые состояния: `{BULL, BEAR, RANGE, TRANSITION}`.

**Изменение в v3:** метод `predict_exposure` из v2 удалён. Он вводился ради `baseline_voltarget` — единственного кандидата с непрерывной экспозицией. Кандидат отвергнут (§5.1), метод не нужен. Экспозиция определяется отображением состояния через `ALLOCATION_MATRIX` (§6.2).

## 5. Алгоритмы-кандидаты

| Ключ | Описание | Параметров |
|---|---|---|
| `baseline_always_range` | всегда RANGE, детектора нет | 0 |
| `baseline_sma200` | `close > SMA200 → BULL`, иначе `BEAR` | 0 |
| `rules2d` | doc 01 v4, §2–3 | 4 |
| `cusum` | CUSUM по накопленному отклонению лог-доходности, два симметричных порога | 2 |
| `hmm` | `hmmlearn`, Gaussian, 3 состояния; фичи: лог-доходность 1д, реализованная вол. 14д | ~2 |
| `gmm` | `GaussianMixture`, 4 кластера по [лог-доходность 20д, реал. вол. 14д, ER 90д, dist до SMA200] | ~1 |
| `ensemble` | голосование `rules2d` + `cusum` + `hmm`; разногласие → `TRANSITION` | 0 |

`buy_and_hold` — бенчмарк доходности, живёт в `eval/`.

### 5.1 baseline_voltarget — отвергнут (изменено в v3)

В версии 2.0 этот кандидат был **обязательным**, с ожиданием, что он может побить композит. Ожидание не подтвердилось.

Измерено на BTC 2020–2026 (`19-razbor-voltarget-v2.md`):

| Показатель | Значение |
|---|---|
| CAGR / MaxDD / Sharpe | 33.3% / −75.0% / 0.81 |
| Для сравнения, buy & hold | 39.9% / −76.6% / 0.86 |
| Дней с экспозицией на потолке 1.0 | 67% |
| Минимальная экспозиция за историю | 0.29 |
| Экспозиция: лучшие / худшие дни | 0.73 / 0.78 |
| Отношение защита / цена | 0.79 |

Причина не в реализации — все пять технических проверок чистые. Инструмент решает задачу «стабилизировать риск», а наша метрика измеряет способность **избегать просадок**; для второго нужен механизм выхода, а vol targeting никогда не выходит.

**Кандидат не прогоняется в основном сравнении.** Условия возможного возврата — §12.

### 5.2 Ловушки HMM и GMM

1. **Перестановка состояний.** Номер скрытого состояния произволен и меняется от прогона к прогону. Метки назначать по средней доходности внутри состояния **на обучающем окне**: наибольшая → BULL, наименьшая → BEAR, средняя → RANGE. Никогда по индексу.
2. **Переобучение на 3 циклах.** Ожидание, зафиксированное **до** эксперимента: хорошая картинка in-sample, посредственный out-of-sample. Записать, а не «чинить» подбором числа состояний.

## 6. Протокол оценки

### 6.1 Walk-forward

- Прогрев: первые 2 года. Прогретые дни в оценку не входят и **не заполняются**.
- Расширяющееся окно: обучение `[start, T]`, предсказание `(T, T+90]`, шаг 90 дней.
- Параметры из `params.yaml` в цикле WFO не меняются.

**Важно (`t08`):** walk-forward не делает честными параметры, выбранные по всей истории. Протокол проверяет процедуру, а не число.

### 6.2 Экономический прокси

| Состояние | Экспозиция |
|---|---|
| BULL | 100% |
| TRANSITION | 50% |
| RANGE | 0% (кэш 8%/год — прокси ядра S1) |
| BEAR | 0% |

- Реаллокация равными шагами за 5 торговых дней.
- Комиссия 0.05% от оборота, проскальзывание 0.05%.

В отчёте пометить: **это прокси, а не P&L бота.** Сравнимы только относительные числа.

### 6.3 Метрики

Технические: `lag_days` (медиана), `flips_per_year`, `state_accuracy`, `false_bear_rate`, `turnover`.

Экономические: `MaxDD`, `CAGR`, `Sharpe`, главное — **Δ MaxDD / Δ CAGR относительно buy & hold**.

Обязательно к каждому Sharpe:

- доверительный интервал `SE(S) ≈ √((1 + S²/2)/T)`, `T` в годах;
- **дефлированный Sharpe** `S_defl ≈ S − SE(S)·√(2 ln N)`, где `N` — число гипотез из журнала (§7).

Голый Sharpe без интервала в отчёт не попадает: при 3 годах данных интервал вокруг `S = 1.0` шире, чем расстояние от нуля до двойки (`t07`).

### 6.4 Критерий выбора (изменено в v3)

Победитель — по `Δ MaxDD / Δ CAGR` на out-of-sample.

**Правило отсечения сложности:** кандидат, не превзошедший `baseline_sma200`, отвергается независимо от вложенных сил. Если побеждает baseline — детектор в проде становится однострочником.

В v2 требовалось превзойти также `baseline_voltarget`. Требование снято вместе с кандидатом: сравниваться с отвергнутой конструкцией бессмысленно.

Справочно, текущий результат `rules2d` (doc 01 v4 §5): CAGR 32.7%, MaxDD −25.2%, отношение 0.14 против 4.12 у voltarget.

## 7. Журнал гипотез

Файл `reports/hypotheses.md`, **append-only**: строки не редактируются и не удаляются.

```
| дата | гипотеза | мотивация | результат | решение |
```

Записывается **всё**: идеи, отброшенные после первого взгляда; варианты параметров «просто посмотреть»; отладочные прогоны, случайно показавшие интересный результат.

**Зачем.** Из `t08`: ожидаемый Sharpe лучшей из `N` бесполезных стратегий равен `σ_S·√(2 ln N)`. При 3 годах данных и 50 гипотезах это ≈ 1.96 — то есть результат, выглядящий как открытие, соответствует чистому перебору. Без журнала `N` неизвестно.

Минимум три записи уже обязательны:

```
| — | S как max(vol_z, dd_speed, liq_pct), выход S<0.5 три дня | doc 01 v2 | 515 дней в CRASH (21.5%), медиана 20д | отвергнуто: храповик в dd_speed |
| — | дневной таймфрейм для распознавания каскада | doc 18 A7 | passed = 53%, отскок +5д = −8.0% | не годится для S7, нужен внутридневной контур |
| — | volatility targeting, clip(σ_target/σ30д, 0, 1) | t02/t05 v1 | 67% на потолке, min 0.29, защита/цена 0.79 | отвергнуто: несоответствие инструмента задаче |
```

## 8. Кросс-рыночная проверка

Выполняется **после** выбора победителя, до выводов о пригодности. Победивший детектор без изменения параметров прогоняется на:

| Рынок | Инструмент | Период |
|---|---|---|
| Крипто | ETH | 2017– |
| Акции | SPY | 1993– |
| Золото | XAU/USD | 1990– |
| Нефть | WTI | 1990– |
| Валюта | EUR/USD | 1999– |

**Критерий:** эффект сохраняется по знаку и порядку величины — просадка снижается, доходность частично теряется, отношение в разумных пределах.

- Работает везде → сильное свидетельство робастности, ценнее любого улучшения метрик на BTC.
- Только на BTC и только на нашем окне → почти наверняка подгонка.
- Ломается на одном рынке → разобраться, чем он отличается; часто это содержательное открытие.

**Почему это самая ценная проверка.** История коротка (`t05`: точность оценки средней доходности BTC ±25 п.п.). Другие рынки дают десятилетия данных бесплатно, тем же кодом.

## 9. Режим доступа к отложенной выборке

**Отложенная выборка:** последние 18 месяцев, резервируются до начала работы.

1. В разработке, отладке и анализе устойчивости не используются вообще.
2. Обращение допускается **не более двух раз** за весь проект.
3. Каждое обращение фиксируется в журнале с датой и причиной.
4. После обращения изменение модели требует новой отложенной выборки, которой нет.

Из `t08`: при итеративной доработке «по результату на тесте» тестовая выборка перестаёт быть тестовой к десятой итерации.

## 10. Антибаг-чеклист

1. **Causality test (критично).** Для 20 случайных дат: `predict(df[:t]).iloc[-1]` совпадает с `predict(df).loc[t]`. Для **каждого** детектора, включая baseline.
2. **Изоляция разметки.** Ни один модуль в `detectors/` не импортирует `labeling`. Проверять AST-обходом, не grep'ом.
3. **Тест на перемешанных данных.** Преимущество над buy & hold должно исчезнуть. 20 перемешиваний, в отчёт — распределение.
4. **Warm-up не заполняется.** Первые `max(200, 90) + запас` дней отбрасываются, без `ffill`-хвостов.
5. **Корреляции.** `corr(D, T)` на всей истории. При `|corr| > 0.8` оси не ортогональны — написать прямо.
6. **Sanity-check baseline.** `baseline_sma200` снижает MaxDD примерно с −80% до −50…−65% и проигрывает buy & hold по CAGR. Если лучше по обоим — утечка или забытые комиссии.
7. **Стабильность HMM.** 5 разных `random_state`; границы гуляют более чем на 2 недели → модель нестабильна, отметить.
8. **Комиссии применяются.** Прогон с 0% и 1% даёт разный результат.
9. **Детерминированность.** Два прогона с одним конфигом — идентичный отчёт.
10. **Журнал гипотез непуст** и согласован с числом прогонов.
11. **Кросс-рыночный прогон выполнен** для победителя.
12. **Реестр отвергнутого заполнен** (§12, новое в v3).

Пункт про частоту CRASH удалён вместе с состоянием (doc 01 v3).

## 11. Чего делать не надо

- **Не подбирать пороги.** Коммит с `params.yaml` — до коммита с результатами.
- **Не добавлять фичи после первого прогона.**
- **Не исключать «аномальные» периоды.** Март 2020 и май 2021 — не выбросы, это те дни, ради которых детектор существует.
- **Не улучшать разметку под результат.**
- **Не редактировать журнал гипотез задним числом.**
- **Не возвращать отвергнутые конструкции** без нового основания (§12).

## 12. Реестр отвергнутого (новое в v3)

Файл `reports/rejected.md`. Назначение — чтобы через полгода не начать заново то, что уже проверено и закрыто.

| Конструкция | Основание отказа | Что могло бы вернуть |
|---|---|---|
| Ось `S` с `dd_speed` | doc 18 A1/A2: храповик по построению, серии до 41 дня | ничего: дефект следует из определения формулы |
| Состояние `CRASH` | doc 18 A4: CAGR 26.9% против 32.7% при идентичном MaxDD | измерение, показывающее выигрыш на другом рынке или таймфрейме |
| `baseline_voltarget` | doc 19 v2: 67% на потолке, min 0.29, защита/цена 0.79 | версия с плечом (отдельное решение о риске) либо мультиактивный портфель |
| Множитель `stress_level` | doc 01 v4 §2.4: диапазон [0.5, 1.0] выходит ещё меньше | новое измерение под **другую** задачу — например, защита моментума (doc 17) |

**Правило:** возврат требует нового измерения, опровергающего основание, а не аргумента «попробуем иначе» и не изменения конфига.
