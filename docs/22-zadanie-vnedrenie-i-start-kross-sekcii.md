## Блок C. Проверка жизнеспособности S3

Из `21-granicy-detektora-i-naklon-sma-v2.md` §5.1.

### C1. Что прогнать

Тот же прокси, что в `slope_gate_b.md`:

```
z = (close − SMA20) / std20
LONG при z < −1, выход при z ≥ 0
SHORT при z > +1, выход при z ≤ 0
±1 позиция
```

Три прогона на BTC и ETH, полные окна:

| Прогон | Издержки |
|---|---|
| 1 | 0.10% с оборота (эталон, уже есть) |
| 2 | **0%** |
| 3 | 0.02% (мейкерское исполнение) |

### C2. Дополнительно

Распределение P&L по сделкам: гистограмма, медиана, доля прибыльных, размер худших 5%. Если убыток сосредоточен в редких крупных потерях — это профиль проданного опциона, и средние вводят в заблуждение.

### C3. Решение

| Результат прогона 2 (0% издержек) | Вывод |
|---|---|
| минус | идея мертва по существу → S3 **удаляется** из пула, не приостанавливается |
| плюс, но прогон 3 в минусе | мертва по исполнению → переписывать под лимитные ордера либо закрывать |
| плюс, и прогон 3 в плюсе | стратегия жива, нужен гейт — вопрос возвращается открытым |

Отчёт: `reports/s3_viability.md`. Запись в журнал гипотез.

## Блок D. Кросс-секция, фаза 1

Основная работа. Спецификация — `17-tz-kross-sekcionnyj-stend-v3.md`.

### D1. Порядок неизменен

```
вселенная point-in-time
  → движок с издержками
  → равновзвешенная корзина + BTC B&H
  → только потом S2 с измерением IC
```

**Правило «тривиальный бенчмарк первым»** (`15-…-v5.md` §4.1). Равновзвешенная корзина считается **до** реализации S2. Это ровно тот урок, который стоил детекторного направления: SMA200 надо было прогнать первым, а прогнали последним после четырёх версий композита.

### D2. Вселенная point-in-time — блокирующая задача

`universe(date) -> list[symbol]`, состав **на ту дату**, без знания будущего.

Фильтры (`17` §3.4): исключить стейблкоины, обёрнутые токены (WBTC, stETH и аналоги), токены младше 60 дней с первой свечи; порог ликвидности по медианному обороту за 30 дней.

**Делистинг обрабатывается явно:** позиция закрывается по последней доступной цене. Молчаливое исчезновение из данных — скрытая утечка, при которой убыток не попадает в результат.

### D3. Измерить смещение выживаемости

Отдельная задача, число в отчёт (`17` §3.3):

```
1. Вселенная наивно: сегодняшний топ-100, прогнать назад
2. Вселенная корректно: point-in-time
3. Прогнать одну и ту же стратегию на обеих
4. Разница в CAGR — цена ошибки
```

Отчёт: `reports/universe_bias.md`.

### D4. Чего не делать

**Не запускать на сегодняшнем топ-100 «пока, для предварительной оценки».** Такой прогон не даёт предварительного результата — он даёт дезинформацию, потому что мёртвые монеты в выборку не попадают, и результат получается великолепным и полностью фальшивым.

## Общие правила

- **Параметры фиксируются в конфиге до прогона.** Захардкоженное число в коде — дефект.
- **Журнал гипотез append-only.** Каждый прогон — запись, включая отброшенные и отладочные. Без честного `N` дефлированный Sharpe считать нельзя.
- **Отвергнутое не возвращается** без нового измерения, опровергающего основание. Реестр — `rejected.md`, сводка — `00-index-i-status-v2.md` §3.
- **Не перекалибровывать ничего** «раз уж всё равно переделываем».
