# Детектор режима рынка — v2

**Статус:** ревизия v1 (`01-detektor-rezhima.md`).
**Причина ревизии:** v1 работает, но склеивает в один скаляр три разные по смыслу вещи — направление тренда, фазу цикла и уровень риска. Из-за этого возникают состояния, где сильный сигнал одного компонента гасится противоположным сигналом другого, и на выходе получается `RANGE` там, где рынок очевидно направленный. Ниже — разбор конкретных дефектов и новая архитектура.

---

## 0. Зачем детектор вообще нужен и что он обязан уметь

Детектор — это **медленный гейт**, который решает, каким стратегиям из пула разрешено работать. Он не торгует, не предсказывает и не обязан ловить развороты рано.

Требования, из которых выведена вся логика:

| Требование | Следствие в конструкции |
|---|---|
| Ошибка «не переключился» дешевле ошибки «дёргается» | Гистерезис + минимальное время в состоянии |
| Выход потребляется аллокатором капитала, а не входным сигналом | Дискретное состояние + непрерывный confidence |
| Данные могут отвалиться | Каждый компонент имеет нейтральное значение по умолчанию |
| История коротка (~3 цикла) | Минимум свободных параметров, никакой оптимизации весов |
| Запаздывание 2–6 недель приемлемо | Можно использовать медленные, устойчивые метрики |

Ключевой вывод: детектор оптимизируется **не на точность классификации**, а на экономику — сколько просадки он снимает и сколько доходности при этом стоит. Это разные целевые функции, и v1 нигде явно этого не фиксировал.

## 1. Что конкретно сломано в v1

### 1.1 Главный дефект: одномерный score

`RANGE` в v1 определён как `|score| < 0.30`. Но это два разных состояния мира, слитых в одно:

- **настоящий флэт** — рынок болтается, тренда нет;
- **разногласие компонентов** — например, цена ниже SMA200 (`C1 = −0.7`), но funding положительный и MVRV в зоне «здорового роста» (`C2, C3 > 0`). Сумма ≈ 0 → `RANGE`.

Второй случай опасен: `RANGE` включает S3 (mean reversion), а разногласие компонентов при падающей цене — это ровно тот сценарий, где mean reversion ловит падающий нож. Симптом «работает, но не идеально» с высокой вероятностью растёт отсюда.

**Направление и «трендовость» — ортогональные оси, их нельзя складывать в один скаляр.**

### 1.2 C2 (on-chain) внутренне противоречив

В тексте v1 даны два несовместимых определения:

- список: `z > 3 → −1`, `z ∈ [0..2] → +0.5..+1`, `z < 0 → +0.5`;
- формула: `C2a = 1 − clip(|z − 1| / 2.5, 0, 2)`.

При `z = −1` список даёт `+0.5`, формула — `+0.2`. Хуже того, формула симметрична относительно `z = 1`, то есть капитуляция (`z ≈ −1`) и перегрев (`z ≈ 3`) получают близкие оценки. Экономически это противоположные ситуации.

Плюс концептуальная нестыковка, которую v1 сам же и признаёт: **MVRV кодирует фазу цикла, а не направление** — и после этого получает второй по величине вес (0.25) в направленном скоре.

### 1.3 Конфликт правил гистерезиса

- «Вход в BULL: score > +0.30 и держится ≥ 10 дней»
- «TRANSITION: первые 15 дней после любой смены режима»

Итого: `BULL` фактически недоступен аллокатору первые ~25 дней после разворота. При медленной реаллокации (5–10 дней равными шагами) полная бычья экспозиция достигается на ~35-й день. Для цикла длиной 12–18 месяцев это терпимо, но нигде не посчитано и не заявлено.

Кроме того, FSM не определён для быстрого перехода. Что происходит, если score за 3 дня уходит с +0.35 на −0.45 (обвал)? Правила выхода из BULL, входа в BEAR и определения TRANSITION противоречат друг другу. Такая неоднозначность в спеке = баг в коде.

### 1.4 C5 почти наверняка дублирует C1

Доля монет топ-100 выше своей SMA200 и позиция BTC относительно своей SMA200 — это одна и та же величина, измеренная по-разному. Правило v1 №2 («если |corr| > 0.8 — вес урезается») скорее всего сработает именно на этой паре. То есть заявленные веса ≠ эффективные веса.

Отдельно: **топ-100 «сегодняшний» ≠ топ-100 исторический**. Считать breadth по текущему списку — прямая survivorship bias, мёртвые монеты исключены, ширина систематически завышена.

### 1.5 Ревизия on-chain данных = скрытый look-ahead

Glassnode/CryptoQuant пересчитывают realized cap при смене методологии кластеризации сущностей. Ряд MVRV, скачанный сегодня, не равен ряду, который был бы виден в реальном времени в 2021 году. Бэктест на текущем срезе завышает качество. Doc 04 этот случай не покрывает.

### 1.6 Confidence малоинформативен

`confidence = clip(|score|, 0, 1)` — при усреднении пяти клипованных компонентов `|score|` редко выходит за 0.6, то есть confidence почти никогда не приближается к 1. И главное: он измеряет **силу**, а не **согласие**. Ситуация «все пять компонентов сходятся на +0.3» и «два по +0.9, три по −0.1» дают похожий score, но кардинально разную надёжность.

### 1.7 Нет определения «правильного ответа»

Сказать «работает, но не идеально» нельзя, пока нет разметки истории и метрик. v1 предлагает критерий «не пропустил ли катастрофу» — это направление мысли верное, но неоперациональное.

## 2. Новая архитектура: три оси вместо одного скаляра

Детектор выдаёт **не одно число, а вектор**, и состояние собирается из него по явным правилам.

```
D  — Direction   ∈ [−1, +1]   направление долгосрочного тренда
T  — Trendiness  ∈ [0, 1]     насколько движение направленное, а не пилообразное
S  — Stress      ∈ [0, 1]     острота рыночного стресса (обвал / каскад)
```

Плюс три **модификатора**, которые не участвуют в определении состояния, но передаются аллокатору отдельно:

```
cycle_phase  ∈ {ACCUMULATION, EARLY, MID, LATE, EUPHORIA}   — из on-chain
macro_flag   ∈ {−1, 0, +1}                                  — из макро
breadth      ∈ [0, 1]                                       — ширина рынка
leverage_warning ∈ {true, false}                            — из деривативов
```

Это и есть главное изменение: **то, что раньше складывалось в score, теперь имеет отдельного потребителя и отдельную семантику.** Фаза цикла не двигает состояние — она ограничивает размер позиции. Макро не двигает состояние — оно даёт вето. Ширина не двигает состояние BTC — она гейтит альт-стратегии (S2).

### 2.1 Ось D — направление (только цена)

Цена — единственный компонент, который доступен всегда, не ревизуется задним числом и не зависит от платного вендора. Поэтому направление определяется **исключительно** ей.

```
dist  = (close − SMA200) / ATR90
slope = (SMA200_t − SMA200_{t−30}) / ATR90

D = 0.7 · clip(dist / 4, −1, +1) + 0.3 · clip(slope / 1.5, −1, +1)
```

Веса 0.7/0.3 — единственная пара «магических» чисел на этой оси, унаследована из v1 и оставлена намеренно (см. §6, правило о фиксации).

Данные: дневные свечи BTC/USDT, ccxt, любая крупная биржа.

### 2.2 Ось T — трендовость

Медиана трёх независимых измерителей (медиана, а не среднее — устойчивость к выбросу одного из них):

```
ER      = |P_t − P_{t−90}| / Σ|P_i − P_{i−1}|        # Kaufman Efficiency Ratio
R2      = R² линейной регрессии log(P) по времени, окно 90 дней
ADX_n   = ADX(14), нормированный: clip((ADX − 15) / 25, 0, 1)

T_raw = median(ER_norm, R2, ADX_n)
T     = процентильный ранг T_raw по скользящему окну 3 года
```

Использование **процентильного ранга, а не абсолютного порога** — сознательное решение: абсолютные уровни ER для BTC дрейфуют со временем по мере снижения волатильности актива, а ранг устойчив. Цена — лёгкая адаптивность, но она не подгоняется под доходность, только под распределение самой метрики.

### 2.3 Ось S — стресс

Нужна отдельным состоянием, потому что обвал ≠ медленный медвежий боковик, и стратегии там разные (в обвале работает S7 panic-fade, не работает S3).

```
vol_z    = z-score реализованной волатильности 7д относительно 1 года
dd_speed = просадка от максимума за 30 дней, делённая на ATR90
liq_pct  = процентиль суммарного объёма ликвидаций за 24ч (окно 1 год)

S = max( clip(vol_z / 3, 0, 1), clip(dd_speed / 6, 0, 1), liq_pct )
```

Данные: свечи (первые две метрики), Coinglass/биржевые ленты ликвидаций (третья). При отсутствии ленты ликвидаций `liq_pct` выпадает — S считается по двум первым.

### 2.4 Модификаторы

**cycle_phase** — из on-chain, только дискретная метка, без арифметики:

| Условие | Метка |
|---|---|
| MVRV Z < 0 и supply_in_profit < 50% | ACCUMULATION |
| MVRV Z ∈ [0, 1) | EARLY |
| MVRV Z ∈ [1, 2.5) | MID |
| MVRV Z ∈ [2.5, 3.5) или supply_in_profit > 90% | LATE |
| MVRV Z ≥ 3.5 или supply_in_profit > 95% | EUPHORIA |

Потребитель — аллокатор: `EUPHORIA` срезает максимальный плечевой лимит и запрещает наращивание, `ACCUMULATION` разрешает лестницу S6. Направление состояния метка не меняет — этим устраняется противоречие §1.2.

**macro_flag** — грубый флаг из FRED (ставка, баланс ФРС) + тренд DXY, обновление раз в неделю, ручная установка допустима. Потребитель — аллокатор: `−1` умножает целевую экспозицию на 0.75. Вето, не сигнал.

**breadth** — доля монет из **исторического, point-in-time** топ-100 выше своей SMA200. Потребитель — S2 (моментум-ротация по альтам): при `breadth < 0.35` альт-стратегии не запускаются даже в BULL.

**leverage_warning** — `true`, если отношение OI / MarketCap выросло на ≥ 20% за 14 дней без роста цены, или если funding по BTC+ETH держится > 0.05%/8ч более 7 дней подряд. Потребитель — риск-модуль и confidence.

## 3. Классификация состояния

Порядок проверки важен — правила применяются сверху вниз, первое сработавшее выигрывает.

```
1. если S ≥ 0.80                          → CRASH
2. если дней_в_текущем_состоянии < 15     → текущее состояние (dwell-time lock)
3. если T < 0.40                          → RANGE
4. если T ≥ 0.40 и D > +0.20              → BULL
5. если T ≥ 0.40 и D < −0.20              → BEAR
6. иначе                                  → TRANSITION
```

Ключевые отличия от v1:

- **CRASH — отдельное состояние с приоритетом.** Он обходит dwell-time lock: обвал должен распознаваться за часы, а не за 15 дней. Выход из CRASH: `S < 0.5` в течение 3 дней подряд, после чего состояние пересчитывается с нуля с обнулением dwell-таймера.
- **Dwell-time lock заменяет двойной гистерезис v1.** Одно правило вместо трёх взаимно противоречащих. Минимум 15 дней в состоянии, кроме входа в CRASH.
- **TRANSITION — это «направленность есть, направление неясно»**, а не «прошло меньше 15 дней». Честная семантика: состояние неопределённости, в котором аллокатор держит нейтральную позицию.
- **RANGE — это низкая трендовость**, независимо от знака D. Устраняется дефект §1.1.

### 3.1 Confidence

Считается из согласия, а не из силы:

```
agreement = 1 − |D_price_dist − D_price_slope| / 2      # согласие внутри оси D
clarity   = |D|                                          # удалённость от нуля
persistence = clip(дней_в_состоянии / 30, 0, 1)

confidence = 0.4·clarity + 0.3·agreement + 0.3·persistence
confidence *= 0.7  если leverage_warning
confidence *= (1 − 0.15 · число_отвалившихся_источников)
```

Диапазон честно достигает 1.0 при устойчивом согласованном тренде — в отличие от v1, где это было практически невозможно.

## 5. Как измерять качество (этого не было в v1)

### 5.1 Разметка истории

Объективные метки строятся алгоритмом датировки пиков и впадин (подход Lunde–Timmermann), а не вручную:

```
- Идём по ряду цены, отмечаем локальные экстремумы.
- Подъём от впадины к пику ≥ +50%  → отрезок помечается BULL.
- Падение от пика к впадине ≥ −30% → отрезок помечается BEAR.
- Остальное → RANGE.
- Отрезки короче 30 дней поглощаются соседними.
```

Важно: эта разметка **смотрит в будущее по построению** и используется только для оценки, никогда — как признак.

### 5.2 Метрики

**Технические:**

- `lag_days` — медианное число дней от истинного разворота до смены состояния. Целевое: ≤ 30, приемлемое: ≤ 45.
- `flips_per_year` — число смен состояния. Целевое: ≤ 4.
- `state_accuracy` — доля дней с совпадением метки. Ориентир, не цель.
- `false_bear_rate` — доля BEAR-дней внутри истинных BULL-отрезков. Это самая дорогая ошибка (пропущенный рост).

**Экономические — приоритетные:**

- Δ MaxDD относительно buy & hold.
- Δ CAGR относительно buy & hold.
- Отношение первого ко второму: **сколько процентов доходности стоит один процент снятой просадки**. Это главное число всего документа.

### 5.3 Обязательные бенчмарки

Любой кандидат сравнивается с тремя тривиальными моделями:

1. `always RANGE` (детектора нет, работает только нейтральное ядро S1);
2. `buy & hold`;
3. **`price > SMA200 → BULL, иначе BEAR`** — одно правило, ноль параметров.

**Правило отсечения сложности:** если композит из трёх осей и четырёх модификаторов не превосходит правило №3 по экономической метрике §5.2 на out-of-sample, композит не оправдывает свою сложность и должен быть заменён на SMA200. Это правило не подлежит смягчению «потому что мы много работали».

## 6. Правила, защищающие от самообмана (обновлено)

1. **Параметры фиксируются до бэктеста.** Порог `T < 0.40`, порог `|D| > 0.20`, dwell 15 дней, `S ≥ 0.80` — заданы до первого прогона. Изменение допустимо один раз, с записью в changelog и повторной проверкой на отложенном периоде.
2. **Оптимизация порогов запрещена.** Grid search по 4 порогам на 3 циклах истории гарантированно даёт переобучение (doc 04, §5).
3. **Корреляционный контроль.** После имплементации посчитать corr(D, T, S) и corr(breadth, D) на истории. Ожидание: `corr(breadth, D) > 0.7` — именно поэтому breadth вынесен в модификаторы, а не в оси.
4. **Point-in-time данные обязательны.** Для breadth — исторический состав топ-100. Для on-chain — снимок ряда на дату, а если снимков нет, применять к результатам с MVRV дисконт и явно помечать бэктест как оптимистичный.
5. **Отказ данных = нейтраль.** Компонент недоступен → нейтральное значение, событие в лог, confidence снижается (§3.1).
6. **Детектор не меняется под стратегию.** Если стратегия плохо работает в RANGE, чинится стратегия, а не определение RANGE.

## 7. Псевдокод суточного цикла

```python
def daily_update():
    px      = fetch_price_series()             # обязательный источник
    D       = direction_axis(px)
    T       = trendiness_axis(px)
    S       = stress_axis(px, liquidations())  # деградирует при отказе ленты
    mods    = fetch_modifiers()                # on-chain, макро, breadth, деривативы

    state   = classify(D, T, S, prev_state, days_in_state)   # правила §3
    conf    = compute_confidence(D, state, days_in_state, mods)

    persist(date, D, T, S, mods, state, conf)

    if state != prev_state:
        alert(f"REGIME CHANGE: {prev_state} → {state} (conf={conf:.2f})")

    allocator.set_targets(ALLOCATION_MATRIX[state], conf, mods)
```

Реаллокация капитала при смене режима — не мгновенная: целевые веса достигаются за 5–10 торговых дней равными шагами. Исключение — вход в `CRASH`: снижение экспозиции исполняется немедленно (защита важнее цены исполнения).

## 8. Открытые вопросы для следующей итерации

1. **BTC как единственный прокси.** В 2023–2025 наблюдались периоды роста BTC при медвежьем рынке альтов. `breadth` частично это ловит, но, возможно, нужен отдельный режим для альт-сегмента.
2. **Двухуровневый детектор.** Текущий работает на дневных данных и бесполезен для внутридневных стратегий. Кандидат: макро-режим (дневной) + микро-состояние (4ч) для S7.
3. **Порог CRASH `S ≥ 0.80`** задан умозрительно. Требует калибровки по числу срабатываний на истории — целевое 2–5 событий в год.
4. **Альтернативные алгоритмы классификации** (HMM, changepoint detection, кластеризация) — предмет отдельного документа и сравнительного теста на общей разметке §5.1.
