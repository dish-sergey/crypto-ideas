# Детектор режима рынка

Цель: раз в сутки выдавать состояние `{BULL, RANGE, BEAR, TRANSITION}` и confidence ∈ [0..1]. Детектор **распознаёт**, а не предсказывает: допустимое запаздывание — 2–6 недель от фактической смены режима. Расчёт ведётся по BTC как прокси всего рынка (альты следуют за режимом BTC с большей амплитудой).

## 1. Компоненты композита

Каждый компонент нормализуется в диапазон [−1, +1], где +1 — максимально бычье значение. Итоговый score — взвешенная сумма.

### C1. Трендовый фильтр по цене (вес 0.30)

Основной и самый надёжный компонент.

```
dist = (close − SMA200) / (ATR90)        # расстояние до 200-дневной в единицах волатильности
C1 = clip(dist / 4, −1, +1)              # ±4 ATR = насыщение
```

Дополнительно (подтверждающий фактор, входит в C1 c долей 30%):
наклон SMA200 за последние 30 дней, нормированный так же через ATR.

Данные: дневные свечи BTC/USDT (любая крупная биржа, ccxt).

### C2. On-chain оценка цикла (вес 0.25)

Композит из трёх подметрик (усредняются):

- **MVRV Z-score**: нормализация — z > 3 → −1 (перегрев ≠ бычий сигнал на годовом горизонте!), z в [0..2] → +0.5..+1 (здоровый рост), z < 0 → зона дна, значение для C2 = +0.5 (бычье для накопления, но см. C1 — тренд должен подтвердить).
  ВАЖНО: MVRV кодирует *фазу цикла*, а не направление. В композите его роль — гасить экспозицию у вершин и разрешать лестницу S6 у дна. Реализация: `C2a = 1 − clip(|z − 1| / 2.5, 0, 2)` → максимум при z≈1, спад к краям.
- **Supply in profit**: доля монет в прибыли. >95% → поздняя фаза → −0.5; 50–80% → нейтрально/бычье; <40% → капитуляция.
- **LTH net position change**: долгосрочные холдеры (монеты 155+ дней) распродают → −1, накапливают → +1. Нормализация по перцентилям за 4 года.

Данные: Glassnode / CryptoQuant API (платно) или бесплатные аппроксимации через Dune-запросы. На старте допустимо реализовать только MVRV (публикуется бесплатно несколькими источниками) и добавить остальное позже.

### C3. Структура деривативов (вес 0.20)

- **Funding 30-дневное скользящее среднее** по BTC+ETH: устойчиво положительный умеренный funding (0.005–0.02%/8ч) → +1 (здоровый бык); экстремальный (>0.05%/8ч неделями) → снижение до 0 (перегрев); устойчиво отрицательный → −1.
- **OI / Market Cap**: рост отношения без роста цены за 14 дней → штраф −0.5 (набитые плечи = топливо каскадов в любую сторону, снижает confidence).

Данные: API бирж (funding history — бесплатно), Coinglass для агрегированного OI.

### C4. Макро-фон (вес 0.15)

Грубый трёхуровневый флаг, обновление раз в неделю, допустима ручная установка на старте:

- Цикл ФРС смягчение / QE-режим → +1
- Пауза / неопределённость → 0
- Ужесточение / рост DXY тренд → −1

Данные: FRED API (ставка, баланс ФРС), DXY через любой маркет-дата API. Этот компонент осознанно примитивный — его задача давать фон, не сигнал.

### C5. Ширина рынка (вес 0.10)

Доля монет из топ-100, торгующихся выше своей SMA200. >70% → +1; <30% → −1; линейно между. Отсекает ситуации "BTC растёт один" (узкий, хрупкий рост).

Данные: дневные свечи топ-100 по капитализации.

## 2. Итоговый score и классификация

```
score = 0.30·C1 + 0.25·C2 + 0.20·C3 + 0.15·C4 + 0.10·C5   # ∈ [−1, +1]
```

Пороги с гистерезисом (ключевая защита от пилы):

```
Вход в BULL:   score > +0.30  и держится ≥ 10 торговых дней
Выход из BULL: score < +0.10
Вход в BEAR:   score < −0.30  и держится ≥ 10 дней
Выход из BEAR: score > −0.10
RANGE:         всё, что между, при |score| < 0.30 стабильно ≥ 15 дней
TRANSITION:    первые 15 дней после любой смены режима,
               либо score в "ничейной зоне" без стабилизации
```

`confidence = clip(|score| , 0, 1)`, дополнительно умножается на 0.7, если C3 показывает перегруженность плечами (OI-штраф активен).

## 3. Правила, защищающие от самообмана

1. **Веса зафиксированы до бэктеста.** После прогона на истории разрешено менять их не более одного раза и только с письменным обоснованием в changelog. Подбор весов оптимизатором запрещён.
2. **Компоненты должны быть слабо коррелированы.** При имплементации посчитать корреляционную матрицу C1–C5 на истории; если |corr| > 0.8 у пары — один из компонентов дублирует другой, его вес урезается.
3. **Отказ данных = нейтраль.** Если источник компонента недоступен, компонент получает 0 и его вес перераспределяется, событие логируется. Система не должна падать из-за одного API.
4. **История коротка.** 2017→2025 — это ~3 цикла. Детектор проверяется на "не пропустил ли катастрофу", а не на "максимум доходности" (критерии — док. 04, §5).

## 4. Псевдокод суточного цикла

```python
def daily_update():
    raw = fetch_all_components()          # C1..C5, с обработкой отказов
    score = weighted_sum(raw)
    state = hysteresis_fsm.step(score)    # конечный автомат с порогами §2
    confidence = compute_confidence(score, raw)
    persist(date, raw, score, state, confidence)
    if state != prev_state:
        alert(f"REGIME CHANGE: {prev_state} → {state}")
    allocator.set_targets(ALLOCATION_MATRIX[state], confidence)
```

Реаллокация капитала при смене режима — не мгновенная: целевые веса достигаются за 5–10 торговых дней равными шагами (уменьшает цену ложного переключения).
