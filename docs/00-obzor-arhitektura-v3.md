# Торговая система: обзор и архитектура — v3

> Статус: спецификация. Числовые параметры — стартовые значения, подлежащие проверке на исторических данных.

**Что изменилось в v3:** S1 исключена из постоянной архитектуры по результатам гейта активации (`30-variant-b-peresmotr-arhitektury.md`); **ядром становится S4**; матрица аллокации переписана; дорожная карта обновлена под фактическое состояние.

---

## 1. Идея системы в одном абзаце

Система состоит из двух уровней. **Верхний** — детектор режима рынка (бык / медведь) на дневных данных, обновляется раз в сутки. **Нижний** — пул стратегий, каждая со своим родным режимом. Детектор не предсказывает будущее, а распознаёт режим с запозданием в дни-недели; его задача — включать и выключать стратегии и задавать веса капитала.

**Изменение в v3:** ядром доходности является не funding-арбитраж, а размещение стейблкоинов под доходность. Постоянного нейтрального ядра с приемлемым отношением доход/сложность на розничном капитале не найдено.

┌─────────────────────────────────────────────┐
│ 1. Data Layer                               │
│    цены/объёмы (CEX API), funding, OI,      │
│    on-chain, macro                          │
└──────────────┬──────────────────────────────┘
               │
┌──────────────▼──────────────────────────────┐
│ 2. Regime Detector (док. 01 v5)             │

└──────────────┬──────────────────────────────┘
               │
┌──────────────▼──────────────────────────────┐
│ 3. Allocator                                │
│    режим + модификаторы → веса капитала     │
└──────────────┬──────────────────────────────┘
               │
┌──────────────▼──────────────────────────────┐
│ 4. Strategy Pool (док. 02)                  │
│    ЯДРО: S4 стейблкоин-доходность           │
│    S2/S9 моментум │ S5 unlock │ S6 ladder   │
│    S7 panic-fade (внутридневной контур)     │
└──────────────┬──────────────────────────────┘
               │
┌──────────────▼──────────────────────────────┐
│ 5. Execution + Risk Monitor (док. 03)       │
│    ордера, лимиты, контрагентский риск      │
└─────────────────────────────────────────────┘

**Слой данных:** on-chain, макро и ширина рынка **не участвуют в определении состояния** — они модификаторы, влияющие на размер позиции (`01-detektor-rezhima-v5.md` §2). Состояние определяется исключительно ценой.

## 3. Пул стратегий

| ID | Стратегия | Родной режим | Роль | Статус |
|----|-----------|--------------|------|--------|
| **S4** | **Стейблкоин-доходность** | **все** | **Ядро** | к реализации |
| S2/S9 | Кросс-секционная моментум-ротация | BULL | Направленный доход | заблокирована данными |
| S5 | Event-шорты под токен-разлоки | BEAR | Событийный доход | не начата |
| S6 | Лестница накопления по капитуляции | BEAR + ACCUMULATION | Подготовка к циклу (бета) | не начата |
| S7 | Fade panic | событийная, внутридневная | Событийный доход | нужен контур |
| S1 | Funding-арбитраж | — | **исключена** | см. §3.1 |
| S3 | Mean reversion | — | **удалена** | минус без издержек |

### 3.1 S1 — исключена, с измеримым условием возврата

Гейт активации провалил критерий: запас над S4 +2.3 п.п. при требуемых 4.0; активна 17% времени при требуемых 30% (`30` §1).

При этом механизм не сломан: **в активные периоды S1 приносит около 18.5% годовых**. Сломана доступность — премия сжалась и стала эпизодической (16% → 19% → 7.6% по подпериодам).

**Условие возврата:** доля времени с `EMA7(funding_BTC) ≥ 0.010%/8ч` достигает ≥30% на скользящем годовом окне. Метрика считается автоматически, проверяется ежеквартально. Это условие, а не аргумент.

## 4. Матрица аллокации (стартовая)

| Стратегия | BULL | BEAR |
|-----------|------|------|
| **S4 стейблкоин-доходность** | **40%** | **75%** |
| S2/S9 моментум | 40% | 0% |
| S5 unlock-шорты | 0% | 10% |
| S6 лестница накопления | 0% | 0–15%* |
| Свободный резерв | 20% | 15% |

\* Только при `cycle_phase = ACCUMULATION`, забирает долю из S4.

S7 вне матрицы — событийная, работает на выделенном малом капитале.

**Изменение относительно v2:** доля S1 (50% в BULL, 30% в BEAR) перераспределена в S4 и в увеличенный резерв. Резерв повышен сознательно: работающих стратегий сейчас мало, и держать капитал незанятым честнее, чем впихивать в непроверенные конструкции.

**Модификаторы поверх матрицы:**

| Модификатор | Действие |
|---|---|
| `cycle_phase = EUPHORIA` | запрет наращивания, срезание плечевого лимита |
| `cycle_phase = ACCUMULATION` | разрешает S6 |
| `macro_flag = −1` | целевая экспозиция × 0.75 |
| `breadth < 0.35` | S2/S9 не запускаются даже в BULL |
| `leverage_warning` | сигнал риск-модулю; влияет на темп ввода капитала (`23` §4) |
| `stress_level` | **диагностический, на решения не влияет** |

## 5. Принципы, которые не обсуждаются

1. **Детектор медленный и простой — результат измерения, а не вкуса.** Композит из четырёх параметров не превзошёл однострочник на кросс-рыночной проверке. Детектор выбран как самый дешёвый среди статистически неразличимых.
2. **Детектор не является защитным механизмом** (`03` §9). Плечо не увеличивается на основании «детектор защитит».
3. **Никакая направленная стратегия не работает без разрешения детектора.**
4. **Тривиальный бенчмарк прогоняется до постройки сложного.** Главный процессный урок проекта.
5. **Параметры не оптимизируются под историю.**
6. **Комиссии и проскальзывание считаются в каждом бэктесте** по пессимистичной модели.
7. **Плечо ≤ 2x и только в нейтральных конструкциях.** Значение 3x запрещено: внутридневной рост +36.2% превышает уровень ликвидации при 3x (`27` §2).
8. **Минимум 2 биржи и 2 эмитента стейблкоинов.** С переходом S4 в ядро контрагентский риск становится главным риском системы.
9. **Отвергнутое не возвращается без нового основания.** Реестр — `rejected.md`.
10. **Каждая идея отвечает на два вопроса:** кто на другой стороне и почему платит; что произойдёт, если половина участников выйдет в один день (`t03 v2` §4.5).

## 6. Дорожная карта

| Этап | Содержание | Критерий выхода | Статус |
|------|-----------|-----------------|--------|
| 0. Данные | Свечи D1, funding, OI | 3+ года без дыр | ✓ выполнено |
| 1. Детектор режима | SMA200, док. 01 v5 | воспроизведение эталона | ✓ выполнено |
| 2. Бэктест-движок | издержки, отчёты, тест на look-ahead | воспроизводимость | ✓ частично |
| 3. **S4 как ядро** | лимиты, мониторинг депега, диверсификация площадок | работает на малом капитале 1 мес. | **текущий** |
| 4. **S5 unlock** | календари вестинга, event study | положительное матожидание после издержек | **следующий** |
| 5. Историческая вселенная | внешний источник рангов + цены делистнутых | `universe(date)` с 2019 | параллельно |
| 6. S2/S9 кросс-секция | корзина → IC → отбор | бьёт равновзвешенную корзину | после этапа 5 |
| 7. Внутридневной контур | лента сделок, ликвидации, стакан | разметка каскадов по часам | позже |
| 8. Малый капитал live | 5–10% планируемого | 3 мес. без расхождений paper vs live | — |

Этап 3 добавлен: S4 перестала быть «местом переждать» и требует собственной проработки как носитель основного капитала.

## 7. Честная оценка состояния

**Работает и внедрено:** детектор SMA200.

**Готово к реализации:** S4.

**Всё остальное:** заблокировано данными, не построено или закрыто измерениями.

Семь направлений закрыто числами: композитный детектор, состояние CRASH, volatility targeting, ансамбль, гейт наклона, S3, S1 в постоянной архитектуре. Ни одно не дошло до живых денег — это и есть основной результат проекта на сегодня.

**S4 под 5% годовых можно разместить без единой строки кода.** Признать её ядром означает признать, что автоматизация пока не создала ценности сверх этого. Ценность появится, если заработает хотя бы одна из S5, S7 или кросс-секции.
