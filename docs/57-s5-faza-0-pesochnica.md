# S5: фаза 0 — проверка интеграции в песочнице Kraken

**Назначение:** задание для исполнителя (Claude Code).
**Повод:** у Kraken Futures есть самостоятельная демо-среда — появляется возможность проверить исполнение без денег и без ожидания редких событий.
**Статус:** новая фаза перед микро-live. Протокол `54` не меняется, к нему добавляется предшествующий этап.

---

## 1. Что даёт песочница

`demo-futures.kraken.com` — отдельная среда с изолированными ключами. Регистрация самостоятельная, почта не подтверждается. REST и WebSocket идентичны продакшену по эндпоинтам и структуре ответов; **отличается только базовый URL**, то есть переход на прод — замена одной константы.

**Ограничение:** среда периодически сбрасывается и предназначена для проверки интеграции, а не для накопления истории. Для наблюдения за премией она не годится.

### 1.1 Проверить доступность первым делом

Источники расходятся: актуальная документация описывает sandbox как рабочий и самообслуживаемый, при этом более раннее уведомление сообщало о выводе демо-среды из эксплуатации 14 июля. Вероятно, среду перезапустили или мигрировали.

**До всякой сборки:** зарегистрироваться, выпустить ключ, сделать один запрос к `/derivatives/api/v3/instruments`. Если среда недоступна — вернуться к плану без фазы 0 и решить, как проверять стоп иначе (§6).

---

## 2. Зачем это нужно: два непроверенных компонента

Фаза 0 закрывает ровно те два места, которые иначе ушли бы в прод непроверенными.

### 2.1 Стоп-логика

`54` §5: за три месяца микро-live ожидается **2–3 срабатывания стопа** — мало для уверенности, что механизм работает.

В песочнице стоп прогоняется искусственно: порог 1% вместо 30%, открыть позицию, дождаться срабатывания, повторить два десятка раз.

### 2.2 Отмена разлока после входа

`55` §2.3: при переносе или отмене разлока позиция закрывается немедленно.

Событие редкое — в живых данных может не встретиться месяцами. В песочнице воспроизводится по команде: подменить дату в тестовом фиде и убедиться, что позиция закрылась и записалась в журнал отдельной категорией.

---

## 3. Три фазы — общая картина

| Фаза | Среда | Капитал | Что проверяется |
|---|---|---|---|
| **0. Интеграция** | demo-futures | нет | ордера, стопы, ошибки, реконнект, отмена события |
| 1. Микро-live | futures | $1,000 | проскальзывание, издержки, реальная премия |
| 2. Реальный капитал | futures | по решению | после критериев `54` §6 |

Фаза 0 не измеряет доходность и не заменяет наблюдение за премией — среда сбрасывается, а цены там не всегда соответствуют рынку.

---

## 4. Задание: что проверить в фазе 0

### 4.1 Базовая интеграция

| Проверка | Критерий |
|---|---|
| Аутентификация, подпись, nonce | запросы проходят стабильно |
| Список инструментов | получен, сопоставим с продакшеном |
| Размещение лимитного ордера | ордер виден в стакане |
| Размещение рыночного ордера | исполнен, позиция открыта |
| Отмена ордера | ордер снят |
| Чтение позиций и баланса | данные согласуются с историей ордеров |
| Обработка ошибок | недостаточная маржа, неверный символ, слишком малый размер — понятные сообщения, не падение |

### 4.2 Стоп-логика — главное

**Прогнать не менее 20 срабатываний.** Порог занизить до 1–2%, чтобы события происходили часто.

Проверить всю цепочку:

```
обнаружение достижения порога по внутридневному максимуму
    → расчёт убытка
    → отправка закрывающего ордера
    → подтверждение закрытия
    → запись в журнал
```

**Отдельно проверить сбойные сценарии:**

| Сценарий | Ожидаемое поведение |
|---|---|
| Закрывающий ордер отклонён | повтор, эскалация, алерт |
| Разрыв соединения в момент срабатывания | после реконнекта позиция проверяется и закрывается |
| Позиция уже закрыта вручную | не пытаться закрыть повторно, записать факт |
| Цена прошла порог с разрывом | закрытие по факту, фиксация проскальзывания |

Последний пункт важен: стоп −30% при разрыве может исполниться на −40%, и система должна это записать, а не проигнорировать.

### 4.3 Отмена разлока

Подменить дату события в тестовом фиде на открытой позиции. Проверить: позиция закрывается немедленно, в журнал попадает отдельная категория, срок до плановой даты фиксируется.

### 4.4 Устойчивость

| Проверка | Как |
|---|---|
| Реконнект WebSocket | принудительный разрыв, проверка восстановления подписок |
| Перезапуск процесса с открытыми позициями | состояние восстанавливается из биржи, а не из памяти |
| Сброс демо-среды | система переживает потерю позиций, пишет инцидент |

Третий пункт полезен побочно: сброс среды — бесплатная имитация отказа биржи.

### 4.5 Approval Gate

Проверить, что каждое событие уходит на ручное подтверждение и без него ордер не отправляется. При ~5 событиях в месяц в проде это будет редкий путь кода — тем важнее прогнать его в песочнице десятки раз.

---

## 5. Критерии выхода из фазы 0

| Условие | Порог |
|---|---|
| Стоп сработал корректно | ≥20 раз, включая ≥3 сбойных сценария §4.2 |
| Отмена разлока обработана | ≥3 раза |
| Реконнект и перезапуск | без потери состояния |
| Approval Gate | ни одного ордера в обход |
| Ошибки API | обработаны, процесс не падает |

**При выполнении** — переход к микро-live по протоколу `54`, единственное изменение в коде: базовый URL.

---

## 6. Если песочница недоступна

Зафиксировать заранее.

Стоп-логику проверять на **синтетике**: локальный мок биржевого API, воспроизводящий ответы и ценовые ряды. Дольше в разработке, но покрывает те же сценарии §4.2.

Отмену разлока — так же, через подмену данных в тестовом фиде.

**Чего не делать: не идти в микро-live с непроверенным стопом**, рассчитывая, что два-три живых срабатывания покажут проблемы. Стоп — единственная защита хвоста, и в BULL хвост толще (`s5_diagnostics.md`: худшие 10% = −31% против −20.6%).

---

## 7. Чего не делать

- **Не измерять доходность в песочнице.** Цены там не всегда соответствуют рынку, среда сбрасывается.
- **Не считать фазу 0 заменой микро-live.** Проскальзывание и реальные издержки проверяются только на живых ордерах.
- **Не менять протокол `54`** по результатам фазы 0 — она проверяет исполнение, а не стратегию.
- **Не пропускать сбойные сценарии §4.2.** Именно они отличают работающую систему от работающей в хорошую погоду.
