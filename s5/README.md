# S5: разлоки по вселенной Kraken Futures

Обход всех перпов Kraken Futures в поиске **бесплатных** источников расписаний
вестинга. По одному файлу на инструмент: что за монета, нашлись ли разлоки и
можно ли их собирать автоматически.

Собрано 02.09.2026. Вселенная — 274 перпетуала `PF_*` (плюс 8 датированных
фьючерсов на BTC/ETH/SOL, которые не отдельные монеты и в разбор не входят),
снято с `https://futures.kraken.com/derivatives/api/v3/instruments`.

## Источник: бесплатный CDN DefiLlama

Оговорка: **это не новость для проекта.** Бот уже ходит именно туда —
`DefiLlamaEmissionSource` (doc 50). Устарел был только текст CLAUDE.md, который
утверждал, что бесплатных разлоков нет; он поправлен. Платным стал лишь
API-хост `api.llama.fi/emissions` (HTTP 402), а корпус целиком лежит на CDN,
который кормит их собственный фронтенд, и отдаётся без ключа и без лимитов:

```
GET https://defillama-datasets.llama.fi/emissionsProtocolsList   # 372 протокола
GET https://defillama-datasets.llama.fi/emissions/{slug}         # расписание одного
```

Проверено на всех 372 протоколах: HTTP 200, JSON, форвардные события до 2032 года.

Содержимое одного файла:

| Поле | Что внутри |
|---|---|
| `metadata.events[]` | дискретные события: `timestamp`, `noOfTokens`, `category`, `unlockType` (`cliff`/`linear`), `rateDurationDays` |
| `documentedData.data[]` | посуточный ряд `{timestamp, unlocked, rawEmission, burned}` по каждому траншу, включая будущее |
| `documentedData.tokenAllocation` | доли траншей: `current` / `final` / `progress` |
| `supplyMetrics` | `maxSupply`, `adjustedSupply`, `tbdAmount` |
| `gecko_id`, `metadata.token` | связка с CoinGecko для маппинга на тикер |

### Грабли, найденные на живых данных

1. **`gecko_id` бывает мусорным** (у IOTA там строка `IOTA`, а не id). Маппить
   надо по `metadata.token` вида `coingecko:iota`, и только потом падать на `gecko_id`.
   Без этого теряется часть монет.
2. **`timestamp` иногда приходит строкой**, а не числом (например, у Curve).
   Приводить типы обязательно, иначе разбор падает.
3. **`unlockType: "linear"` в `noOfTokens` хранит смену скорости** `[было, стало]`
   за `rateDurationDays`, а не объём. Считать объём по таким событиям как по
   обрывам — грубая ошибка.
4. **Не всякий `cliff` — событие S5.** Часть адаптеров моделирует линейный
   вестинг как ежедневные микрообрывы (Celestia: 183.6 тыс TIA каждый день,
   0.02% циркуляции). Настоящее событие надо отбирать по размеру, а не по типу.
   Здесь порог — обрыв больше 0.5% циркуляции.
5. **Слаг протокола не равен монете.** `portal` в корпусе — это Wormhole (W),
   а игровой PORTAL там отсутствует. Проверять связку только через токен.

Вывод: бесплатной альтернативы DefiLlama нет — и она не нужна, потому что сам
DefiLlama бесплатен через CDN. Остальные платные источники покрыли бы 35 монет
из «пробела» ниже.

## Сверка с боевым S5

Логика `UnlockFeed` воспроизведена на том же корпусе (порог, окно, способ
считать циркуляцию — как в коде) и сопоставлена с этим разбором.

Три вложенных множества, **не три разных списка**:

| Правило | Монет | Что это |
|---|---|---|
| `UnlockFeed` как есть: **отдельный транш** ≥3% | **11** | 2Z, BIGTIME, CELO, INIT, LAYER, MON, ONDO, OPN, PYTH, RIVER, XPL |
| порог 3% к **сумме траншей за день** | 17 | те же 11 + ALT, CYBER, EIGEN, KAITO, STRK, ZRO |
| этот разбор: транш >0.5% | 27 | те же 17 + ARB, GMT, GRASS, HFT, PUMP, REZ, S, SEI, ZETA, ZK |

11 ⊂ 17 ⊂ 27, расхождений нет. Совпадение по 11 монетам — полное.

### Найдено расхождение с собственным замыслом кода

`UnlockFeed.collect()` отсекает по `MIN_PCT = 3%` **каждый транш по
отдельности**, и только уцелевшие попадают в `merge()`. Но комментарий к
`merge()` говорит, что слияние существует ради «истинного размера клиффа за
день». Для XPL это работает (3.2 + 32.5 + 32.5 — каждый транш и так проходит),
а день из нескольких траншей ниже порога отбрасывается целиком, хотя в сумме он
порог перекрывает.

Что теряется — 6 монет и ближайшее событие всего через 12 дней:

| Монета | Дата | Сумма за день | Из чего |
|---|---|---|---|
| STRK | 2026-09-14 | 3.35% | транши < 3% |
| KAITO | 2026-09-19 | 3.83% | транши < 3% |
| **ZRO** | **2026-09-19** | **3.74%** | **1.68% + 2.06%, оба `insiders`** |
| ALT | 2026-09-25 | 3.36% | транши < 3% |
| EIGEN | 2026-10-01 | 4.27% | транши < 3% |
| CYBER | 2026-11-14 | 4.92% | транши < 3% |

И дальше ежемесячно: у STRK, KAITO, ZRO, ALT, EIGEN разлок помесячный, то есть
это не единичный промах, а систематический.

Порядок правки очевиден из самого кода: сначала `merge()` по `символ@день`,
порог `MIN_PCT` — после слияния. Отдельный вопрос — не занижен ли при этом
порог: 3% к сумме отбирает не то же самое, что 3% к траншу, и вселенная
вырастет с 11 до 17 монет. Это решение по стратегии, а не по коду, поэтому
здесь оно не сделано.

### В бэктесте слияния нет вообще — 41% сделок дублируют друг друга

Проверены все стадии: `S5Unlocks`, `S5Model`, `S5Paper`, `S5Reentry`,
`S5EventImporter` — везде порог приложен к траншу, а `merge()` не вызывается
нигде. Каждый уцелевший транш становится отдельной сделкой. То есть логик не
две, а три:

| | Порог | Слияние | XPL 25.09 даёт | ZRO 19.09 даёт |
|---|---|---|---|---|
| Бэктест | к траншу | **нет** | **3 сделки** (3.2 / 32.5 / 32.5%) | ничего |
| Бот `UnlockFeed` | к траншу | есть | 1 сделку 68.2% | ничего |
| «3% к сумме» | к сумме | есть | 1 сделку 68.2% | 1 сделку 3.74% |

Реплика `S5Unlocks` на сегодняшнем корпусе с фильтром по перпам Binance даёт
**1431** транш-строку против **1433** в `s5_unlocks_run.txt` — считаем одно и
то же. Но за ними стоит лишь **838** различных событий «символ + день»:

| | |
|---|---|
| Транш-строк (что бэктест считал сделками) | 1431 |
| Различных событий | **838** |
| Многотраншевых событий | 323 (39%) |
| Строк-дубликатов | **593 (41%)** |

Дубликаты не просто коррелированы, а тождественны: вход и выход зависят только
от символа и дня, значит один исход посчитан по 2–10 раз. Отсюда: эффективная
выборка 838 вместо 1433 → доверительный интервал у́же настоящего примерно в
**1.31 раза**; среднее перекошено к крупным многотраншевым разлокам; максимум
одновременно открытых позиций **19 по траншам против 10 по событиям**, а лимит
сайзинга ≤4.5% выводился из сценария «18 одновременных».

Разбор и план правки — `docs/130-s5-porog-do-sliyaniya-i-dubli-sobytiy.md`.

### Второй риск, найденный при сверке

`geckoToTicker` — это отображение `gecko_id → тикер` по всему списку CoinGecko,
без проверки, что протокол и монета Kraken — одно и то же. У `velodrome-finance`
тикер `VELO`, и на Kraken `PF_VELOUSD` есть, но это другая монета (Velo Labs).
Сейчас Velodrome будущих событий не даёт, поэтому вреда нет, но подмена
структурная: любой протокол, чей тикер совпал с чужим перпом Kraken, отдаст
чужое расписание.

## Пробел: вестинг есть, бесплатных данных нет

`ACE, AEVO, AKT, ANIME, AUCTION, BANANA, BEL, BIO, CATI, CGPT, COOKIE, DEXE,
GALA, GPS, HMSTR, ID, IO, KAIA, MIRA, NIGHT, OPEN, PIXEL, PORTAL, PROMPT,
RENDER, RSR, SAND, SOON, SSV, SYN, TRB, WLFI, XCN, ZBT, ZIG`

Три пути закрыть, по возрастанию стоимости:

1. **Написать адаптер в `DefiLlama/emissions-adapters`** — репозиторий открытый,
   принятый адаптер сам появится в CDN, и данные придут бесплатно всем. Дешевле
   всего для монет, у которых вестинг задан контрактом.
2. **Свой ончейн-коллектор** под конкретный контракт вестинга. Тот же путь, что
   для XRP и LUNA2, но без общего профита.
3. **Платная подписка** CryptoRank Pro или Tokenomist.

## Что дальше по S5

- Вселенная S5 сужается до 27 монет — и это верхняя граница, потому что она ещё
  не фильтрована по ликвидности перпа и по шагу контракта Kraken. Шаг контракта
  уже закрывал хедж на живом масштабе (см. CLAUDE.md про `contractValueTradePrecision`),
  так что через этот фильтр пройдут не все 27.
- Порог «крупного» события 0.5% циркуляции выбран как отсечка от ежедневной
  капели адаптеров, а не измерен. Его надо калибровать по отклику цены, иначе
  вселенная либо забьётся шумом, либо потеряет события.
- Расписание — не факт, а план: даты и объёмы в адаптерах меняются задним
  числом. Для честного бэктеста нужен снимок расписания на момент времени
  (принцип `available_at` из док. 04 §1), то есть корпус надо снимать
  ежедневно и хранить версиями, а не перечитывать текущее состояние.
- Чёрный список из 93 монет стоит перепроверять раз в месяц по
  `emissionsProtocolsList`: адаптеры добавляются.

## Как перегенерировать

```sh
curl -s https://futures.kraken.com/derivatives/api/v3/instruments        # вселенная
curl -s https://defillama-datasets.llama.fi/emissionsProtocolsList       # список протоколов
curl -s https://defillama-datasets.llama.fi/emissions/<slug>             # расписание
curl -s https://api.coingecko.com/api/v3/coins/markets?vs_currency=usd&per_page=250&page=N
```

Связка тикер Kraken → слаг DefiLlama идёт через `metadata.token` (`coingecko:<id>`)
и список CoinGecko; ручных разрешений два — `VELO` (в корпусе два кандидата,
берётся `velo-finance`) и `BB` → `bouncebit`.
