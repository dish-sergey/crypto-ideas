# S5: протокол paper trading — финальная версия (doc 54)

Заменяет план из `s5_paper_plan.md` (doc 53). К исполнению. Механизм и три предзапусковые находки —
в `s5_paper_plan.md`; здесь — итоговый протокол и зафиксированные до запуска правила.

## 0. Название и природа

**Не «шорт под разлоки на вынужденных продажах», а «шорт под ПРЕДВОСХИЩЕНИЕ разлока».** Профиль цены
(−7…0 дней: 0/−0.90/−2.02/−2.64/−2.46/−2.86/−3.66/−3.96%) показывает: рынок отыгрывает публичную дату
ЗАРАНЕЕ, постепенно к дню −3. Значит:
- премия за дискомфорт (`t03 v3` §5.2) **не применима** — это «все знают и делают», а не «неудобно делать»;
- **арбитрируемость высокая** (как у моментума) → монитор деградации = условие эксплуатации, не формальность;
- окно входа 5 дней обосновано (вход за 3 дня ловит остаток 0.09%).

**Правка спеки `02-strategii-v2.md` (за постановщиком):** переименовать S5 и заменить механизм
«вынужденная продажа» → «предвосхищение публичного разлока»; я спеки не трогаю.

## 1. Масштаб: оперировать ≈ +13 п.п., не +179%

`125 сделок/год × 2.49% × 4.5% позиция ≈ 14%/год` + альт. на остатке `3%×74% ≈ 2.2%` → ≈ 16.2%/год
против альтернативы 3% → **≈ +13 п.п.** И это **верхняя граница** (расписания не point-in-time; продления
локов не учтены → реальная величина ниже на неизвестную величину). Цифру +179% в оценках НЕ использовать.

## 2. Протокол

```
Капитал:    $1,000 (микро; проверка системы в проде, не доход)
Позиция:    ≤4.5% ($45), суммарная экспозиция ≤81%   ← НЕ ослаблять (лимит консервативен, но не менять)
Вход:       шорт перпа за 5 дней до клифф-разлока ≥3% circulating
Выход:      в день разлока до разблокировки
Стоп:       −30% по внутридневному максимуму (проскальзывание ≥1%)
Фильтр:     пропускать события с funding < −1.5% за 5 дней (дорогой шорт)
Монитор:    rolling-20 и rolling-40 премии — в НАБЛЮДЕНИИ, без авто-паузы (§3)
Approval Gate: включён на весь период — ~10 сделок/мес, каждую видеть глазами
Срок:       ≥3 месяца ИЛИ 20 событий, что дольше
```

## 3. Калибровка порога деградации — способ зафиксирован ДО данных

Порог `rolling-20 < 0` опровергнут бэктестом (73x против 2242x — паузит на нормальной дисперсии).
**Заменять подобранным по paper числом ЗАПРЕЩЕНО** (это тот же фиттинг, только медленнее).

Правило паузы формулируется из ПРИНЦИПА (устойчивый уход премии в минус), а не из данных:
```
пауза при:  rolling-40 < 0  ЛИБО  два подряд отрицательных rolling-20
```
В paper — вести в наблюдении; допустимо только **подтвердить или отвергнуть** эту формулировку, не
подбирать окно/порог. Окончательный порог фиксируется **до реального капитала**, не в процессе paper.

## 4. Что сверять (главный индикатор — издержки, `03-v2 §8`)

| Величина | Модель | Порог тревоги |
|---|---|---|
| Комиссии + проскальзывание | 0.19%/сделка | > 1.5× |
| Funding фактический | по данным | расхождение |
| Цена входа vs плановой | — | систематическая задержка |
| Частота событий | ~10/мес | существенно ниже |
| Срабатывания стопа | ~8% | см. §5 |

## 5. Стоп-логика может остаться НЕПРОВЕРЕННОЙ

За 3 мес при 8% ожидается **2–3 стопа** — мало для уверенности. **Отсутствие стопов ≠ успех, это
непроверенный компонент.** До реального капитала прогнать стоп-логику отдельно (синтетика или тестовый
режим с заниженным порогом): убедиться, что срабатывание, расчёт убытка (−30% ≈ $13.5 при $45) и
закрытие позиции работают.

## 6. Критерии выхода из paper → реальный капитал

| Условие | Порог |
|---|---|
| Издержки | ≤ 1.5× модельных |
| Реализованная премия | положительна и в ДИ модели |
| Сбои исполнения | ≤ 10% |
| Стопы | ~8% без систематических проскоков **или** отдельная проверка §5 |

При выполнении → реальный капитал той же микро-суммой, транширование по `23 §4`.

## 7. Чего не делать

- Не оперировать +179% нигде.
- Не подбирать порог деградации по paper-данным (§3).
- Не ослаблять лимит 4.5% из-за отсутствия массовых стопов.
- Не считать отсутствие стопов подтверждением стоп-логики (§5).
- Не переходить на реальный капитал до всех критериев §6.
- Помнить: механизм арбитрируем — монитор деградации не формальность.

## 8. Что нужно построить для запуска (инфраструктура — отдельно)

Протокол выше — что делать; исполнение требует системы (реальные ордера на Kraken):
1. **Live-фид разлоков:** DefiLlama datasets-CDN (`emissions/{slug}`) → клифф-события ≥3% circ на 5 дней
   вперёд; сопоставление slug→тикер→Kraken-перп.
2. **Фильтр дорогого шорта:** funding Kraken за 5 дней (предиктивный из `kraken_ticker`).
3. **Approval Gate** (`07-approval-gate.md`): каждое событие на ручное подтверждение.
4. **Исполнение:** шорт-ордер на Kraken Futures (микро), стоп −30% по внутридневному максимуму.
5. **Монитор:** журнал сделок, rolling-20/40 в наблюдении, сверка издержек с моделью.

Это самостоятельная сборка с реальным размещением ордеров (микро-капитал) — запускать по решению
постановщика; протокол параметров зафиксирован здесь.

## Статус

S5 — единственная из восьми стратегий, прошедшая всю воронку до paper, по тем же правилам, что закрыли
шесть остальных. Итог сдержанный: ≈+13 п.п. (не +179%), масштаб ограничен кластеризацией, механизм
арбитрируем (предвосхищение), премия — верхняя граница, стоп не проверен исполнением. Первый работающий
результат проекта — идёт в paper с открытыми глазами на все ограничения.

## Дополнения (doc 55) — к внесению до первой сделки

### Терминология: это МИКРО-LIVE, не paper
§8 описывает реальные ордера на Kraken Futures (микро). Проскальзывание, задержка исполнения,
поведение стакана, фактические комиссии — **проверяются** (paper их не измеряет по определению, а §4
называет издержки главным индикатором). **Переименовать: микро-live.** Роль прежняя — проверка системы
в проде, не доход.

### Правило пересмотра расписания после входа (§2)
Расписания пересматриваются (именно поэтому премия — верхняя граница). В протоколе выхода этого не было.
```
При объявлении переноса/отмены разлока ПОСЛЕ входа:
    позиция закрывается НЕМЕДЛЕННО (не ждать плановой даты) — основание сделки исчезло
    фиксировать отдельной категорией журнала
```
Побочная выгода — **измерение частоты пересмотров** (той самой величины дисконта, что сейчас неизвестна):
фиксировать долю событий с изменением расписания после входа, срок до даты объявления, результат позиции.
Требует **ежедневного перечитывания расписаний по открытым позициям** (не разовой загрузки при входе) —
**шестой пункт инфраструктуры §8**.

### Пред-запусковые проверки (§3) — ВЫПОЛНЕНЫ

**§3.1 Доступность на Kraken:** из 1433 событий (≥3%circ) на Kraken торгуются **798 (56%)**; уникальных
токенов 100/182. Частота Kraken-событий **~5/мес** (не 10). Ожидание §6 (40–70%) подтверждено. Следствие:
20 событий наберётся за **~4 месяца** (критерий ≥3мес/20 событий → реально ~4 мес). Порог 3%circ НЕ снижать.

**§3.2 Предсказуемость funding:** корреляция текущей ставки с накопленной за 5 дней = **0.812**; решение
фильтра (дорогой/дешёвый) по `current×5` совпадает с фактической 5-дневной в **94%** случаев. ⇒ **текущая
ставка из тикера годна как прокси фильтра в live** (ожидание подтверждено — funding персистентен). Оговорка:
считано на Binance-funding (ранги не переносятся на Kraken, но персистентность — свойство площадки; проверить
на Kraken-funding в наблюдении).

### Обновлённый срок
Критерий ≥3 месяца ИЛИ 20 событий, что дольше. При ~5 Kraken-событий/мес — реально **~4 месяца**. Ускорять
снижением порога 3%circ нельзя.
