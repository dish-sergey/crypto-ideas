# Окно истории сделок Kraken — проверка (doc 33 §C)

Проверено вживую 2026-08-08, эндпоинт v3 `/history?symbol=PF_XBTUSD&lastTime=…`.

## C2. Результат

| Запрос | Ответ |
|---|---|
| `lastTime` = сейчас − 30 дней | **пусто** |
| `lastTime` = сейчас − 1 год | **пусто** |

Оба глубоких запроса вернули пустой ответ. Толкование подтвердилось: эндпоинт — это
**скользящий буфер ~7 дней (или до перезапуска движка)**, а не архив. Тиковую историю
через REST достать нельзя.

## C3. Выкачка нереалистична независимо от C2

Даже будь окно скользящим: 100 сделок за запрос × десятки тысяч сделок/сутки по активному
перпу → сотни запросов на день на инструмент. За 3 года по одному BTC — ~100k запросов до
лимитов частоты; по 150+ инструментам — неподъёмно.

**Вывод (фиксируется независимо): тиковая история требует платного источника либо
собственного forward-сбора (Блок D).**

## C4. Приоритеты не заблокированы

**S12 тики не нужны** — ей достаточно funding, mark price, OHLCV (всё доступно, funding с
ограничением глубины см. `perp_universe.md`). Тики требуются только внутридневному контуру
S7, который отложен. **Блок C приоритетное направление (S12) не блокирует.**
