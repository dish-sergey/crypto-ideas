# Детектор v5 — проверки блока A (doc 22 §A8)

Реализация: `RegimeDetectorV5`, таблица `regime_daily_v5`, CLI `--backfill=regime-v5`.
Состояние = `close > SMA200 → BULL, иначе BEAR`. Оси D/T/S, состояния RANGE/TRANSITION/
CRASH, dd_speed, dwell-lock, гистерезис — **удалены**. Модификаторы сохранены (состояние
не меняют). `confidence` — непроверенная эвристика, для размера капитала не используется.
`stress_level` — диагностический (флаг `stress_level_is_diagnostic`). Добавлен
`dist_atr = (close − SMA200)/ATR90`.

## A8.1 Causality ✓
Состояние дня `t` = `close[t] > SMA200[t]`, где `SMA200[t]` использует только `close[t−199..t]`.
Зависит исключительно от прошлого → каузально по построению. Идентичное правило
(`Candidates.Sma200`) прошло causality-тест **20/20** в стенде (`reports/bench/checklist.md`).

## A8.2 Воспроизведение эталона ✓ (точно)
`--report=regime-econ --table=regime_daily_v5`, BTC 2020-01-01 … 2026-07-23, прокси стенда:

| | v5 (факт) | эталон (doc 22) | расхождение |
|---|---|---|---|
| CAGR | **36.7%** | 36.7% | 0.0 п.п. |
| MaxDD | **−53.7%** | −53.7% | 0.0 п.п. |
| Sharpe | 0.94 | — | — |

Совпадение точное (порог: расхождение >0.5 п.п. = ошибка). B&H: CAGR 39.9%, MaxDD −76.6%.

## A8.3 Потребители удалённых полей — аудит ✓ (тихого обвала нет)
Поиск по `axes / RANGE / TRANSITION / CRASH / regime_daily_v2/v3` в `src/main`:

| Где | Что читает | Ломается на v5? |
|---|---|---|
| `RegimeDetector`, `RegimeDetectorV2/V3`, `RegimeFsmV2/V3`, `HysteresisFsm` | собственные состояния/таблицы v1/v2/v3 (исторические детекторы) | нет — самодостаточны, свои таблицы |
| `AllocationProxy` (crash-econ, maxdd, ensemble, voltarget) | `regime_daily_v2.d/t/s` | нет — таблица v2 сохраняется |
| `RegimeReport.generateCompare` | `regime_daily_v2.d/t/s` (панель D/T/S) | нет — читает v2 |
| `Bench`, `Candidates`, `PeakTroughLabeler` | эталонная разметка + свечи, состояния кандидатов | нет — не читают детектор |

**Вывод:** v5 — новая таблица `regime_daily_v5`, ничего существующее её не читает и не
ожидает у неё `axes/RANGE/...`. Все читатели удалённых полей работают против исторических
таблиц v2/v3, которые не тронуты. Тихого обвала на отсутствующем ключе нет. Для прод-дашборда
нужен отдельный v5-отчёт + переключение cron (шаг деплоя, вне §A).

## A8.4 Гистерезис отсутствует ✓
`days_in_state` сбрасывается в 1 при любой смене состояния — минимальная длительность = 1 день.
В стенде sma200 давал 8.5 переключений/год при медианной длительности 4 дня (короткие серии
есть). Никакого dwell-lock/сглаживания — сознательно (doc v5 §1).
