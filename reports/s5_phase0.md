# S5 фаза 0: песочница Kraken недоступна → путь §6 (синтетика)

**Первый шаг §1.1 (проверить доступность) выполнен и решил вопрос.** Проверено 2026-08-14.

## Песочница выведена из эксплуатации

| Проверка | Результат |
|---|---|
| `demo-futures.kraken.com/derivatives/api/v3/instruments` | **HTTP 301** → `www.kraken.com/gb/features/futures` (маркетинг) |
| `demo-futures.../tickers`, `/`, `/api/v3/instruments` | все 301 на ту же маркетинг-страницу |
| прод `futures.kraken.com/derivatives/api/v3/instruments` | HTTP 200 (работает) |

Демо-хост больше не отдаёт API — только редирект на страницу фич. **Уведомление о выводе демо-среды
14 июля (упомянутое в §1.1 doc 57) подтвердилось.** Фаза 0 через sandbox невозможна.

## Решение: путь §6 — синтетический мок

Раз песочницы нет, по §1.1/§6 переходим к плану без неё, но **стоп проверяем на синтетике** (не идём в
микро-live с непроверенным стопом — §6, §7). Стоп — единственная защита хвоста, а в BULL хвост толще
(`s5_diagnostics.md`: худшие 10% −31% против −20.6%).

### Что строить вместо фазы 0

**Локальный мок биржевого адаптера** (Kraken Futures REST/WS), воспроизводящий ответы и ценовые ряды,
через который прогоняются те же сценарии §4.2/§4.3, что планировались в песочнице:

1. **Абстракция исполнения** `ExchangeAdapter` с двумя реализациями:
   - `MockExchange` — детерминированный: задаёт ценовой путь, отвечает на ордера, имитирует сбои
     (отклонение закрывающего ордера, разрыв соединения, гэп через порог, уже-закрытую позицию);
   - `KrakenFutures` — реальный (прод), включается сменой ОДНОЙ константы (base URL) для микро-live.
2. **Стоп-логика (§4.2, главное):** цепочка обнаружение по внутридневному high → расчёт убытка →
   закрывающий ордер → подтверждение → журнал. Прогнать на моке **≥20 срабатываний** + ≥3 сбойных
   сценария (гэп −30%→−40% фиксируется, не игнорируется; реконнект-докрытие; повторное закрытие не шлётся).
3. **Отмена разлока (§4.3):** подмена даты события в тестовом фиде на открытой позиции → немедленное
   закрытие + отдельная категория журнала + фиксация срока до плановой даты.
4. **Approval Gate (§4.5):** ни одного ордера в обход ручного подтверждения — прогнать десятки раз.
5. **Устойчивость (§4.4):** реконнект WS (мок форсирует разрыв), перезапуск процесса → состояние из
   «биржи» (мока), не из памяти.

Критерии выхода — как §5 doc 57 (≥20 стопов вкл. ≥3 сбойных, ≥3 отмены, реконнект/перезапуск без потери
состояния, Approval Gate без обхода, ошибки API обработаны). При выполнении → микро-live по `54`,
переключение `MockExchange`→`KrakenFutures` (base URL прод + реальные ключи).

## Что нужно и порядок

**Оговорки:**
- Мок не заменяет микро-live: проскальзывание и реальные издержки — только на живых ордерах (§7).
- Мок дольше в разработке, но покрывает те же сценарии §4.2 (§6).
- Микро-live требует прод-ключей Kraken Futures (действие постановщика) — код готовится против мока до этого.
- Протокол `54` не меняется; фаза 0 проверяет исполнение, не стратегию.

**Статус:** путь к запуску определён — вместо sandbox строим мок-адаптер, на нём закрываем два
непроверенных компонента (стоп-логика, отмена разлока), затем переключение константы на прод для
микро-live. Это самостоятельная сборка торговой системы (Spring Boot приложение проекта) — начинать по
решению постановщика; для микро-live дополнительно понадобятся API-ключи Kraken Futures.
