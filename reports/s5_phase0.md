# S5 фаза 0: песочница Kraken недоступна → путь §6 (синтетика)

**Первый шаг §1.1 (проверить доступность) выполнен и решил вопрос.** Проверено 2026-08-14.

## Песочница выведена из эксплуатации

| Проверка | Результат |
|---|---|
| `demo-futures.kraken.com/derivatives/api/v3/instruments` | **HTTP 301** → `www.kraken.com/gb/features/futures` (маркетинг) |

Демо-хост больше не отдаёт API — только редирект на страницу фич. **Уведомление о выводе демо-среды
14 июля (упомянутое в §1.1 doc 57) подтвердилось.** Фаза 0 через sandbox невозможна.

**Проверка «может, переехал» (2026-08-14):** ссылка `/features/futures/the-sandbox` — это про токен SAND
(«The Sandbox»), совпадение по названию, не тестовая среда. Официальный саппорт-артикул
(`support.kraken.com/articles/360024809011`) прямо пишет: `demo-futures.kraken.com` выключается 14 июля
13:00 UTC, **замещающего URL НЕТ**, после тестов — прод. API-доки перечисляют только прод. Три источника
+ живой 301 → **песочница закрыта без замены, не переехала.**

## Решение: путь §6 — синтетический мок

Раз песочницы нет, по §1.1/§6 переходим к плану без неё, но **стоп проверяем на синтетике** (не идём в
микро-live с непроверенным стопом — §6, §7). Стоп — единственная защита хвоста, а в BULL хвост толще
(`s5_diagnostics.md`: худшие 10% −31% против −20.6%).

### Что строить вместо фазы 0

**Локальный мок биржевого адаптера** (Kraken Futures REST/WS), воспроизводящий ответы и ценовые ряды,
через который прогоняются те же сценарии §4.2/§4.3, что планировались в песочнице:

1. **Абстракция исполнения** `ExchangeAdapter` с двумя реализациями:
   - `MockExchange` — детерминированный: задаёт ценовой путь, отвечает на ордера, имитирует сбои
     (отклонение закрывающего ордера, разрыв соединения, гэп через порог, уже-закрытую позицию);
   - `KrakenFutures` — реальный (прод), включается сменой ОДНОЙ константы (base URL) для микро-live.
2. **Стоп-логика (§4.2, главное):** цепочка обнаружение по внутридневному high → расчёт убытка →
   закрывающий ордер → подтверждение → журнал. Прогнать на моке **≥20 срабатываний** + ≥3 сбойных
   сценария (гэп −30%→−40% фиксируется, не игнорируется; реконнект-докрытие; повторное закрытие не шлётся).
3. **Отмена разлока (§4.3):** подмена даты события в тестовом фиде на открытой позиции → немедленное
   закрытие + отдельная категория журнала + фиксация срока до плановой даты.
4. **Approval Gate (§4.5):** ни одного ордера в обход ручного подтверждения — прогнать десятки раз.
5. **Устойчивость (§4.4):** реконнект WS (мок форсирует разрыв), перезапуск процесса → состояние из
   «биржи» (мока), не из памяти.

Критерии выхода — как §5 doc 57 (≥20 стопов вкл. ≥3 сбойных, ≥3 отмены, реконнект/перезапуск без потери
состояния, Approval Gate без обхода, ошибки API обработаны). При выполнении → микро-live по `54`,
переключение `MockExchange`→`KrakenFutures` (base URL прод + реальные ключи).

## Что нужно и порядок

| Шаг | Что | Кто |

| 3 | Фаза 0 на моке по §4, критерии §5 | сборка |

**Оговорки:**
- Мок не заменяет микро-live: проскальзывание и реальные издержки — только на живых ордерах (§7).
- Мок дольше в разработке, но покрывает те же сценарии §4.2 (§6).
- Микро-live требует прод-ключей Kraken Futures (действие постановщика) — код готовится против мока до этого.
- Протокол `54` не меняется; фаза 0 проверяет исполнение, не стратегию.

**Статус:** путь к запуску определён — вместо sandbox строим мок-адаптер, на нём закрываем два
непроверенных компонента (стоп-логика, отмена разлока), затем переключение константы на прод для
микро-live. Это самостоятельная сборка торговой системы (Spring Boot приложение проекта) — начинать по
решению постановщика; для микро-live дополнительно понадобятся API-ключи Kraken Futures.

## Ход сборки: ядро фазы 0 построено и проверено на моке (2026-08-15)

Пакет `org.home.data.trade` (не трогает существующий код):
- `ExchangeAdapter` — абстракция исполнения (мок ↔ прод = смена реализации/base URL);
- `MockExchange` — детерминированный, с внедрением сбоев (разрыв, отклонение закрытия, гэп, внешнее закрытие);
- `StopEngine` — стоп по внутридневному максимуму, ретраи→эскалация, гэп-проскальзывание, реконнект-докрытие, без двойного закрытия; источник истины — `positions()`;
- `ApprovalGate` — ни одного ордера в обход подтверждения;
- `TradeJournal` — категории: PLANNED_EXIT / STOP / STOP_GAP / UNLOCK_CANCELLED / RECONNECT_CLOSE / ALREADY_CLOSED / CLOSE_FAILED.

**Тесты `StopEngineTest` — 12/12 зелёные (`./gradlew test`).** Покрыты критерии §5:
- ≥20 корректных стопов (pnl −30%);
- 5 сбойных сценариев (§4.2): гэп→проскальзывание зафиксировано, отклонение→ретраи→успех, сверх ретраев→CLOSE_FAILED+алерт+докрытие, уже-закрыта→без двойного закрытия, разрыв→докрытие после реконнекта;
- отмена разлока ≥3 (§4.3, немедленное закрытие, отдельная категория);
- Approval Gate: без подтверждения ордер не идёт (§4.5);
- удержание режима «надо закрыть» по внутридневному максимуму после отката.

**Осталось для микро-live (нужны ключи/дальнейшая сборка):** `KrakenFuturesExchange` (прод-реализация,

## Фид разлоков + монитор деградации построены и протестированы (2026-08-15)

- `UnlockFeed` — из `EmissionSource` (DefiLlama CDN, прод `DefiLlamaEmissionSource`) извлекает предстоящие
  клифф-разлоки ≥3% circ, сопоставляет протокол→тикер→перп Kraken, фильтрует по доступности; `dueForEntry`
  выдаёт события с датой = сегодня+5 (день входа). Парсинг — как в бэктесте.
- `ScheduleTracker` — сверка даты разлока по открытым позициям (doc 55 §2.3): перенос/отмена → сигнал
  закрыть; журнал пересмотров (§2.4, частота = дисконт премии).
- `DegradationMonitor` — rolling-20/40 в наблюдении; **пауза из ПРИНЦИПА** (doc 54 §3): rolling-40<0 ЛИБО
  два подряд отрицательных rolling-20 (правило rolling-20<0 отвергнуто до запуска). Нормальная дисперсия
  при положительном среднем НЕ триггерит — проверено.

**Тесты: 27/27 зелёные** (StopEngineTest 12 + UnlockFeedTest 4 + DegradationMonitorTest 6 + ScheduleTrackerTest 5).

**Осталось только с ключами/оркестрацией:** `KrakenFuturesExchange` (прод-адаптер, API-ключи Kraken Futures)

## Каркас оркестратора построен (2026-08-15)

`S5Orchestrator` (против `ExchangeAdapter` — тестируется на моке без ключей) склеивает всё:
- `discover(today)` — события с днём входа сегодня (unlock−5) → фильтр дорогого шорта (`FundingSource`,
  текущая ставка как прокси 5д) → лимит экспозиции (≤81%) → подача в Approval Gate;
- `executeApproved()` — открыть шорт по подтверждённым (сайзинг 4.5% капитала), зафиксировать дату;
- `maintain(today)` — плановый выход в день разлока; перенос/отмена расписания → закрытие немедленно;
- `pollStops()` — опрос стопов; закрытия пишутся в `DegradationMonitor` (наблюдение);
- `recover()` — усыновление позиций с биржи при перезапуске (источник истины `positions()`).
Абстракции `EventFeed`/`FundingSource`/`S5Config`.

**Тесты: 33/33 зелёные, полный `./gradlew test` проходит** (StopEngine 12 + UnlockFeed 4 + Degradation 6 +
Schedule 5 + Orchestrator 6). Полный цикл на моке: обнаружение→Gate→открытие→плановый выход; отмена
расписания→закрытие; лимит экспозиции→18 позиций; стоп→монитор; recover→усыновление+стоп по восстановленной.

**Осталось ТОЛЬКО с ключами:** `KrakenFuturesExchange implements ExchangeAdapter` (аутентификация/nonce/
подпись, реальные ордера) + `KrakenFundingSource implements FundingSource` (текущая ставка из тикера) +
планировщик (ежедневно discover→maintain, часто pollStops). Вся бизнес-логика закрыта на синтетике.
